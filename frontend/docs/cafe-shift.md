# 카페 아르바이트 — 프론트엔드 인수인계

작성일: 2026-10-17. `feat/8-시뮬레이션-게임-ui-제작`에서 만든 카페 근무 활동의 규칙과 구현 경계를 기록한다. 실제 카페 자격 교육이나 당사자 사용성 평가 결과가 아니다.

## 한 번의 근무

동료에게 업무를 받고, 마을의 친구 세 명을 차례대로 맞는다. 주문을 기억해야만 진행할 수 있는 시험이 아니라 주문표·레시피를 다시 보고, 동료에게 묻고, 필요하면 다시 만들 수 있는 생활 게임이다. 제한 시간, 손님 인내심 감소, 실수 금전 차감, 게임 오버를 두지 않는다.

1. **민수**: 아이스 라테 주문을 받는다.
2. 컵을 놓고 재료를 넣은 뒤 음료를 완성한다. 완성한 음료를 쟁반에 올려 주문한 손님에게 건넨다.
3. 사용한 손님 자리를 정리한 뒤 다음 손님을 맞는다.
4. **지영**: 따뜻한 아메리카노를 주문한 다음, 만들기 전에 아이스 아메리카노로 바꿔 달라고 한다. 바뀐 주문을 확인해야 제조를 시작할 수 있다.
5. **수진**: 복숭아 아이스티를 주문한다. 전달·정리를 마친다.
6. 모든 주문과 자리 정리를 마친 뒤 동료에게 완료를 알린다. 이 보고를 해야 결과가 생성된다.

첫 근무의 손님·주문·주문 변경은 고정이다. 무작위 사건이나 seed는 사용하지 않아 같은 입력을 다시 재현할 수 있다. 주문 변경은 지영의 한 번뿐이다.

## 진입과 그림 크기

- 앱 퀘스트의 **카페 첫 근무**, 마을 수첩의 같은 카드, 마을 카페 입구로 진입한다.
- 마을 입구 `(1455, 1168)`, 복귀 `(1420, 1168)`. 입구를 막던 은행 화단을 은행 아래 앞뜰로 옮겨 실제 이동 경로를 확보했다.
- 개발용 웹 미리보기는 `?cafePreview=1&muteAudio=1`이다. 배포 사용자 진입은 퀘스트와 마을 입구를 사용한다.
- 도서관과 같은 플레이어 배율 `0.55`로 표시한다. 직원 표시 높이 `92px`로 여백을 제외한 플레이어의 실제 그림 높이에 맞췄다. 플레이어 캔버스 높이는 `105.6px`이다.
- 작업대 `450×142`, 기본 테이블 세트 `200×104`, 벽 선반 `260×89`. 생성 PNG의 알파 영역을 잘라 종횡비를 유지해 축소했다.
- 새 생성 에셋 7개: 작업대, 테이블/의자, 벽 선반, 직원, 라테, 아메리카노, 복숭아 아이스티. `assets/images/game/cafe/v1/source/`에 원본을 보존하고 실제 앱은 작은 런타임 파일만 참조한다. 생성 도구·프롬프트·크기는 같은 폴더의 `manifest.json`에 기록했다.
- 이동은 기존 공통 `GameControls`와 캐릭터 스프라이트를 사용한다. 슬라이드 패드 모드에서 멀리 있는 물체를 눌러 자동 이동하지 않으며, 터치 이동 모드에서는 목적지 안내를 눌러 실제 경로를 걸어간다. 키보드 WASD/방향키와 Shift 달리기도 유지한다.

## 음료 규칙

| 음료 | 컵 | 재료 |
| --- | --- | --- |
| 아이스 라테 | 차가운 음료 컵 | 얼음, 우유, 에스프레소 |
| 따뜻한 아메리카노 | 머그잔 | 물, 에스프레소 |
| 아이스 아메리카노 | 차가운 음료 컵 | 얼음, 물, 에스프레소 |
| 복숭아 아이스티 | 차가운 음료 컵 | 복숭아 베이스, 물, 얼음 |

따뜻한 아메리카노는 첫 주문/레시피 정보에 존재하지만 이번 근무에서는 지영의 주문 변경으로 최종 제공하지 않는다. 실제 제공 음료는 세 종류다.

레시피 배열 순서는 UI에서 보여 주는 권장 조립 순서다. **최종 컵과 재료의 구성이 맞으면 재료를 넣은 순서가 달라도 인정한다.** 실제 카페별로 달라지는 제조 순서를 하나의 절대적인 정답으로 가르치지 않는다. 양, 기계 조작, 뜨거운 물 취급, 알레르기, 위생·보관 절차 전체는 구현하지 않았다.

- 컵 없이 재료를 넣을 수 없다.
- 같은 재료의 연속 터치는 추가 투입으로 계산하지 않는다.
- 재료를 넣기 전에는 컵을 바로 바꿀 수 있다. 재료를 넣은 뒤에는 **다시 만들기**로 비우고 컵을 바꾼다.
- 빠진 재료는 이어 넣으면 된다. 다른 재료를 넣었거나 컵이 다르면 짧은 안내를 읽고 다시 만들 수 있다.
- 잘못된 손님을 골라도 쟁반을 잃지 않는다. 주문한 손님을 알려 주고 다시 건넬 수 있다.
- 완성·전달·정리·완료 보고를 연속 눌러도 같은 작업을 중복 집계하지 않는다.

## 상태와 API

규칙 파일: [cafeSession.ts](../src/game/cafeSession.ts). 테스트: [cafeSession.test.ts](../__tests__/cafeSession.test.ts).

`CafeSession.phase`는 `briefing → working → finished`다. `guests`는 세 명의 주문 상태를 담고, `guestIndex`는 현재 손님을 가리킨다. 각 손님 상태는 다음과 같다.

`waiting → order-change(지영만) → preparing → ready → carrying → served → cleaned`

| 함수 | 용도 |
| --- | --- |
| `createCafeSession({id?, now?})` | 새 근무 생성. 기본 시간·ID는 생성 시 한 번만 정하고, 화면을 다시 열 때 재생성하지 않는다. |
| `applyCafeAction(session, action)` | 상태와 명시적 액션만으로 작업을 처리하는 reducer. 이동/근접 판정은 화면 담당이다. |
| `getCurrentCafeGuest(session)` | 현재 손님의 작업 상태 또는 `null` |
| `getCafeGuest(guestId)` | 손님 이름·주문 대사·감사 대사 |
| `getCafeRecipe(session)` | 현재 주문에 맞는 레시피 |
| `getCafeObjective(session)` | 지금 해야 할 짧은 행동 문구 |
| `canReportCafeShift(session)` | 세 명의 변경 후 주문과 정리를 모두 마쳤는지 확인 |
| `getCafeResult(session)` | 유효하게 완료한 근무의 결과. 미완료/불일치 상태는 `null` |

액션은 `START`, `TAKE_ORDER`, `ACKNOWLEDGE_CHANGE`, `CHOOSE_CUP {cup}`, `ADD_INGREDIENT {ingredient}`, `FINISH_DRINK`, `PICK_UP_TRAY`, `SERVE {guestId}`, `CLEAN_TABLE`, `NEXT_GUEST`, `ASK_AGAIN`, `ASK_HELP`, `REMAKE`, `CLEAR_ERROR`, `REPORT {now}`, `RESET {id, now}`다.

`REPORT`와 `RESET`에는 호출자가 시각을 넣는다. `RESET`에는 새 ID도 넣는다. reducer 안에서 현재 시각이나 무작위 값을 만들지 않아 동일한 상태/액션을 재생하면 동일한 결과가 나온다. 새 세션 factory의 기본 ID 생성은 예외이며 명시적 새 근무 시작에만 쓴다.

잘못된 순서의 작업은 다른 손님이나 완료 상태를 바꾸지 않고 `lastActionError`로 안내한다. 다음 유효한 작업은 오류를 지운다. 완료된 근무는 명시적 `RESET` 외에는 바뀌지 않는다.

결과에는 실제 제공한 음료, 응대한 손님 수, 정리한 자리 수, 바뀐 주문 확인, 다시 질문한 손님 수, 도움을 요청한 손님 수, 다시 만든 횟수와 `facts` 문장이 들어간다. 질문·도움·다시 만들기는 감점이 아니다. 실제로 선택하지 않은 도움 행동이나 교육 효과·자립 능력 향상을 결과에 추가하지 않는다.

## 화면·저장 경계

앱 퀘스트의 **카페 첫 근무**는 `QuestScreen → AppShell → GamePrototypeScreen`의 `initialActivity='cafe'`로 연결한다. 기존의 일반 대화 연습용 **카페에서 주문하기** 카드를 실제 근무 카드로 바꿨다. 홈 API/목업 목록의 같은 이름 항목까지 임의로 교체한 것은 아니다.

게임 수첩에는 `GameHud.onOpenCafe`가 연결된 화면에서 **카페 첫 근무** 카드가 나타난다. 카드는 현재 근무의 다음 행동을 표시하고 수첩 닫기 애니메이션이 끝난 뒤 부모 진입 콜백을 실행한다. 전달할 콜백이 없는 화면에는 동작하지 않는 카페 버튼을 추가하지 않는다. 기존 도서관 일정·장보기·연락 확인 카드와 휴대폰 규격은 유지한다.

카페는 기존 마을의 활동으로 연결하고 공통 이동·상호작용 UI와 플레이어 크기를 유지한다. 화면이 이동/근접 판정을 맡고 reducer는 작업 순서만 판정한다. 작업 패널에서 쟁반 준비를 마쳤다는 이유만으로 자동 배달하거나 자동 정리한 것으로 기록하지 않는다.

진행 상태는 [cafeStore.ts](../src/game/cafeStore.ts)의 현재 실행 메모리에 유지한다. `getCafeDraft`, `keepCafeDraft`, `useCafeDraft`를 부모 게임 화면/HUD가 공유한다. 같은 상태 객체를 다시 넣으면 알림을 발생시키지 않는다. 앱 종료·새로고침 후 중간 저장이나 서버 동기화가 추가됐다고 설명하지 않는다.

완료 앨범은 [activityAlbum.ts](../src/game/activityAlbum.ts)의 `makeCompletedCafeActivity(session)` / `recordCompletedCafeActivity(session)`로 생성한다. `getCafeResult`로 최종 주문·정리·보고를 다시 검증하고, 세션의 실제 `completedAt`과 실제 행동 문구를 사용한다. `kind: 'cafe'`와 세션 ID로 중복을 막으며 기존 장보기·도서관·버스·연락 확인 기록을 보존한다. 같은 세션의 결과를 다시 열어도 새 근무로 기록하지 않는다.

[PhonePhotos.tsx](../src/components/game/PhonePhotos.tsx)의 **카페 근무** 앨범에서 기록과 즐겨찾기를 볼 수 있다. 카드/상세에는 카페 라테 에셋을 따뜻한 배경 위에 `contain`으로 표시해 컵이 잘리지 않게 한다. 실제 플레이를 촬영한 사진이라고 표시하지 않는다. 저장은 기존 규칙대로 웹 localStorage를 사용할 수 있으면 보관하며, native/차단 환경은 현재 실행 메모리로 대체한다.

백엔드·실제 결제·주문 API는 사용하지 않는다. 이 근무의 주문과 대사는 로컬 가상 데이터다. 이미지·공통 UI 통합의 검증 범위는 아래 기록을 구현 완료 후 갱신한다.
