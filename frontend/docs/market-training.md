# 장보기 훈련 테스트와 이동 경로

작성일: 2026-11-15. 작업 브랜치: `feat/8-장보기-게임-구체화`.

## 실행과 테스트 만들기

장보기 시작 화면 → **설정(디버그)** → **기본 설정 → 과제·힌트·돌발 상황**에서 고른다.

| 선택 | 동작 |
| --- | --- |
| 기본 장보기 | 목록의 물건을 골라 계산한다. |
| 어머니 심부름 | 어머니의 부탁 안내와 물건 목록을 보고 찾아 가져온 뒤 계산한다. |
| 매대 위치 찾기 | 부탁 목록의 매대를 열어 살펴본 뒤 ‘위치 찾기 완료’를 누른다. 구매·결제는 필요 없다. |
| 직원 안내 연습 | 직원에게 위치를 물으면 목표 매대 방향에 화살표를 보여 준다. |
| 지도 활용 연습 | 플레이 중 ‘매장 지도’를 열 수 있다. |
| 돌발 상황 도전 | 사람 몰림, 쿵 소리와 빛을 함께 사용한다. |

힌트와 상황은 각자 바꿀 수 있다. **기본값은 지도 없음, 화살표 없음, 돌발 상황 없음**이다. 일반 ‘이용 방법’과 직원의 말로 하는 안내는 유지한다.

‘부탁 물건 목록’에서 상품을 추가·제거하고 수량을 정한다. 마지막 물건은 제거하지 않는다. 같은 상품을 추가하면 수량을 올린다. ‘내가 만든 테스트’에서 이름을 정해 저장하고 다시 선택할 수 있다. 배치·시드·물건 목록·재고·학습 조건·새 훈련 조건을 함께 저장하며 **설정 적용**으로 실행 화면에 반영한다. 기존 AI 추천의 조건 수정과 직접 만든 테스트 선택을 구분하여, 직접 만든 목록을 새 AI 추천으로 덮어쓰지 않는다.

테스트 보관함은 AsyncStorage를 이용하는 기기/브라우저별 저장이며 최대 24개다. 같은 이름의 기존 테스트를 덮어쓰지 않는다. 저장 실패는 화면에 알린다. 기기 간 이동에는 기존 **세이브·로드 → 전체 설정 JSON 저장/불러오기**를 사용한다. 보관함 저장은 이전 플레이 기록이나 페르소나 식별자를 재사용하지 않는다.

## 직원과 위치 안내

- 직원 아래에 보이던 ‘종업원 1’ 등의 이름표를 제거했다. 접근·상호작용 판정은 그대로 유지한다.
- 가까운 직원의 머리 위에 검정 반투명 배지와 흰색 선으로 그린 작은 대화 말풍선·점 세 개를 표시한다. 별/AI 기호와 채워진 말풍선 아이콘을 사용하지 않는다.
- 화살표를 켠 테스트에서 위치를 물으면 목표 매대 중심 방향을 표시한다. 화면 밖이면 화면 가장자리에 표시한다.
- 목표 매대의 일부가 실제 카메라의 보이는 영역에 들어온 시점부터 3초 후 650ms 동안 사라진다. 대화창이 덮고 있는 동안에는 새로 ‘보았다’고 계산하지 않는다. 같은 위치를 다시 질문하면 다시 표시한다. 모션 감소 시 사라지는 전환 시간을 줄인다.

## 돌발 상황

동일한 시드·배치·조건이면 같은 지점에서 발생한다. 시작 화면을 읽는 동안에는 발생하지 않는다.

| 종류 | 시작 후 | 지속 | 구현 범위 |
| --- | --- | --- | --- |
| 사람 몰림 | 18초 | 18초 | 기존 손님 그림 3명이 모인 시각적 주의 분산 상황. 충돌 경로를 막거나 스스로 움직이는 군중 AI는 아니다. |
| 쿵 소리와 빛 | 단독 18초 / 두 상황 모두 40초 | 빛 8초 | 자체 제작한 짧은 저음 효과음과 해당 위치의 부드러운 빛. 반복 점멸은 없다. |

발생 지점·예정 시간·실제 발생 시간을 `incident_started` 이벤트에 남긴다. 백그라운드에서는 새 상황을 띄우지 않고, 돌아온 뒤 아직 실행하지 않은 상황을 발생시킨다. 늦게 발생한 경우 실제 발생 시점부터 지속 시간을 센다. 효과음 음량·개발용 음소거 설정을 따른다. 화면을 열고 닫아도 같은 소리를 반복 재생하지 않는다.

## 결과 경로와 페르소나 연동

종료·중단·시간 초과·AI 수행 검토·이전 기록에서 **이동 경로·시간 확인**을 연다. 지도 위의 흰 선은 기록된 이동, 시간 점은 선택한 간격의 위치, 빨간 표시는 같은 곳에 머문 구간, 초록 점은 선택 시점/마지막 위치다. 시간이 겹치는 위치의 라벨은 `0s +2`처럼 묶으며 ‘처음/이전/재생/다음/전체’로 개별 시간과 좌표를 확인한다. 시간 간격은 2·5·10초다.

실제 허용된 `player_moved` 이벤트를 사용한다. 사람이 이동할 때는 0.5초 주기와 방향 전환·문 통과 시점, 정지 중에는 약 2초마다 위치를 보존한다. 페르소나의 bounded `move`는 수락된 실제 위치를 기록한다. 시간 점은 표본 사이를 선형 보간하며 전수 프레임 측정이나 미터 단위 거리를 뜻하지 않는다. 거리는 마트 월드 좌표 단위다. 왕복 후 원위치로 돌아온 이동을 정지로 표시하지 않는다. 배치 변경 전후는 선을 끊고 순간 이동을 이동 거리로 더하지 않는다. AI 분석·평가 화면을 읽는 대기 시간은 종료된 경로 시간을 늘리지 않는다.

기존 `market_export_episode`의 `episode.trajectory`에 다음 필드를 추가했다. **종료 전 감사용 전체 경로는 actor observation에 넣지 않는다.** Backend 코드는 수정하지 않았으며 서버 DB나 분석 화면이 자동으로 새 그림을 저장하는 기능은 별도 연동이다.

```json
{
  "schema": "oneuldo.market.trajectory.v1",
  "intervalSeconds": 5,
  "durationSeconds": 27.2,
  "distance": 480,
  "points": [{"x": 600, "y": 1200, "elapsedSeconds": 0, "segment": 0}],
  "markers": [{"x": 600, "y": 1200, "elapsedSeconds": 0, "segment": 0}]
}
```

`points`는 보존한 위치 표본 전체, `markers`는 표시 간격과 종료 시점의 위치다. `segment`가 다른 점끼리는 연결하지 않는다. ‘경로 그림 저장’은 SVG, ‘게임 기록 저장’은 원본 이벤트와 trajectory를 포함한 JSON이다. 네이티브에서는 공유 창으로 전달한다. 과거 기록에 trajectory가 없으면 보존된 이벤트에서 계산한다.

### 행동 위치 마커 (2026-11-18)

- 매대 열기/닫기, 상품 담기/내려놓기를 `trajectory.actions`에 시간순으로 함께 내보낸다. 행동 ID·종류·상품/매대·수량·경과 시간·좌표·경로 segment·위치 출처를 포함한다. 거부된 행동과 게임 종료 뒤 이벤트는 표시하지 않는다.
- 새 `station_closed`, `cart_changed` 이벤트는 당시 캐릭터 좌표를 저장한다. 매대 닫기에는 닫기 전 매대 ID, 상품 변경에는 당시 상품명도 보존한다. 종업원을 통한 반환은 매대 위치가 아닌 캐릭터가 직원과 대화한 위치를 사용한다.
- 지도에는 행동 번호와 색상별 마커를 표시하고, 화면상 가까운 행동은 `+건수`로 묶는다. 번호 또는 아래 타임라인을 누르면 해당 시점의 경로·정확한 위치·시간·행동을 보여 준다. 종류별 필터, 모든 행동 시각을 포함하는 재생, 기록 시간/행동 수/이동 거리 요약을 제공한다.
- 과거 trajectory에 actions가 없으면 원본 이벤트에서 다시 계산한다. 과거 행동에 좌표가 없으면 마지막 확인 위치만 사용하고 `positionSource: last-known`과 화면 안내를 남긴다. 새 좌표는 `recorded`다. 과거 위치를 정확한 위치로 추정해 표시하지 않는다.
- 경로 SVG에도 번호·묶음·행동 타임라인을 포함한다. JSON 내보내기에는 전체 actions를 보존한다. 현재 UI는 기기/페르소나 실행의 기존 episode를 사용하며, 운영 서버의 분석 데이터를 새로 조회하는 화면은 추가하지 않았다.
- 기존 `SHOP.SHELF_OPENED`, `SHOP.SHELF_CLOSED`, `SHOP.QUANTITY_CHANGED` 업로드에 행동 당시 `x`, `y`를 추가한다. 백엔드가 이미 허용하는 필드만 사용하며 백엔드와 develop은 수정하지 않는다. 실제 운영 DB 수신 여부와 실기기 동작은 별도 검증 대상이다.
- 검증 자료: `output/market-route-actions-2026-11-18/`. 사용자 효과 평가나 새 페르소나 실험이 아닌 코드·UI 회귀 검사다.

### 지도 글꼴·연속 재생·종업원 대화 (2026-11-19)

- 결과 지도와 힌트 지도의 글꼴을 Pretendard로 통일했다. 매대·입구·출구는 11→12px, 시간 표시는 8→9px로 키웠다. SVG의 글꼴 지정에도 반영했다.
- 재생은 시간 마커마다 건너뛰는 방식에서 하나의 연속 시계로 선을 그리는 방식으로 바꿨다. 기록 시간의 2배속이며, 실제 머문 시간에는 현재 위치를 유지한다. 이전/다음은 기존처럼 시간·행동 시점을 선택한다. 일시정지/이어 재생, 처음/전체 보기, 화면을 닫거나 앱이 백그라운드에 들어갔을 때의 정지를 지원한다.
- 선의 기하 정보는 재사용하고 선 길이와 현재 위치를 Animated 값으로 갱신한다. iOS/Android는 네이티브 드라이버, 웹은 JS 드라이버를 사용한다. 텍스트·마커의 React 갱신은 약 80ms 간격으로 제한한다. 배치 변경 구간은 연결하지 않는다.
- 성공한 `station_interacted`의 `staff:*` 대상을 `staff-talked` 행동 마커로 표시한다. 종업원 대화 시작 당시 캐릭터 위치와 경과 시간을 기록하며, 종업원 대화 필터와 SVG 내보내기에도 포함한다. 백엔드의 기존 `SHOP.STAFF_HELP_REQUESTED`에는 위치와 직원 stationId를 함께 전송한다. 모든 대화 선택지를 별도 마커로 표시하는 기능은 아니다.
- trajectory의 `actionSchemaVersion: 2`로 이전 저장 기록을 구분한다. 이전 버전의 행동 마커는 원본 episode 이벤트에서 다시 계산해 종업원 대화를 포함한다.
- 지도 힌트가 켜진 과제에서는 `지도`라는 58px 원형 버튼을 공통 84px 행동 버튼 왼쪽에 12px 간격으로 배치하고 세로 중심을 맞춘다. 지도 제공의 기본값은 계속 꺼짐이다. 메뉴·대화·지도 화면이 열려 있을 때는 지름길 버튼을 숨긴다.
- 단독 장보기 개발 화면도 같은 공통 원형 행동 버튼을 사용하고 달리기 버튼을 그 위로 정렬하여, 일반 마을 진입과 개발 화면 모두 지도·행동·달리기가 겹치지 않도록 했다.
- 검증 자료: `output/market-route-refinement-2026-11-19/`. 브라우저 UI fixture와 단위·회귀 검사이며 실제 이용자·신규 페르소나 모델 실험이나 Expo Go 실기기 검증을 의미하지 않는다.

### 동선 대비·마트 NPC 아트 통일 (2026-11-19)

- 흰 경로를 2→3px로 키우고 5px의 옅은 녹색 외곽선을 더했다. 선 끝을 둥글게 처리하고 현재 위치 표시는 10→12px로 키웠다. 연속 재생과 SVG 내보내기에도 같은 대비 기준을 적용했다.
- 종업원 4종, 성인·노년·어린이 손님 각 4종을 플레이어의 SD 비율·갈색 윤곽선·단순한 얼굴·차분한 색감에 맞춰 별도로 편집했다. 기존 의상·머리·안경·연령 구분을 참고했으며, 기존 v1 이미지는 보존한다. 현재 정적 아트는 `*-chibi-v2.png`다.
- 성인 표시 높이는 104→92 월드 px로 플레이어의 약 86px에 맞췄으며 어린이는 기존 0.76배다. 새 256×384 캔버스는 종횡비를 유지하고 발 하단을 정렬했다. 픽셀을 가로·세로로 따로 늘이지 않는다. 이전 발 충돌 사각형은 별도 기준으로 유지해 경로·직원 접근 판정을 바꾸지 않는다.
- 일반 월드와 단독 마트 화면, 계산대 직원이 같은 아트를 사용한다. 대화 말풍선은 실제 머리 높이 위로 배치하고 인물 이미지의 초기 페이드는 끈다. 걷기 등 새로운 NPC 애니메이션을 만든 것은 아니다.
- 아트·프롬프트 안내: `frontend/assets/images/game/market/people/README.md`, `chibi-v2-prompts.json`. 패키징은 `frontend/scripts/prepare-market-chibi-people.cjs`, 비교와 검증은 `output/market-visual-polish-2026-11-19/`에 있다.
- 개발 서버가 작업 중 생성되는 이미지 원본·보고서·브라우저 프로필까지 감시하지 않도록 workspace의 `output/`, `tmp/`, `.codex-tmp/`를 Metro 감시 대상에서 제외했다. 앱 코드·런타임 아트·의존성은 제외하지 않으며 경계 검사로 확인한다.

### 코너 표지와 버튼으로 여는 구매 목록 (2026-11-19)

- 직원이 없는 계산대에는 ‘직원 호출’ 상태 배지를 표시하지 않는다. 계산대 번호와 기존 직원에게 계산을 부탁하는 게임 동작은 유지한다. 직원이 있는 계산대의 ‘계산 가능’ 표시는 유지한다.
- 코너 이름은 바닥 아래에서 매대 그림 위로 이동했다. 가로·세로 배치 모두 위쪽 가구의 그림과 10 월드 px 간격을 두고 묶음 가운데에 배치한다. 렌더러와 페르소나 재현의 표지 좌표가 `getMarketCategoryMarkerRect`를 공유하며 보이지 않는 호출 표지는 재현 관찰에도 넣지 않는다.
- 상시 노출하던 물품·수량 행을 없앴다. 상단 ‘목록 보기’ 버튼을 누르면 세로 스크롤 가능한 전체 목록 창이 열리고 X 또는 Android 뒤로 가기로 닫힌다. 요구 물품·수량과 장바구니는 구분하며 대체 상품 승인에 따른 목록 갱신도 유지한다.
- 목록을 열었을 때 이동을 잠그고 닫거나 HUD를 떠나면 해제한다. 기존 `SHOP.SHOPPING_LIST_OPENED/CLOSED` 기록을 유지한다. 개발 재현의 `readList`도 같은 창을 열고 세로로 읽은 뒤 닫으며 중단 시에도 창을 닫는다.
- 카메라 구도와 기존 재현의 상단 가림 영역은 이전의 보수적인 HUD 높이 기준을 유지한다. 목록에 적힌 상품 이름을 평소 월드 화면에서 읽을 수 있다는 의미로 해석하지 않는다.
- 검증과 캡처: `output/market-hud-signs-2026-11-19/`. 브라우저와 코드 검사이며 Expo Go 실기기나 신규 페르소나 모델 실험은 아니다. 외장하드 보관 여부는 해당 폴더의 `archive-status.json`을 따른다.

### 하단 장보기 버튼·캐릭터 방향 안내·공사 안내 (2026-11-20)

- 목록 보기·장바구니 버튼은 흰색 배경과 은은한 바깥 그림자를 공유한다. 하단 위치·크기와 기존 열기 동작은 유지한다. 이후 게임 캡처는 8081 기본 앱에서 실제로 진입해 촬영하며, 이 스타일 수정에서는 사용자 요청에 따라 재촬영하지 않았다.
- 상단 마트 헤더의 테두리와 그림자를 제거했다. 목록·장바구니 버튼은 하단 가운데, 기존 가방/수첩/휴대폰/설정 툴바 위에 12px 간격을 두고 배치한다. `reader`, `basket` 채움 아이콘을 사용한다.
- 640px 미만 화면에서는 마트의 이동·행동·달리기·지도 컨트롤을 함께 위로 조정해 하단 버튼과 겹치지 않도록 했다. 지도는 계속 행동 버튼 왼쪽에서 세로 중심을 맞춘다. 일반 마을의 조작 위치는 유지한다. 상단 카메라 여유 영역은 기존 보수적 기준을 보존하고, 재현 관찰은 새 하단 버튼 영역도 가린다.
- 구매 목록 제목은 ‘사야 할 물품’만 표시하며 종류 수와 항목 아래 구분선을 제거했다. 물품별 구매 수량·세로 스크롤·열고 닫을 때의 이동 잠금과 기록은 유지한다.
- 직원에게 위치를 물었을 때의 화살표는 캐릭터 몸 주변을 따라가는 파란 채움 방향 아이콘으로 바꿨다. 실제 플레이어 좌표→목표 매대 방향과 카메라 프레임으로 계산한다. 매 프레임 하나의 Animated transform만 갱신하고 전체 월드나 캐릭터를 다시 렌더링하지 않는다. 매대가 화면에 들어온 뒤 3초+기존 페이드로 사라지는 규칙과 힌트 기본 꺼짐은 유지한다.
- 공사 중인 입구의 충돌 사각형에서 100 월드 px 이내에 접근하면 ‘공사 중입니다. 출구가 아닌 측면 통로를 이용해주세요.’를 표시한다. 안쪽·바깥쪽 모두 적용하고 130px 밖으로 벗어나면 숨겨 경계에서 깜빡이지 않게 한다. 공사가 없거나 다른 패널을 보는 동안에는 표시하지 않는다. 기존 입구 충돌·출구 역진입 판정·감점은 변경하지 않는다.
- 검증·사용자 제공 이전 화면·수정 후 캡처: `output/market-controls-guidance-2026-11-20/`. 실제 브라우저에서 직원에게 위치를 묻고 이동하여 화살표가 따라가는 것, 가드레일까지 월드 탭으로 이동해 문구가 뜨는 것을 확인했다. 별도 Expo Go 실기기·운영 DB·신규 페르소나 모델 실험은 아니다.

설정 예시(기존 전체 설정의 training 필드):

```json
{
  "training": {
    "task": "mother-request",
    "mapHint": false,
    "directionHint": true,
    "incidents": "both",
    "routeIntervalSeconds": 5
  }
}
```

기존 AI 입력/출력, 잠금 조건, 시간 제한, 기록 접수 흐름을 유지한다. 시작 조건과 상황 발생은 기존 행동 로그의 `marketContent`에도 기록한다. 페르소나의 모델명·인격 정보와 synthetic 표시는 기존 계약을 따른다. 이번 검증은 단위·UI·브라우저 기능 검사이며 신규 페르소나 실험이나 사용자 효과 검증을 진행한 것이 아니다.
