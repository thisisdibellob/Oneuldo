# 수상한 연락 확인하기 — 프론트엔드 인수인계

작성·자료 확인: 2026-10-17. 이 문서는 `feat/8-시뮬레이션-게임-ui-제작`의 로컬 프론트엔드 구현을 설명한다. 실제 보이스피싱 탐지·신고 서비스나 교육 효과 평가 결과가 아니다.

## 플레이 흐름

앱 퀘스트의 **수상한 연락 확인하기**, 마을의 퀘스트 메뉴, 게임 속 휴대폰의 **메시지**에서 시작하거나 이어 한다. 별도 마을이나 앱으로 이동하지 않고 기존 휴대폰 프레임·민수·지영을 사용한다.

1. **연락 확인하기**를 눌러 민수라고 하는 사람의 메시지를 본다. 더 물어보거나, 답장을 멈추거나, 지영에게 도움을 요청할 수 있다.
2. 연락을 멈춘 뒤 **원래 저장된 민수 연락처** 또는 **마을의 민수와 직접 대화**로 사실을 확인한다. 기존 전화 앱에서 저장된 민수를 선택해도 확인된다. 받은 번호로 다시 전화하는 방식은 아니다.
3. 사칭 연락이면 차단하고 필요하면 연락 내용을 신고하는 연습을 한다. 확인하기 전에 차단했다는 이유만으로 완료되지 않는다.
4. **확인 마치기**를 누르면 선택한 행동을 결과에 보여 준다. 도움 요청은 실패나 감점이 아니다.
5. 결과에서 다른 연락을 골라 기관 사칭 전화, 택배 문자, 실제 민수의 약속을 확인한다. 정상 연락은 확인 후 약속을 정하거나 거절해도 완료된다.

마을에서 직접 확인할 때는 민수에게 가까이 가서 말을 걸고 **이 연락 네가 보냈어?**를 고른다. 지영에게는 **수상한 연락, 같이 봐 줄래?**로 도움을 받을 수 있다. 휴대폰을 닫아도 현재 앱 실행 중에는 진행을 유지한다.

### 구현된 시나리오

| ID | 내용 | 인정하는 독립 확인 | 확인 결과 |
| --- | --- | --- | --- |
| `friend-scam` | 휴대폰이 고장 났다는 민수 명의의 송금 부탁 | 저장된 연락처 / 직접 만남 | 실제 민수가 보낸 연락이 아님 |
| `friend-real` | 다른 번호로 온 민수의 약속 제안 | 저장된 연락처 / 직접 만남 | 실제 민수가 보낸 연락이며 수락·거절 선택 가능 |
| `authority` | 기관을 사칭하며 안전한 계좌로 돈을 옮기라는 전화 | 직접 찾은 공식 연락처 | 기관 사칭 수법 확인 |
| `parcel` | 배송 주소·재배송 비용을 확인하라는 문자 | 공식 주문 내역 / 공식 연락처 | 실제 배송은 정상이며 해당 문자는 사칭 |

상대의 주장과 확인된 사실을 구분한다. 연락처가 낯설다는 이유만으로 사기 판정을 내리거나, 아는 이름·개인정보를 말한다는 이유로 정상이라고 판정하지 않는다. 판정은 이 게임에 미리 작성된 가상 상황에 한정된다.

### 이미 응한 상황의 연습

열려 있는 사칭 연락에서 **이미 응했다면**을 눌러 개인정보를 알려 준 상황 또는 돈을 보낸 상황을 명시적으로 선택할 수 있다. 실제 입력·송금 없이 연습 상태만 바뀐다.

- 연락을 멈춘 뒤, 독립 확인을 기다리지 않고 **112에 상황 알리기**와 **금융회사에 도움 요청하기**를 할 수 있다.
- 송금한 상황은 금융회사에 지급정지를 요청하는 내용이다. 정보를 알려 준 상황은 정보 노출을 알리고 보호 조치를 문의하는 내용이다.
- 두 도움 행동 후 독립 확인과 차단을 마치면 결과로 이어진다. 게임이 정한 완료 순서이며 실제로 기관의 도움을 받을 수 있는 조건을 뜻하지 않는다.
- 환급이나 피해 회복을 보장하지 않는다. 실수 선택 때문에 타이머·게임 오버·금전 감점을 주지 않는다.

## 구현 위치와 상태 계약

| 파일 | 역할 |
| --- | --- |
| `src/game/phishingSession.ts` | 시나리오 문구·상태·순수 reducer·완료 조건·목표·행동 요약 |
| `src/game/phishingStore.ts` | `useSyncExternalStore` 기반 현재 실행의 공유 진행 상태 |
| `src/components/game/PhoneSafety.tsx` | 메시지·확인 방법·도움·노출 상황 선택·결과 |
| `src/components/game/GamePhonePanel.tsx` | 메시지 앱과 기존 연락처 앱 연결 |
| `src/components/game/GameHud.tsx` | 게임 퀘스트 진입과 완료 앨범 기록 |

| `src/screens/QuestScreen.tsx`, `AppShell.tsx` | 앱 퀘스트에서 `initialActivity='phishing'`로 진입 |
| `src/game/activityAlbum.ts`, `src/components/game/PhonePhotos.tsx` | 완료된 `safety` 활동의 요약 기록과 표시 |

`PhishingSession`에는 ID, 시나리오, 시작/완료 시각, `active/completed`, 답장·연락 중단·도움 요청, 확인 방법과 결과, 차단·신고·금융회사 문의, `none/information/money` 노출 상태, 정상 연락의 수락/거절이 있다. 개인정보·계좌번호·실제 전화번호를 보관하지 않는다.

| 액션 | 조건과 결과 |
| --- | --- |
| `REPLY` | 연락이 열린 동안 한 번 더 질문한 상태를 기록 |
| `STOP` | 연락을 끝내고 독립 확인 가능 |
| `VERIFY { method }` | 연락이 끝났으며 해당 시나리오의 허용 방법일 때만 확인 결과 기록 |
| `ASK_HELP` | 진행 중 언제든 도움 요청 기록. 대신 확인하거나 자동 완료하지 않음 |
| `SIMULATE_EXPOSURE { exposure }` | 사칭 연락이 열려 있고 미확인일 때만 가상 노출 상태 선택. 이미 발생한 돈 노출을 정보 노출로 낮출 수 없음 |
| `BLOCK` | 연락을 차단하고 중단. 이것만으로 완료할 수 없음 |
| `REPORT` | 연락 중단 후, 사칭을 확인했거나 가상 노출 상황일 때 신고 연습 기록 |
| `CONTACT_BANK` | 연락 중단 후 가상 정보/금전 노출 상황에서 금융회사 문의 연습 기록 |
| `GENUINE_DECISION { decision }` | 정상 연락을 독립 확인한 뒤 수락 또는 거절 |
| `FINISH { now? }` | 완료 조건과 유효한 시각을 만족할 때 한 번 완료. 이후 액션은 상태를 바꾸지 않음 |

사칭 완료는 **연락 중단 + 유효한 독립 확인 + 차단**이 필요하다. 노출 상황이면 **신고 + 금융회사 문의**도 필요하다. 정상 연락 완료는 **연락 중단 + 유효한 독립 확인 + 수락/거절**이다. 결과에는 확인된 사칭 연락의 차단만 긍정 행동으로 표시하며 정상 연락을 미리 차단한 것은 성공 행동으로 표시하지 않는다.

`startPhishingEpisode(id)`는 새 연락을 명시적으로 골랐을 때만 호출한다. 휴대폰을 열 때마다 호출하면 진행을 초기화하므로 금지한다. `getPhishingSession`, `usePhishingSession`, `dispatchPhishingAction`, `clearPhishingSession`은 같은 메모리 상태를 공유한다.

## 저장·통신·접근성 경계

- 진행 중 상태는 앱 프로세스의 메모리다. 휴대폰/마을 화면 왕복은 유지하지만 앱 종료·새로고침 이후 중간 저장을 보장하지 않는다.
- 완료 앨범은 기존 활동 앨범 저장 규칙을 따른다. 웹 localStorage가 가능하면 보관되며 native 영구 저장이나 서버 동기화를 추가한 것은 아니다. 활동 종류+세션 ID로 중복 기록을 막는다.
- 계정·AI·백엔드·통화·SMS·송금·신고 API를 호출하지 않는다. 문자 안의 실제 악성 주소, 외부 이동 링크, 개인 정보 입력 필드도 없다.
- 공식 연락처 확인과 주문 조회는 게임 안에 작성된 응답이다. 실제 사이트 조회나 실제 신고가 이루어졌다는 메시지로 바꾸지 않는다.
- 글로 전 과정을 진행하며 소리를 들어야만 답할 수 있는 단계는 없다. 현재 게임에 새 통화 음성 합성을 추가한 것은 아니다.
- 기존 휴대폰 비율과 스크롤을 재사용하고 짧은 화면 전환 효과는 모션 감소 설정에 따른다. 접근성 적합성이나 발달장애인 당사자의 사용성 평가가 완료됐다고 주장하지 않는다.

## 내용 근거와 적용 범위

2026-10-17에 아래 페이지 본문을 다시 확인했다. 교육 내용의 근거이며 앱이 해당 기관과 제휴했거나 기관 인증을 받았다는 뜻은 아니다.

- [경찰청 전기통신금융사기 통합대응단 — 보이스피싱, 이것만 기억해](https://www.counterscam112.go.kr/campaign/index.html): 피해가 발생하면 즉시 112에 알리라는 안내, 기관·지인 사칭 및 출처 불명 문자 주소 주의 내용을 참고했다. 캠페인의 안전 지수나 피해 방지 보장 표현은 게임 결과에 사용하지 않는다.
- [한국금융소비자보호재단 — 신고·피해구제 기관 안내](https://kfcpf.or.kr/front/protect/reportingAgency.do): 송금했을 때 경찰 또는 금융회사 등에 즉시 알리고 지급정지를 요청하는 절차, 정보 노출 후 보호 조치 안내를 참고했다. 복잡한 환급 심사·제출 절차 전체를 구현한 것은 아니며 환급을 보장하지 않는다.
- [금융위원회 — 최근 금융권 개인정보 유출사고에 따른 보이스피싱·스미싱 등 피해에 주의하세요 (2026-10-06)](https://www.fsc.go.kr/po010101/87882): 상대가 개인 정보를 알고 있어도 정상 연락의 증거가 아니라는 점, 자산 보호 명목의 이체 요구와 불명확한 문자 주소를 경계하고 공식 채널로 직접 확인하라는 내용, 금전 피해 발생 시 즉시 경찰/금융회사에 지급정지를 요청하라는 내용을 반영했다.

개인정보가 노출되었거나 악성 앱이 설치된 실제 상황의 대응은 훨씬 넓다. 이 버전은 정보/금전 노출 후 **멈추고 도움 요청하기**의 입문 연습이며, 악성 앱 설치·기기 감염 진단·계좌 피해구제 절차 전체를 다룬다고 설명하지 않는다.

## 검증 범위

`__tests__/phishingSession.test.ts`는 네 시나리오, 정상 연락의 수락·거절, 도움 요청, 중단 전/잘못된 확인 거부, 무조건 차단만으로 완료 불가, 정상 연락 차단을 성과로 표시하지 않음, 신고·금융회사 도움 후 회복 흐름, 완료 후 불변성과 메모리 재진입을 검사한다.

2026-10-17 검증 결과:

- `pnpm typecheck` 통과.
- `pnpm test`: 100개 suite, 1,094개 테스트 통과. 기존 일부 테스트의 `act(...)` 경고는 남아 있다.
- 최종 변경 후 core·PhoneSafety·퀘스트/앨범·HUD 통합·기존 GameHud의 5개 suite, 48개 테스트 재검증 통과. 위 전체 테스트 수와 중복되는 테스트이므로 합산하지 않는다.
- `pnpm build:web` 통과. 로컬 Expo의 iOS 번들도 HTTP 200으로 생성 확인했다. 실제 iPhone의 렌더링·입력 확인과는 다르다.
- 웹 375×812에서 민수 직접 방문/저장된 연락처, 기관 사칭과 가상 송금 후 신고·금융회사 상담, 택배 주문 내역 확인, 정상 연락 확인 후 거절, 사진 앨범 상세까지 직접 플레이했다. 375×667에서도 결과 화면의 버튼이 표시되는지 확인했다.
- `git diff --check` 통과. Windows 줄바꿈 변환 안내는 있으나 공백 오류는 없다.
- `pnpm exec expo install --check`는 설치된 Expo 57 패키지들의 최신 패치 버전 권고로 실패한다. 이번 기능 때문에 SDK나 의존성을 변경하지 않았다. 예: `expo 57.0.21 → ~57.0.30`, `@expo/metro-runtime 57.0.15 → ~57.0.17`, `expo-asset 57.0.16 → ~57.0.20`.

이 문서는 Expo Go 실제 기기나 당사자 플레이 테스트가 완료됐다는 근거가 아니다. 개발용 웹 확인 주소는 `http://localhost:8081/?phishingPreview=1&muteAudio=1`이며, 일반 플레이는 퀘스트 또는 게임 휴대폰의 메시지 앱에서 진입한다.
