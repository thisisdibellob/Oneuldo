# 사용자 제공 플레이어 동작 v3

사용자의 `walk1.png`, `walk2.png`, `sprint.png`, `idle.png`에서 분리한 게임용 이미지다. 새 캐릭터를 그리거나 얼굴·팔다리를 합성·변형하지 않았다. 걷기 8방향, 달리기 8방향, 앞·뒤 대기 애니메이션을 제공한다. 원본 시트는 중복으로 포함하지 않으며, SHA-256과 분리·정렬·프레임 대응 정보는 `provenance.json`에 기록한다.

## 게임 매핑

- `frontend/src/game/chibiPlayerAvatar.ts`의 `chibiPlayerAvatar`에서 정적 Metro require를 사용한다.
- 걷기 뒤 정면만 walk1에서 가져오고, 나머지는 walk2의 실제 방향 및 좌우 반전으로 구성한다.
- walk2의 네 번째 원본은 **뒤왼쪽**이며 뒤오른쪽은 좌우 반전이다.
- 달리기 뒤대각선은 게임 내 방향 피드백에 따라 두 이미지 묶음의 연결을 교환했다. 실제 뒤왼쪽 달리기는 `back_right_sprint` 파일, 뒤오른쪽 달리기는 `back_left_sprint` 파일을 사용한다. 파일명과 아래 출처 표는 최초 추출 이름을 유지하며, 실제 이동 방향은 `chibiPlayerAvatar.ts`의 연결을 따른다. 재생성 시에도 이 교환을 유지한다.
- 대기는 앞·뒤 각각 36프레임, 62.5ms/프레임(16FPS), 한 주기 약 2.25초다. 뒤·뒤왼쪽·뒤오른쪽은 뒤 대기를 공유하고, 나머지는 앞 대기를 공유한다. 대기 그림을 방향마다 중복 저장하지 않는다.
- 걷기와 달리기의 주기가 방향마다 달라 전체에 같은 프레임 수를 강제하지 않았다.

## 크기와 추출

- 1x PNG 128×192, @2x PNG 256×384. 논리 기준점 (64, 186).
- 선택한 고유 프레임 274장 × 2밀도 = **PNG 548장**이다.
- 시트별 정면·뒤 00의 서 있는 신장만으로 한 배율을 정하고, 시트 전체에 동일하게 적용했다. 00의 바닥 높이는 같은 기준으로 맞췄다. 달리며 다리를 접는 자세를 기준으로 키를 키우거나 매 프레임 발 높이를 고정하지 않았다.

원본의 인물 간격과 묶음 경계가 균등하지 않아 행 전체의 연결된 인물을 분리했다. 일부 달리기 그림은 머리 끝이 서로 닿아 원본에서 가장 좁은 접점을 따라 나눴다. 가려진 부분을 새로 그리지 않았으며, 해당 프레임 정보는 추출 검증 보고서에 기록했다. 배경은 바깥에 연결된 밝은 부분만 제거했고 옷·신발 내부 색을 보존했다. idle의 베이지 배경은 실제 배경색을 추정해 테두리 번짐을 처리했다.

원본 이미지 자체의 일부 달리기 뒤 동작은 진행 중 조금 옆으로 기울어 보인다. 추출 과정에서 방향을 새로 그리거나 포즈를 교정하지 않았다.

재생성 작업 폴더는 `output/player-actions-2026-09-23/`다. 원본 네 파일을 보관한 뒤 `process-actions.cjs`, `finalize-loops.cjs`, `validate-exports.cjs` 순으로 재생성·검증할 수 있다. 선택 구간은 `loop-selection.json`에 있다. 원본 4개 파일의 체크섬, 전체 추출 manifest, 처리 스크립트 체크섬을 함께 보존한다. 이전 `chibi-user-v1/`, `chibi-user-v2/`는 삭제하지 않는다.
