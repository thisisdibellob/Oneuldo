# 마트 v6 — 장바구니 팝업·입구 공사·모퉁이 지점

2026-09-13 · 오늘도 프론트엔드 · 브랜치 `feat/8-시뮬레이션-게임-ui-제작`

이번 작업은 진열대 안의 장바구니와 배경을 정리하고, 선택 가능한 입구 공사 조건과 건물 구조가 다른 세 번째 마트를 추가했습니다. 사람과 AI 실행기가 같은 환경·충돌·구매 규칙을 사용하도록 기존 설정과 행동 기록에도 새 조건을 연결했습니다.

## 최신 요청 9개와 반영 결과

| 번호 | 요청 | 반영 내용 |
|---|---|---|
| 1 | 직원 선택지에서 그만두기 제거 | 직원 대화에서 게임을 그만두는 선택지를 제거했습니다. 계산 요청·물건 반납 도움·대화 종료는 유지합니다. 게임 전체의 포기 기능은 기존 화면에서 사용할 수 있습니다. |
| 2 | 감사 인사 문구 수정 | 대화를 닫는 선택지를 **“아니에요, 감사합니다.”**로 바꿨습니다. 눌렀을 때 직원 대화가 닫히고 매장으로 돌아갑니다. |
| 3 | 작은 텍스트 비프음 키우기 | 마을·직원 대화의 공통 재생 볼륨 계수를 **0.12 → 0.30**으로 높였습니다. 신호 진폭 계수는 2.5배, 계산상 약 **+7.96dB**입니다. 기존 부드러운 파형과 재생 간격 제한은 유지했습니다. 이는 볼륨 계수 변화이며 실제 청감이 2.5배라는 뜻은 아닙니다. |
| 4 | 장바구니를 애니메이션이 있는 가로 팝업으로 | 상품을 위로 밀어 올리던 아래 펼침을 중앙 팝업으로 교체했습니다. 가로로 넘기는 각 카드에 **이미지 → 상품명 → 개당 가격 → 담은 수량**을 표시합니다. 현재 진열대 상품은 1개씩 내려놓고, 다른 상품에는 돌아갈 진열대를 안내합니다. 총금액은 표시하지 않습니다. |
| 5 | 계산대 번호 표지 조정 | `1`·`2` 표지 폭을 **48**, 숫자 크기를 **18**로 조정했습니다. 접근성 설명에는 계산대라는 의미를 유지합니다. 모퉁이 지점은 계산대 위쪽 좌표 y870, 직원·고객 접근점 y930으로 맞춰 주변 통로와 간격을 확인했습니다. |
| 6 | 진열대 UI의 상하 끊김 제거 | 음료 코너의 하늘색 띠 등 분류별 배경 차이를 없앴습니다. 기존 선반 그림에 맞춘 크림색 바탕과 위아래로 이어지는 세로 프레임을 적용하고 헤더·하단 배경을 투명하게 처리했습니다. |
| 7 | 공동 출입문 가까이에서 시작 | 기본·가로 통로·모퉁이 지점 모두 공동 출입문 안쪽 로비에서 시작하도록 했습니다. 문 앞에서 시작해 실제 통로를 따라 매장으로 들어갑니다. |
| 8 | 선택 가능한 입구 공사와 우회 | 설정에서 공사 여부를 선택할 수 있습니다. 새 펜스 이미지와 실제 충돌을 함께 배치하고, 막힌 입구로 이동하거나 상호작용하지 못하게 했습니다. 옆문 또는 출구로 돌아갈 수 있습니다. |
| 9 | 전체 건물 구조가 다른 세 번째 마트 | **모퉁이 지점**을 추가했습니다. 진열대만 재배치한 것이 아니라 건물 크기·외벽·판매장·오른쪽 복도·엘리베이터실·로비·공동문·계산대·NPC/오브젝트 후보 위치를 바꿨습니다. 동일한 구매·반납·직원 도움을 수행할 수 있고 입구 공사와도 조합됩니다. |

## 화면에서 설정하는 방법

1. 마트에 입장해 장보기를 시작하기 전 **연습 환경 설정**을 엽니다.
2. **매장 배치**에서 **기본 배치 / 가로 통로 배치 / 모퉁이 지점**을 선택합니다.
3. **매장 입구 공사**에서 **공사 없음 / 입구 공사 중**을 고릅니다. 인원·기둥·계산원·키오스크·진열대 섞기 등도 함께 설정할 수 있습니다.
4. **설정 적용**을 누른 뒤 시작 안내를 진행하고 **장보기 시작**을 누릅니다.

설정은 게임 시작 전에 적용합니다. 진행 중인 장바구니나 시도 횟수를 다른 매장으로 옮기는 기능은 아닙니다. **연구용 상세 설정 · JSON 가져오기**와 **설정 JSON 저장**을 이용하면 동일 조건을 팀원에게 전달할 수 있습니다.

공사 조건은 **판매장과 아래 로비 사이의 안쪽 입구 하나**를 막는 것으로 해석했습니다. 건물 밖으로 이어지는 공동 출입문까지 닫으면 게임 진입·퇴장이 막히므로 공동문은 열어 둡니다. 별도 출구와 옆문도 유지하며, 기본·가로 통로 지점은 서쪽 문, 모퉁이 지점은 동쪽 문을 이용합니다. 우회문에도 기존 미결제 반출 경보가 적용됩니다.

## 정우·재현에게 전달할 환경 변수

아래는 전체 세션 설정 중 `environment`에 추가하거나 변경할 부분입니다.

```json
{
  "environment": {
    "layoutId": "corner",
    "entranceConstruction": true
  }
}
```

| 필드 | 값과 의미 |
|---|---|
| `environment.layoutId` | `classic`: 기본 지점, `aisles`: 가로 통로 지점, `corner`: 모퉁이 지점. 생략하면 `classic`. |
| `environment.entranceConstruction` | boolean. `true`: 안쪽 입구 공사, `false`: 공사 없음. 생략하면 `false`. |
| `seed` 및 기존 환경 설정 | 같은 코드 버전·시드·설정으로 재현합니다. 인원·위치 후보·진열대 순서·재고·난이도 설정은 그대로 함께 사용할 수 있습니다. |

모퉁이 지점의 월드는 **1280×1380**이며 기본·가로 통로 지점의 **1100×1500**과 다릅니다. 따라서 AI가 좌표를 고정해서 재사용하면 안 됩니다. 관측의 실제 `environment.world`, `walkableAreas`, `obstacles`, `stationDetails`, `alarmGates`를 읽어야 합니다. 공사 상태는 `constructionZones`와 입구 station의 `available:false`에도 기록되며, 모퉁이 옆 경보기 ID는 `east-door`입니다.

행동 어댑터는 기존처럼 관측·최대 32px 이동·상호작용을 사용합니다. AI의 좌표 순간이동은 허용하지 않습니다. 터치 길찾기는 펜스를 피해 실제 열린 문으로 우회하며, 위치 회복도 경보기 경계를 넘어 미결제 반출을 건너뛰지 않도록 제한했습니다.

- 상세 계약: [환경·행동·결과 인터페이스](../frontend/docs/market-agent-contract.md)
- 바로 실행할 설정: [모퉁이 지점 + 공사 예제 JSON](../frontend/docs/examples/market-corner-construction.json)
- 앞선 진열·조작 변경: [마트 v5 보고서](market-v5-assortment-layout-interaction.md)

환경 `layoutVersion:3`, 관측 `schemaVersion:1`, 에피소드 `version:1`을 유지했습니다. 과거 기록은 저장된 환경 스냅샷을 기준으로 해석해야 하며, 코드 변경 전후에 시드만 같다고 배치까지 같다고 가정하지 않습니다.

## 유지한 학습·게임 규칙

종업원 1~3명, 손님 1~5명, 별도 계산원 0~2명과 두 계산대, 진열대 종류 섞기, 상품별 재고 설정을 유지했습니다. 진열대는 분류별 **서로 다른 12종·4열×3행**이며 350ms 길게 눌러 아래 장바구니에 놓는 조작과 담기 버튼을 그대로 사용할 수 있습니다.

목표 목록은 사야 할 개수만, 장바구니는 담은 개수를 표시합니다. 같은 분류 진열대에서의 반납과 종업원 도움, 계산원 호출, 최종 구매 전 오답 미고지, 제출 후 피드백·재시도·포기·별점 규칙도 유지합니다. 미결제 상품을 담고 열린 입구·출구·옆 경보기를 바깥으로 넘으면 기존 감점과 기록이 발생합니다. 합계는 계산대의 최종 구매 화면에서 확인합니다.

## 검증 결과와 확인 범위

- **TypeScript 통과**, 전체 **34개 테스트 스위트·298개 테스트 통과**.
- **웹·iOS·Android Expo export 모두 통과**.
- 세 배치 × 공사 켜기/끄기의 **6개 자동 실행 모두 성공**, 각 2회 제출·최종 100점. 실제 이동·직원 계산 요청·진열대 반납·직원 반납을 포함했습니다.
- 각 조합의 100개 시드, 총 **600개 최대 밀집 환경**에서 배치 및 상호작용 목적지까지의 경로 검사를 통과했습니다.
- 실제 브라우저의 **390×844 / 844×390**에서 팝업 가로 스크롤·반납·닫기를 확인했습니다. 팝업 전후 12개 상품의 위치와 높이는 같았으며, 작은 높이에서는 팝업 본문만 스크롤됩니다. 음료 배경의 하늘색 경계도 사라졌습니다.
- 메인 앱에서 모퉁이 지점 + 공사 표시, 공동문 근처 시작점, 직원 선택지 제거와 새 감사 인사로 닫기, 음료 장바구니 팝업과 바깥 영역을 눌러 닫기를 확인했습니다.
- 별도 검사 화면에서는 같은 입구로 직접 걸어가 공사 켜기 시 통과가 막히고, 끄면 정상 통과하는 것을 확인했습니다. 켜진 상태에서도 우회 경로로 진열대에 도착했습니다. 두 브라우저 검사 탭의 오류 로그는 없었습니다.
- 대화음은 파형·재생 볼륨 검사와 테스트로 확인했습니다. 브라우저 QA는 **`muteAudio=1`**로 진행했습니다. **실물 휴대폰에서의 청취·터치 검증은 하지 않았습니다.**

자동 실행은 기능 검사용이며 실제 장애인 플레이나 검증된 페르소나 행동 데이터가 아닙니다.
