# 도서관 첫 근무 게임 v1

## 2026-10-02 손님 부탁과 근무 설정

- 도서관에 들어오면 기본 손님 1명이 이미 서 있다. 실제 거리 150px 안에 가면 대화를 시작하지 않아도 작은 `이 책은...` 말풍선이 나타난다. 사서에게 업무를 받은 뒤부터 손님에게 말 걸 수 있다.
- 사서의 `근무 설정 바꾸기` 또는 업무 시작 전 수첩에서 설정한다. 손님 수 0·1·2명(기본 1명), 부탁 종류 섞어서·위치 안내·책 꽂기(기본 섞어서), 반납 도서 6·12·18권(기본 12권), 라벨 훼손 0·1·2권(기본 1권), 안내와 함께·혼자 해보기를 선택한다. 설정을 닫아도 선택은 유지되며, 업무 중에는 바뀌지 않는다. 재근무는 같은 설정에서 책을 새로 배정한다.
- `섞어서`는 한 명이면 두 부탁 중 하나를 배정하고 두 명이면 두 종류를 하나씩 배정한다. 두 손님은 서로 다른 책을 요청하며, 반납 카트의 책과도 겹치지 않는다.
- 위치 문의: 제목·청구기호 확인 → 번호가 붙은 서가 선택 → 손님과 동행 → 실제 서가에서 위치 안내. 한 번에 한 명만 동행한다. 정답 서가는 선택 전에 카드나 수첩에 표시하지 않는다.
- 책 정리 부탁: 관내에서 읽던 책 확인 → 수령 → 실제 서가에 배가 → 손님에게 돌아가 `책을 제자리에 꽂았어요`로 완료 보고. 잘못 꽂으면 다시 꺼내 고칠 수 있다. 책 수령과 배가만으로는 부탁이 완료되지 않는다. 손님 책은 일반 카트 6권과 별도로 들 수 있고, 수령한 책은 업무 권수에 포함된다.
- 손님 0명이면 손님 관련 완료 조건을 제외한다. 훼손 0권이면 정상 배가만 진행하며, 2권이면 각 책의 라벨 확인·사서 문의·확인함 전달을 모두 반영한다. 결과 화면은 실제 수행한 위치 안내·책 정리·사서 연결 건수를 표시한다.
- 기존 단일 손님 구조로 저장한 v1 완료 기록도 읽는다. 새 기록은 설정과 손님별 부탁·처리 결과, 손님에게 받은 책을 함께 보관한다.

검증: 도서관 관련 11개 테스트 파일 165개 테스트, 타입 검사, 웹 빌드 통과. 손님 0명 완료, 두 종류 부탁의 독립 완료, 손님 책 오배가 수정, 훼손 0·2권, 설정 유지와 구 v1 완료 기록 읽기를 검증했다. Expo 의존성 검사는 현재 설치된 SDK 57 패키지 10개의 최신 패치 버전 권고를 보고했다. 이번 기능 작업에서 패키지 버전은 변경하지 않았다.

브라우저 검수: 업무 시작 전 손님 근접 말풍선과 대화 차단, 375×812 설정 화면, 손님 2명에게 서로 다른 부탁을 받아 위치 안내와 실제 배가·완료 응대를 모두 수행한 뒤 수첩의 `손님 부탁 2 / 2`를 확인했다. 실제 Expo Go 기기에서의 터치 조작은 별도로 확인하지 않았다.

## 2026-10-01 큰 창문과 손님 동행 안내

- 뒤벽 폭은 1660→1860으로 늘리고 창문은 110×99→180×162로 키웠다. 창턱은 바닥보다 50px 위로 내려왔다. 창문·연결 서가가 번갈아 나오는 배치와 책장의 20px 전진, 인물·가구·카메라 비율은 유지한다.
- 첫 반납 도서를 가져오면 카트 옆 이용자가 요청 말풍선과 함께 나타난다. 이용자가 요청하는 도서는 해당 근무의 반납 책과 겹치지 않는 소장 도서다.
- 말 걸기 → 요청 듣기 → 책 위치 확인 → 서가 선택 → 같이 이동 → 실제 서가에서 마지막 안내 → 감사 대화 순서다. 손님은 플레이어가 걸은 경로를 따라오며, 대화·휴대폰을 열면 함께 멈춘다. 안내 도중에는 업무 수첩에서 요청한 책과 목적 서가를 다시 확인할 수 있다.
- 정답 선택은 `escorting` 상태로 전환하며 즉시 완료되지 않는다. 목적 서가에 접근해 `여기에서 찾으실 수 있어요`를 선택해야 `finishVisitorGuide`로 완료한다. 오답은 다시 확인할 수 있고, 기다려 달라고 응대를 미루거나 기존 사서 연결 방식으로 도움을 요청할 수도 있다.
- 위치 확인 카드에는 책 제목·표지·청구기호만 표시하고 정답 서가를 미리 표시하지 않는다. 선택지에 `300 사회과학`처럼 KDC 번호를 함께 표시해 청구기호와 비교하도록 한다. 수첩도 선택 전에는 청구기호만 기록하고, 올바른 서가를 선택한 뒤에만 안내 목적지를 표시한다.
- 기존 완료 기록 형식은 유지한다. 새 동행 완료는 `visitor_guide_completed` 이벤트를 추가하며, 중복 완료·조기 완료·잘못된 서가 도착을 거절한다. 진행 중 근무 저장 방식은 변경하지 않는다.

검증: 도서관 관련 10개 테스트 파일 140개 테스트, 타입 검사, 웹 빌드 통과. 브라우저에서 첫 카트 수령 후 요청 발생과 375×812 화면에서 검색·동행·서가 도착·감사 대화를 직접 확인했다. 실제 Expo Go 기기 조작은 이번 검증에 포함하지 않았다.

## 2026-10-01 연결 서가 배치 v6

독립된 책장 10개를 뒤벽 연결 서가 여섯 칸(000~500)과 중앙 양면 서가 네 칸(600~900)으로 다시 구성했다. 네 종류의 새 이미지는 같은 밝은 목재·갈색 외곽선·세이지 받침과 정면 투시를 사용하며 책 배치만 달리한다. 뒤벽은 **창문 → 책장 세 칸 → 창문 → 책장 세 칸 → 창문** 순서다. 두 연결 서가는 동일하게 570×174.8로 원본 비율을 유지하고, 가구 밑동을 벽·바닥 접점보다 20px 앞으로 놓아 두께와 얕은 접지 그림자가 보이게 했다. 창턱은 바닥보다 90px 높고, 창문과 책장 사이 간격은 모두 20px이다. 중앙 두 양면 서가 사이에 200px 통로를 확보했다. 분류 이름과 번호는 18px 한 줄로 가구 헤더에 붙였으며 바닥 분류 카드를 없앴다.

벽 뒤쪽은 걸어갈 수 없으며 중앙 서가의 양옆·앞뒤는 계속 이동할 수 있다. 10개 KDC 분류와 실제 52권 검색, 반납·배가·돌발상황·보고 흐름은 유지했다. 새 그림 원본·프롬프트·모바일용 이미지·검수값은 `frontend/assets/images/game/library/v6/`에 보관한다.

검증: 타입 검사와 도서관 관련 10개 테스트 파일 126개 테스트 통과. 독립 가구 10개가 연결 가구 4개로 통합되어 가구별 매개변수 테스트 수는 줄었으며, 각 KDC 분류 접근·벽 뒤 차단·양면 서가 양옆과 앞뒤 통로 회귀 검사를 추가했다.

추가 검증: 최종 창문 배치와 모바일 카메라 조정 후 공간·렌더 관련 2개 파일 63개 테스트 및 타입 검사 통과. 375×812와 320×568에서 여섯 벽 서가의 실제 상호작용 위치에서도 표지가 업무 카드에 가리지 않으며 발 아래 중앙 툴바 여백이 28px 이상 남는다. PC 카메라는 유지한다.

## 2026-10-01 실내 연출 보강

기존 방 크기와 인물·가구 비율을 유지하면서 따뜻한 목재·크림·세이지 중심으로 실내를 정리했다. 새 투명 아치 창문 네 개, 낮은 추천 도서 전시대 두 곳, 화분 세 곳을 배치하고 벽 몰딩·하부 목재 패널·작은 시계와 벽등을 추가했다. 서가·디지털 열람·중앙 라운지·안내 데스크·입구는 절제된 색의 러그와 발매트로 구분한다. 기능을 설명하는 장식용 문구나 반짝임 효과는 추가하지 않았다.

전시대와 화분은 이미지 밑동만 충돌 범위로 쓰며 캐릭터의 발 높이에 따라 앞뒤 표시를 바꾼다. 10개 서가와 모든 업무 지점의 위치는 동일하다. 새 런타임 이미지 세 개는 총 918,828바이트이고 384–640px PNG에 생성 당시 알파를 보존했다. 원본·프롬프트·파일 검수값은 `frontend/assets/images/game/library/v5/`에 있다.

검증: 도서관 관련 10개 테스트 파일 130개 테스트 및 타입 검사 통과. 모든 시설 간 이동, 큰 이동량의 충돌 방지, 새 전시대·화분 다섯 곳과 PC·데스크·라운지 앞뒤 표시, 기존 근무·검색·가이드북 흐름을 확인했다.

## 2026-10-01 공간·도서·가이드북 확장

현재 구현은 아래의 초기 v1 설명에서 다음 항목을 확장했다.

- 전체 가상 도서 **26 → 52권**, 표지도 신규 26종을 생성하여 각 도서 ID에 연결했다. 실제 책으로 오인하지 않도록 제목·도서기호는 게임용 창작 자료로 관리한다.
- 한 근무에 **12권**을 맡는다. KDC 10개 분류가 모두 포함되고 두 분류에서 추가 책이 나온다. 한 번에 가지고 다니는 책은 최대 6권이며, 남은 책은 반납 카트에서 이어서 가져온다. 최종 보고는 정상 배가 11권·담당자 전달 1권이다.
- 예전 6권 근무 기록과 새 12권 근무 기록을 함께 읽는다. 기존 완료 기록은 변경하거나 삭제하지 않는다.
- 방은 **1360×1240 → 1660×1520**, 면적 약 1.50배다. 플레이어·사서·기존 가구 표시 비율과 카메라 확대는 유지했다.
- 안내 데스크 폭은 178 → 356으로 두 배이며, 사서 자리와 사용자 검색 자리가 함께 있는 새 투명 이미지를 사용한다. 사용자 쪽에서 **도서 검색**을 열면 실제 52권을 제목·소수점 분류번호·KDC 분류로 검색하고, 반납 카트·소지 중·서가·확인함의 현재 위치를 확인할 수 있다. 업무 수령 전에도 사용할 수 있다.
- 중앙에는 새로 생성한 6인 독서 라운지를 둔다. 라운지 표시 크기는 250×114로 인물과 의자 높이를 맞췄다. 앞쪽 의자는 테이블을 향하고, 가구의 바닥 충돌과 정수 깊이값을 맞춰 캐릭터가 앞을 걸으면 가구 앞에 표시된다.
- **수첩 → 도서 알바 가이드북**에서 업무 받기, 청구기호 읽기, 배가, 훼손 자료 확인, 이용자 안내, 완료 보고를 여섯 장으로 읽는다. 업무 전후 모두 열 수 있고 분류표를 보고 돌아오면 읽던 장을 유지한다. 실제 배가의 세부 순서와 게임의 대분류 연습 범위를 구분한다.
- 휴대폰의 공통 노선도와 바로 이동 메뉴를 이어받는다.

검증: 도서관 관련 10개 테스트 파일 120개 테스트 및 타입 검사 통과. 전체 52권 배정·검색, 12권 두 차례 운반과 완료 보고, 기존 6권 기록 읽기, 모든 시설 사이의 충돌 없는 이동, PC·확장 데스크·독서 라운지 앞뒤 표시, 검색·필터·가이드북 복귀를 확인했다. 375×812 브라우저 화면에서 새 검색창과 가이드북의 가독성도 확인했다. 그림 원본·생성 프롬프트·검수 이미지는 `frontend/assets/images/game/library/v4/`에 보관한다.

## 플레이 흐름

1. 마을 도서관 앞에서 입장한다. 마을의 조작 설정을 이어받고, 나갈 때는 도서관 입구 앞으로 돌아온다.
2. 사서에게 업무를 받으며 **안내와 함께 / 혼자 해보기**를 선택한다. 반납 전산처리가 끝난 책 6권을 맡는다. 전체 26권·KDC 10개 분류 중 매번 서로 다른 여섯 분류에서 한 권씩 배정한다.
3. 북카트에서 책의 제목과 라벨을 확인하고 책을 가져온다. 책은 이야기·자연·생활 12종 중 분류별 2권씩 선택되며, 이 중 정확히 1권의 라벨이 훼손되어 있다.
4. 정상 라벨 5권은 분류에 맞는 서가에 꽂는다. 잘못 꽂아도 책을 다시 눌러 꺼내고 다른 서가에 옮길 수 있다.
5. 훼손 라벨을 확인한 뒤 사서에게 **이 책의 라벨이 안 보여요**라고 묻는다. 안내받은 책은 옆의 담당자 확인함에 둔다. 사서 확인 전에는 전달할 수 없고, 훼손된 책을 일반 서가에 꽂을 수도 없다.
6. 책 2권을 올바르게 처리하면 이용자가 나타난다. 찾는 책의 위치를 확인해 해당 서가를 안내하거나 사서에게 연결한다. 두 방식 모두 정상 완료로 처리한다. 잘못 안내한 경우 다시 확인할 수 있다.
7. 사서에게 **정리를 마쳤어요**를 선택하고 서가·확인함의 권수를 보고한다. 정상 서가 5권, 확인함 1권, 이용자 안내 완료, 실제 상태와 일치하는 보고를 모두 만족해야 완료된다.
8. 결과 화면에서 처리 권수, 안내 방식, 잘못 놓은 책을 고친 행동을 확인한다. 만족도 1~5점을 남기거나 마을로 돌아가며, **한 번 더 근무하기**로 새 책 구성을 시작할 수 있다.

현재의 확인함은 게임 속 도서관의 규칙이다. 분류와 청구기호는 입문 과제를 위한 단순화된 설정이며, 같은 서가 안에서 세부 청구기호 순서까지 정렬하는 과제는 포함하지 않는다.

## 조작과 안내

| 기능 | 조작 |
| --- | --- |
| 이동 | 모바일 조이스틱, 터치 모드의 바닥 탭, 웹 방향키/WASD |
| 시설 이용 | 사서·서가·카트를 누르면 접근 경로를 따라 이동한 뒤 이용. 가까이에서는 우측 이용 버튼 또는 웹 E/Space |
| 책 꽂기 | 책을 눌러 선택한 뒤 **이 서가에 꽂기**, 또는 약 260ms 길게 눌러 서가로 드래그 |
| 수정 | 서가에 꽂힌 책을 눌러 다시 꺼낸 뒤 올바른 서가에 배치 |
| 도움 | 업무 수첩, 책등 라벨 확대, 사서의 업무 설명 다시 듣기 |
| 이동 복구 | 공통 메뉴의 위치 복구로 실내 출입문 앞으로 이동 |

**안내와 함께**는 현재 업무 대상에 표식을 표시하고 상단 업무 카드를 눌러 해당 위치로 이동할 수 있다. **혼자 해보기**는 이 대상 표식과 업무 카드의 목적지 이동 안내를 끈다. 기본 업무 문구·수첩·질문 기능·시설을 직접 누르는 이동은 두 방식 모두 사용할 수 있다. 도움 사용은 사용 내역으로 기록하며, 질문 자체에 감점을 주지 않는다.

대화·패널·휴대폰 메뉴를 열면 월드 이동 입력을 잠근다. 책을 드래그하는 동안 패널 스크롤을 잠그고 손을 놓으면 복구한다. 실제 터치 드래그는 기기별 수동 확인이 필요하며, 탭으로 꽂는 대체 조작을 함께 제공한다.

백엔드 업로드·AI 분석·계정별 서버 기록 연동은 포함하지 않는다. 네이티브 환경 또는 브라우저 저장소 사용이 차단된 환경에서는 앱 실행 중 메모리에만 보관하며 재실행 후 영구 보존을 보장하지 않는다. 진행 중 근무의 중단 복구는 구현하지 않았으므로 중간에 나가면 다음 입장에서는 새 근무를 시작한다. 만족도는 사용자가 남기는 주관적 응답이며 수행 점수가 아니다.

## 검증

`pnpm typecheck`, `pnpm build:web`를 통과했다. 전체 테스트를 한 번 실행해 기존 게임 테스트의 통과를 확인했고, 그 실행에서 발견된 신규 연결·테스트 모킹 문제 3건을 수정했다. 수정 후 도서관·입장·폰트·공통 HUD 관련 8개 스위트 82개 테스트를 다시 실행해 모두 통과했다. 추가한 실내 터치 좌표 회귀 테스트 5개도 통과했다(관련 검증 총 9개 스위트, 87개 테스트).

브라우저의 375×812 화면에서 업무 수령 → 책 6권 확인 → 훼손 책 질문·전달 → 정상 책 5권 배치 → 이용자 위치 안내 → 5권/1권 보고 → 별점 → 마을 복귀 → 재입장을 실제 조작으로 완료했다. 768×1024와 1280×800 배치, 휴대폰 나가기 취소 후 입력 복구, 확대된 화면의 바닥 터치 도착 위치도 확인했다. 웹 콘솔 오류는 없었다. 실제 iPhone/Android의 손가락 드래그·오디오·햅틱은 기기에서 추가 확인이 필요하다.

`pnpm exec expo install --check`는 기존 Expo 57 패키지 10개의 권장 패치 버전 차이를 보고했다. 이번 작업에서 의존성 버전은 변경하지 않았다.
