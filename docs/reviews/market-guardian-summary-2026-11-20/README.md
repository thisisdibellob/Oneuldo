# 장보기 게임·보호자 대시보드 변경 사항 통합 정리

정리 기준일: **2026-11-20, 한국 시간**. 이 대화에서 진행한 장보기 UI·훈련·경로·NPC·성능 수정과 독립 보호자 앱을 묶었다. 과거 작업은 당시 기록을 근거로 정리했으며, 모두 이날 새로 구현·촬영·검증했다고 표기하지 않는다. 주차·수행 시간·사용자 학습 효과는 추정하지 않는다.

**현재 상태:** 장보기 쪽은 게임 UI와 훈련·이동 경로 기능을 구현했다. 품절 후 직원 확인과 전화 대체 구매는 기존 구현이 유지된다. 보호자 앱은 독립 프로젝트의 UI·시연·API 클라이언트와 명세를 만들었고, **실제 부모–자녀 연결과 실데이터 조회는 미연결**이다.

## 1. 설정 메뉴·배치 편집 통합

| 이전 또는 문제 | 변경 후 현재 상태 |
| --- | --- |
| 설정창과 그리드 편집의 배치·JSON 진입이 중복되어 역할이 모호함 | 같은 마트 설정으로 진입. 기본 설정 / 상황 설정 / 세이브·로드로 정리 |
| 설정 항목이 긴 한 화면에 나열됨 | 기본 배치·시설 설정과 연습 조건을 구분하고 세부 항목은 펼쳐 보기 |
| 편집 화면의 도구·목록·미리보기가 함께 노출됨 | 그리드 편집 / 테스트 / 보관함을 구분하고 필요한 목록만 펼침 |

| 스크롤 끝이 패널 경계에서 갑자기 잘림 | 남은 내용에 따라 상·하단 가장자리 페이드 표시. 페이드는 제거하지 않음 |

두 JSON을 하나의 의미로 합친 것은 아니다. 전체 설정은 과제 조건까지, 배치 파일은 공간 재사용을 위한 형식이다. 플레이 중 배치 변경은 장바구니·점수·진행을 유지하는 기존 규칙을 따른다. ‘재현용 시드’는 같은 조건의 배치를 다시 만드는 데 사용한다. 시안에만 있던 반전 도면·출구 공사를 새 기능으로 구현했다고 기록하지 않는다.

## 2. 게임 진입 화면·이미지·캐릭터 표시

- GameEntry1을 참고해 긴 시작 전 안내를 카트·제목·연습/도전 선택·시작·기록·종료·설정 중심의 한 화면으로 바꿨다. 자세한 설명은 게임 안 이용 방법에서 확인한다.
- 참고 스크린샷의 배경 사진을 게임 배경으로 붙이지 않았다. 최종 상태는 실제 마트 위에 설정과 같은 어두운 레이어를 적용하며 **배경 흐림은 제거**했다.
- 모드 선택의 외곽선과 흰 선택 배경을 별도 레이어로 맞춰 상하·선택 쪽 간격을 통일했다. 버튼을 누를 때 흰 배경 자체가 움직이지 않게 했다.
- 카트의 부드러운 등장·약한 부유와 버튼 누름 피드백을 적용했다. 모션 감소 설정에서는 장식 움직임을 줄인다.
- 마트 진입 직후 잠깐 다른 위치가 보이는 문제에 대응해 첫 표시 전에 마트 배율과 스폰 카메라를 함께 적용하도록 바꿨다.
- 카트 표시용 PNG를 약 2.06MB에서 0.44MB로 줄였다. 원본과 투명도·비율은 보존했다.
- 방향·걷기·달리기 전환 중 새 이미지를 기다리는 동안 기존 걷기를 이어가고, 최근 디코딩 이미지 재사용과 제한적인 미리 읽기를 추가했다.
- 카메라와 캐릭터가 같은 Animated 좌표 그래프를 사용하도록 정리했다. 모든 Expo 기기의 버벅임·출렁임이 사라졌다고 검증한 것은 아니다.
- Metro가 생성 원본·보고서·브라우저 프로필을 감시하지 않도록 출력 폴더를 제외했다. 앱 코드·런타임 이미지·의존성은 유지한다.
- `marketLab=1`은 같은 장보기 컴포넌트의 개발용 단독 진입, `muteAudio=1`은 검사 중 음소거다. 별도 게임 리소스를 쓰는 모드는 아니다. 사용자에게는 일반 앱 주소를 우선 안내한다.

자료: [시작 화면·성능·여백·선택 메뉴 기록](../market-entry-2026-11-13/README.md).

## 5. 품절 → 직원 확인 → 전화 대체 구매: 기존 기능 유지

**삭제되지 않았다. 이번 확인은 기존 흐름이 남아 있는지 코드로 재확인한 것이며, 새로 추가한 기능으로 계산하지 않는다.**

1. ‘품절 상황 있음’으로 시작한 과제에서 해당 매대를 열어 품절을 확인한다.
2. 직원에게 접근해 ‘재고 있나요?’를 선택한다. 매대를 먼저 살펴봐야 질문이 나타난다.
3. 직원이 재고 없음으로 확인한다.
4. 부탁한 사람에게 전화해 ‘○○로 바꿔도 될까요?’를 선택한다.
5. 승인되면 구매 목표와 목록이 대체 상품으로 변경된다.
6. 대체가 불가능한 조건에서는 못 산 이유를 보고하고 해당 목표를 제외하는 흐름이 있다. 더 비싼 대체 상품은 예산 승인을 별도로 받는 분기도 있다.

설정 경로: **설정 → 상황 설정 → 품절 상황 있음 / 대체 상품 허용**. 일부 기본 미션은 품절을 끄고 시작하도록 되어 있어 모든 장보기에서 항상 나타나지는 않는다.

**구현 한계:** 현재 이 품절 과제의 직원 답변은 ‘창고에도 없어요’로 고정된다. ‘창고에는 있으니 가져다준다’는 재고 있음·보충 분기는 구현되어 있지 않다.

## 6. 결과 지도·동선 재생·행동 시점

- 실제 허용된 이동 기록을 선으로 표시하고, 시간별 위치와 머문 구간을 확인한다. 위치 간격은 2·5·10초로 선택한다.
- 경로를 툭툭 건너뛰는 대신 연속적으로 그리며 재생한다. 일시정지·이어 재생·처음·이전·다음·전체 보기를 제공한다.
- 흰 경로를 2→3px로 키우고 옅은 외곽선을 더해 대비를 높였다. 현재 위치 표시도 키웠다.
- **매대 열기·닫기, 상품 담기·내려놓기, 종업원에게 말 걸기**의 당시 시간과 캐릭터 위치를 마커로 표시한다.
- 가까운 행동은 묶어 표시하고, 종류별 필터와 타임라인·마커 선택으로 해당 순간을 확인한다.
- 지도 글꼴을 Pretendard로 바꾸고 이름·시간 글씨를 키웠다. 입구·출구·매대 이름을 표시한다.
- SVG 경로 그림과 JSON 기록 내보내기에 반영했다. 배치가 바뀐 구간은 선을 연결하지 않는다.
- 과거 기록에 정확한 행동 좌표가 없으면 마지막 확인 위치라는 표시를 남긴다. 정확한 측정값으로 꾸미지 않는다.

현재 완료 범위는 프론트엔드 결과·기록·episode 내보내기와 기존 행동 업로드 필드 확장이다. **백엔드 DB와 원격 보호자 분석 화면에서 실제 경로를 조회·저장하는 연동은 별도**다.

## 7. 독립 보호자 대시보드 ‘오늘도 함께’

기존 게임과 별도인 `guardian-app/` Expo 프로젝트를 만들었다. 자체 의존성·잠금 파일·에셋·앱 식별자·실행 서버를 가지며, 같은 저장소에서 별도 앱으로 관리한다. 모바일 하단 탭과 데스크톱 사이드바를 사용한다.

| 영역 | 구현·준비된 내용 | 현재 범위 |
| --- | --- | --- |
| 로그인 | 이메일·비밀번호 UI, 기존 인증 API용 클라이언트, PARENT 역할 확인 | 실제 서버 주소 미설정. 자녀 조회까지 실계정으로 연결 검증하지 않음 |
| 대시보드 | 완료 횟수·연습 시간·최근 기록·주간 수행 횟수·다음 연습 제안 | 가상 시연 자료로 확인 |
| 자녀 선택 | 자녀별 기록 전환, 이전 상세 화면 닫기 | 시연 가능. 실제 관계 연결은 서버 구현 필요 |
| 훈련 기록 | 최근 7/30일, 장보기·버스·도서관 필터, 기록 상세 | 시연 가능. 실제 각 게임 결과 수집 연동은 별도 |
| 분석 상세 | 관찰·해석·근거·지원 방법·다른 설명·분석 한계 | 예시 분석으로 UI 구현. 새 AI 분석 호출 없음 |
| 이동 경로 | 배치·입구·출구·동선, 1/2배속, 행동 위치 선택, 직원 대화 표시 | 예시 경로로 구현. 실제 자녀 기록 조회는 미연결 |
| 가족·설정 | 연결 코드 입력, 연결 해제 확인, 새로고침, 데이터 안내, 로그아웃 | 시연 연결은 가상 가족만 변경. 실제 승인·해제 API 필요 |
| 데이터 구분 | 시연 명시, 자녀 ID·자료 형식 확인, 로그인 실패 시 시연 결과로 대체하지 않음 | 클라이언트 구현. 서버 인가를 대신하지 않음 |

남은 필수 연결 작업은 부모–자녀 관계·공유 승인·코드 발급/만료/일회 사용, 요청마다 자녀 열람 권한 확인, 자녀의 실제 훈련·분석·경로 조회 API다. 기존 가입이 PARENT 기본값이고 게임 기록이 로그인 회원에 귀속되는 점도 정리해야 한다. 과거 부모 본인의 기록을 임의로 자녀 기록으로 바꾸지 않는다.

현재 인증은 토큰을 메모리에만 보관한다. 자동 로그인·토큰 저장/자동 갱신·앱스토어 배포는 구현하지 않았다. 이 앱은 게임 기반 **훈련 분석**이며 의료적 진단이나 장애 정도를 판단하는 화면이 아니다.

## 9. 검증·남은 작업·Git 상태

- 최근 장보기 조작·화살표·공사 변경: 관련 **13개 테스트 묶음 /149개 테스트**, 타입 검사, 웹 빌드 통과. 실제 브라우저 이동·직원 질문·가드레일 접근 확인.
- 보호자 앱: 관련 **3개 테스트 묶음 /15개 테스트**, 타입 검사, 웹 빌드, Expo 의존성 검사 통과. 1440×1050·390×844·320×640 브라우저에서 확인.
- 과거 전체 테스트 통과 기록과 이후의 관련 검사 실행은 별개다. 중복 테스트 수를 합쳐 전체 프로젝트가 현재 전부 통과했다고 표기하지 않는다.
- 이번 통합 정리는 기존 기록과 코드를 대조한 문서 작업이다. 새 플레이·모델 실험·전체 회귀 테스트를 다시 수행한 기록이 아니다.
- 실제 Expo Go 휴대폰의 최신 터치·성능, 운영 DB 수신·보호자 실데이터 연결, 실제 이용자 사용성·학습 효과는 별도 검증이 필요하다.
- 브랜치는 `feat/8-장보기-게임-구체화`. 이전 UI 작업을 develop 기준으로 반영한 상태이며 develop과 backend는 최근 작업에서 수정하지 않았다. 최근 추가 작업과 이번 문서를 새로 커밋·푸시하지 않았다.
- 캡처·검증 자료는 로컬에 보존되어 있다. 학교 외장하드 보관은 Windows 도구의 `os.O_DIRECTORY` 오류로 미완료다.

## 10. 활동일지에 사용할 수 있는 문장

장보기 설정과 배치 편집의 중복 진입을 통합하고, 사용자 시안을 바탕으로 설정·시작 화면을 재구성하였다. 피드백에 따라 배경 흐림, 하단 여백, 스크롤·탭 전환, 이미지 로딩과 캐릭터 표시를 보완하였다. 장보기 목록과 장바구니는 하단 버튼으로 분리하고, 매대 표지·직원 대화 표시·NPC 아트를 플레이어와 일관되게 정리하였다. 과제·지도·방향 힌트·돌발 상황을 조합해 테스트를 저장하도록 하고, 결과 지도에서 이동 경로와 매대·상품·직원 대화의 행동 위치 및 시간을 확인하도록 확장하였다. 품절 후 직원 재고 확인과 전화 대체 구매는 기존 구현이 유지됨을 재확인했으며 재고 있음 분기는 미구현으로 구분하였다. 별도 보호자 앱에서는 자녀별 대시보드·훈련 기록·분석 근거·동선·가족 관리의 시연 흐름과 서버 연동 계약을 작성하였다. 코드·관련 테스트·브라우저 화면을 확인하고 캡처를 보존했으며, 보호자 실데이터 연결과 실기기·실사용자 검증은 후속 과제로 남겼다.
