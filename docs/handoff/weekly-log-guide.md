# 주차별 활동 일지 작성 기준

이 양식은 **이미 한 일을 근거로 정리하는 용도**다. 활동 기간이나 양식이 주어지지 않았으면 특정 학기 주차/시간을 임의로 정하지 않는다. 코드가 있다는 사실, 커밋한 날, 실제 구현한 날, 검증한 날은 각각 기록할 수 있다.

## 1. 작성 순서

1. 사용자가 정한 1주차 시작일, 주의 기준(예: 월~일), 일지 제출 양식을 확인한다. 아직 없다면 우선 날짜 구간으로 정리한다.
2. [활동 근거 목록](activity-evidence-2026-10-13.md)과 연결된 당시 문서를 읽는다.
3. 해당 커밋의 변경 파일과 작성자를 확인한다. 팀원의 백엔드 작업·병합을 사용자 개인 구현으로 옮겨 적지 않는다.
4. 각 항목을 **요청/조사/기획/구현/수정/검증/공유** 중 실제 수행한 단계로 기록한다.
5. 날짜가 불명확한 여러 날의 작업은 “기간 확인 필요” 묶음으로 둔다. 사용자 확인 없이 주차에 나누거나 모든 항목을 커밋 주차로 몰지 않는다.

## 2. 근거의 의미

| 근거 | 알 수 있는 것 | 추가로 확인할 것 |
| --- | --- | --- |
| 현재 코드 | 기능이 어떻게 구현돼 있는지 | 언제·누가 구현했는지, 실제 기기 동작 |
| Git 커밋 | 저장한 시각, 작성자, 변경 파일 | 실제 작업 시작/종료일, 여러 날 통합 여부 |
| 날짜가 적힌 보고서 | 당시 기록한 조사/설계/검증 내용 | 현재도 같은 구현인지, 실제 수행일인지 문서 작성일인지 |
| 이 대화의 요청·피드백 | 사용자의 의도와 수정 이유 | 모든 항목의 날짜·완료 여부 |
| 테스트 출력 | 해당 코드/환경에서 검증한 항목과 결과 | 실제 이용자의 학습 효과·모바일 실기기 품질 |
| 파일 수정 시각 | 파일이 그 장치에서 바뀐 시각 | clone/복사/재생성 때문에 실제 작업일과 다를 수 있음 |

예를 들어 `a02ca8a`는 2026-10-13에 만든 통합 커밋이며, 그 안의 도서관·버스·마을 기능 전체를 그날 처음 개발했다고 쓰면 안 된다. 2026-10-13 버스 도로 수정 및 최신 검사 결과는 현재 대화에서 확인된 활동으로 따로 쓸 수 있다.

## 3. 항목별 기록 양식

```text
기간/주차:
날짜 근거와 확실성: (확인됨 / 문서 작성일만 확인 / 기간 확인 필요)
활동 주제:
목표·수정 계기:
실제로 수행한 내용:
설계상 판단과 이유:
결과·산출물:
검증한 환경·방법·결과:
남은 문제/다음 활동:
기여 범위: (사용자 프론트엔드 / 팀 공동 / 타 담당 / 확인 필요)
근거: (상대 파일 경로, 커밋, 당시 보고서, 대화 확인 내용)
```

일지 본문은 “버스 기능 개발” 한 줄로 끝내지 말고, 무엇이 불편했고 무엇을 바꿨으며 어떻게 확인했는지 연결해서 쓴다. 개발자가 한 활동의 주차별 일지와 게임 플레이어의 활동 앨범/학습 결과는 서로 다른 기록이다.

## 4. 확인된 한 항목의 작성 예

**활동일: 2026-10-13 / 주차: 제출 기준에 따라 배정**

버스 내부에서 보이는 도로가 단조롭고 주행 중 정지하는 문제를 개선하였다. 보도블록, 가로수, 화단, 가로등과 배수구를 기존 마을 에셋으로 구성하고, 도로와 주변 요소가 같은 반복 구간으로 움직이도록 정리하였다. 웹에서 네이티브 반복 옵션 때문에 애니메이션이 한 차례만 실행될 수 있는 경로를 수정하고, 안내 방송 완료 콜백이 도착 시간을 지연시키지 않게 하였다. PC 및 모바일 크기의 브라우저에서 반복 주행과 정류장 정차를 확인하였다. 관련 80개 테스트를 통과했으며, 이후 통합 커밋 검증에서 전체 982개 테스트·타입 검사·웹 빌드가 통과하였다. Expo Go 실기기 확인과 Expo 패치 버전 정리는 후속 항목으로 남았다.

근거: [BusRoadBackdrop](../../frontend/src/components/game/BusRoadBackdrop.tsx), [BusSimulationScreen](../../frontend/src/screens/BusSimulationScreen.tsx), [도로 회귀 테스트](../../frontend/__tests__/BusRoadBackdrop.test.tsx), [최신 검증 기록](project-state-2026-10-13.md), 통합 커밋 `a02ca8a` 및 해당 날짜 대화.

## 5. 다른 PC로 넘길 때

- 최신 브랜치와 이 문서 묶음을 pull하고, 사용자의 주차 기준·제출 양식을 함께 전달한다.
- 원본 대화를 못 읽는 경우 이 문서에 보존된 의도/근거까지 활용하되, 빠진 내용은 질문하거나 확인 필요로 남긴다.
- 실제 수행 시간, 전체 작업 횟수, 참여 인원, 학습 향상 수치 등을 근거 없이 채우지 않는다.
- 새로 한 작업은 그때그때 위 양식으로 날짜와 결과를 남긴다. 다음 인수인계는 그 기록을 바탕으로 갱신한다.
