# 활동 일지 작성 근거와 조사 자료 인수인계

기준: 2026-10-13, `feat/8-시뮬레이션-게임-ui-제작`의 `a02ca8ad3c142f93485d8955a8394ac56f6094f8`까지. 이 문서는 새 PC의 Codex가 개발 내용뿐 아니라 **무엇을 위해 조사·수정했는지**를 알고 주차별 활동 일지를 작성할 수 있도록 만든 근거 목록이다.

## 기록을 날짜와 개인 활동에 연결하는 방법

- 아래 Git 표의 날짜는 **커밋 작성일**이다. 작업 시작일·전부 완료한 날·작업 시간으로 바꾸어 쓰지 않는다. `a02ca8a`는 9월 말 이후 여러 날의 도서관·버스·마을 작업을 10월 13일에 묶은 커밋이다.
- 문서 제목·본문의 조사일과 구현일은 **그 문서에 기록된 날짜**다. 10월 13일에 처음 Git에 들어왔더라도 문서상 9월 29일 조사와 10월 1일 검증을 모두 10월 13일의 새 작업이라고 쓰지 않는다.
- `VIOLEILLICIT` 작성자의 프론트엔드 커밋을 이 작업의 개발 이력으로 선별했다. Git author는 기여 근거이지 모든 실제 작업을 혼자 수행했다는 증명은 아니다. 다른 작성자의 API·DB·AI·협업 문서 변경과 merge는 사용자 개인 실적으로 합산하지 않는다.
- 자료 조사, 기획, 코드 구현, 자동 테스트, 브라우저 검수, 실제 Expo Go 기기 검수는 구분한다. 과거 문서의 테스트 통과 수는 그 버전의 기록이다. 이번 인수인계 자체가 과거 시험을 다시 실행한 것은 아니다.
- 날짜가 없는 대화 피드백의 순서는 참고할 수 있지만 정확한 일자를 만들지 않는다. 주간 일지 확정 시 날짜가 중요한 부분은 일정표·당시 대화·팀 기록으로 보완한다. 작업하지 않은 주를 그럴듯하게 채우지 않는다.

## 조사 자료와 기술 진단을 넘길 때

**핵심 자체 조사 문서 10개는 이번에 Git 보관본으로 만들었다.** 내용·수량·기존/신규 구분과 원래 로컬 폴더, 옮기지 않은 자료, 원본/보관본 해시는 [연구 인수인계](research/README.md)와 [복사 매니페스트](research/portable-manifest.json)에 있다. 다른 컴퓨터에서 이 두 파일을 먼저 읽으면 원래 대화를 전달받지 않아도 조사 의도를 알 수 있다.

학교 AI 시험의 원본은 이전 저장소 `output/reports/2026-09-18-school-ai/`에 있다. [Git 비식별판](research/school-ai-2026-09-18/학교_AI_서버_연결_및_분석_진단_보고서.md)의 핵심 결과는 다음과 같다.

- 2026-09-18 당시 `9-ai-서비스-구현-jh-api`의 `f124a95`를 별도 detached worktree에서 시험했다. 8번·9번 추적 소스를 수정·커밋한 작업이 아니었다.
- 간헐적인 연결 수립 실패와 최종 합성 사전예산 초과는 서로 다른 단계였다. `time_connect=0`만으로 SYN/SYN-ACK 패킷 상태나 장애 장비를 확정하지 않았다.
- 기본 최종 사전예산 9,485가 한도 7,800을 넘었고, 합성 입력과 출력 예약을 함께 조절한 소량 시험에서는 7,548로 통과해 분석·근거 검토·첫 프로필 저장이 완료됐다. 7,548은 순수 입력 토큰 수가 아니다.
- 이 결과는 당시 소량 합성 시험의 결과이며 현재 네트워크 안정성, 대량 실제 기록, 모바일 전체 흐름, 누적 프로필 갱신의 완료 근거로 쓰지 않는다. 팀원이 전달한 60초 연결 실패 관측은 직접 수행한 6회 검사와 분리했다.

비식별판에는 키·토큰·시험 계정·분석 ID를 넣지 않았다. 다른 PC에서 재현하려면 현재 담당 브랜치/환경/권한을 확인하고 필요한 설정을 담당자와 별도로 맞춘다. 과거에 승인받은 합성 시험을 백엔드 변경·데이터 삭제의 새 권한으로 해석하지 않는다.

## 활동 일지 작성 양식과 예시

실제 일지에는 각 행을 **목적 → 수행 내용 → 결과/검증 → 남은 점 → 근거**로 쓴다. 시간과 개인 역할은 확인된 것만 적는다.

| 항목 | 작성 예시 |
| --- | --- |
| 기간·날짜 근거 | 2026-09-28~10-04, 9월 29일 조사 문서와 10월 1~2일 구현 기록 기준. 통합 커밋은 10월 13일. |
| 목적 | 생활 게임의 직업 과제를 확장하기 위해 공공 지원 일자리와 도서관리 보조 업무를 조사했다. |
| 수행 | 카페·도서관 등 사례를 비교하고 도서관을 첫 대상으로 선정했다. KDC 분류와 청구기호를 확인하고, 책 확인·배가·라벨 훼손 문의·손님 응대·보고로 플레이를 연결했다. |
| 결과·검증 | 구현 문서에 자동 테스트와 모바일 크기 브라우저 검수 기록이 있다. 손님 수·요청 종류·근무 도서·훼손 도서의 설정도 확장했다. 테스트 수치는 해당 기록 버전을 함께 표시한다. |
| 남은 점 | 게임에서의 성공이 실제 도서관 직무 수행으로 이어지는지는 검증하지 않았다. 실제 Expo Go 기기 검수는 각 문서에서 확인된 범위를 따로 적는다. |
| 근거 | 공공 일자리 조사, `docs/library-classification-research.md`, `docs/library-game-v1.md`, `a02ca8a`. |

새 PC의 Codex에게 줄 요청 예시:

> `docs/handoff/activity-evidence-2026-10-13.md`와 `docs/handoff/research/README.md`, 현재 구현 인수인계를 읽고 활동 일지를 작성해 줘. 커밋 작성일과 실제 작업일을 구분하고 VIOLEILLICIT 프론트엔드 이력, 날짜가 적힌 조사·검수 문서를 대조해. 다른 팀원의 작업이나 확인하지 못한 작업 시간은 내 실적으로 넣지 말고, 제안과 실제 구현·검증을 나눠 적어. 기간은 내가 지정한 주차를 사용하고 미확정 날짜는 확인 필요로 남겨.

## 이번 인수인계의 확인 범위

공식 저장소의 Git 작성자·날짜·파일 변경 목록, 날짜별 개발 문서, 이전 저장소의 조사·검증 매니페스트와 자체 요약을 읽었다. 다른 팀원 계정 기록, 서버 DB, 과거 모바일 기기 로그, 전체 대화의 정확한 타임스탬프는 이번 인수인계에서 검증하지 않았다. 사용자 기록의 305개·384개 삭제 여부나 과거 롤백의 실제 DB 결과도 이 자료만으로 확정하지 않는다. 새 담당자는 관련 근거 없이 그런 작업을 재실행하지 않는다.
