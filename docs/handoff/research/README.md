## 조사한 이유와 읽는 순서

장보기 게임에서 관찰한 행동을 구체적으로 설명하고, 다음 생활·직업 게임의 과제를 설계하는 데 사용할 근거를 준비했다. ‘우유를 잘못 골랐다’는 결과를 요청 이해, 상품 구별, 수량 확인, 가격 비교, 조작 성공 등 실제 행동으로 나눠 볼 수 있게 하는 목적이다. 자료를 AI에 전달할 수 있도록 출처·읽은 범위·적용 대상·한계도 함께 정리했다.

1. **무엇을 조사했는지 전체 이해:** [지적장애 개인차와 생활지원 심층조사](individual-differences-2026-09-19/지적장애의_개인차와_생활지원_심층조사.md).
2. **게임으로 어떻게 연결할지:** [기존 조사에서 도출한 장보기 설계 제안](baseline-2026-09-04/06_확장자료_핵심과_시나리오_적용.md), 위 심층조사 7장.
3. **AI에 어떻게 참고시키고 검토할지:** [AI 근거자료 활용과 검증](baseline-2026-09-04/02_AI_근거자료_활용과_검증.md), [전문가 역할 AI 적용 가이드](expert-ai-2026-09-16/03_전문가AI_적용가이드.md).
4. **도서관을 고른 배경:** [공공·지원 일자리 조사](supported-work-2026-09-29/01_공공지원_일자리_조사.md), [최초 도서관 기획안](supported-work-2026-09-29/02_도서관_근무_게임_기획안.md).
5. **출처를 개별 확인:** 아래 자료 묶음별 출처 목록과 대조표.

## 조사 내용의 핵심

| 조사 영역 | 확인하려던 내용 | 게임 설계에서 검토할 내용 |
| --- | --- | --- |
| 발달장애·지적장애 분류 | 용어의 범위, 지적기능과 적응기능, 중증도·지원 필요의 의미 | 진단명만으로 플레이어 행동이나 오답률을 지정하지 않고 실제 과제 조건을 기록한다. |
| 이해·표현·읽기 | 부탁을 이해하는 것, 상품을 식별하는 것, 직원에게 설명하는 데 각각 필요한 조건 | 사진·문구·음성·다시 보기, 선택형 질문 등 표현 방식별 조작을 검토한다. |

| 수량·금전·선택 | 종류와 개수, 가격 비교, 예산, 선택 경험과 지원 | 계산기, 수량 대조, 결제 전 확인, 중복 스캔 수정 등 별개의 과제로 나눈다. |
| 사회적 판단·도움 요청 | 낯선 상대와 대화하기, 모르는 점을 묻기, 거절·보류·상황 설명 | 직원·부탁한 NPC에게 질문하고 받은 답에 따라 구매·대체·미구매 보고로 이어지게 한다. |
| 감각·움직임·환경 | 소음·글자·화면 전환·손 조작과 과제 수행의 관계 | 탭과 끌기, 읽을 시간, 효과음·음성, 이동 UI를 조절하며 조작 문제를 이해 문제로 단정하지 않는다. |
| 지원과 생활 전이 | 시범·단계별 안내 등의 조건, 다른 목록·장소·시간에서도 유지되는지 | 도움 선택과 사용 내역을 남기고 화면 내 성공과 실제 생활의 성공은 각각 확인한다. |
| 전문가 역할 AI | 출처와 주장 일치, 확신·보류·편향·당사자 관점 | 관찰 사실 → 가능한 설명 → 확인 질문 → 지원 제안 → 검토의 순서로 구성한다. |

**지원 방법을 조사했다는 이유로 모든 도움을 항상 켜야 한다는 요구는 아니다.** 무엇을 연습할지 정하고, 그 과제에 필요한 도움을 선택·조절한 뒤 실제로 유용한지 확인하자는 제안이다. ‘언어형·기억형’ 같은 가상 프로필은 테스트 시나리오를 설명하는 예시이며 공식 장애 유형이나 실제 사람의 진단 결과가 아니다. 연구 자료를 모은 작업과 모델 훈련, 당사자·전문가 검증, 교육 효과 입증은 각각 별도 단계다.

## 기획 당시 문서와 현재 게임

도서관 초안의 3개 분류·6권 등은 **최초 제안 값**이다. 이후 KDC 10개 분류·전체 52권, 손님 수·근무 권수 조절, 손님 안내·책 꽂기 부탁으로 확장됐다. 현재 구현은 [도서관 구현 기록](../../library-game-v1.md)과 [분류 조사·적용 기록](../../library-classification-research.md), 실제 `frontend/src/game/librarySession.ts`를 확인한다. 문서 내부에 날짜가 다른 기록이 함께 있으므로 과거 숫자를 현재값으로 복원하지 않는다.

버스의 실제 구조 참고는 [한국·일본 버스 조사](../../bus-reference-research.md), 최초 흐름은 [버스로 도서관 가기 시나리오](../../bus-to-library-scenario-v1.md)에 있다. 현재 플레이 방식과 렌더링은 코드가 우선이다. 조사의 권장 기사 이미지나 오래된 v2·v4 설명만으로 최신 v5 이미지·좌석 동작을 되돌리지 않는다.

## 복사 범위 확인

[복사 매니페스트](portable-manifest.json)는 10개 문서의 기존 `output/` 상대 경로, 원본 SHA-256, 보관본 SHA-256, 변경 내용을 기록한다. 원본 파일은 수정하지 않았다. 서버 진단 비식별 처리와 상단 설명·줄바꿈 정리 이외에 연구 결론을 새로 작성해 원래 조사로 가장하지 않았다. 이 안내의 요약 표는 인수인계를 위해 새로 작성한 길잡이다.

보관본 해시는 UTF-8·LF 줄바꿈 기준이다. Windows의 Git 설정이 파일을 CRLF로 받도록 되어 있으면, 줄바꿈을 LF로 정규화한 바이트로 비교한다. 원본 해시는 이전 PC에 보관된 원본 파일의 실제 바이트 기준이다.
