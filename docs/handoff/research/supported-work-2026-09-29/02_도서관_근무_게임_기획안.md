**오늘도 도서관 — 첫 근무**

작성일: 2026년 9월 29일. 상태: 구현 전 기획안. 직무: 공공도서관 도서정리 보조. 실제 업무를 참고해 구성한 게임 설계이며 기관의 공식 직무교육 교재는 아니다.

**어떤 게임인가**

플레이어가 마을 도서관에 출근해 담당 사서에게 일을 받고, 반납된 책을 확인하고 제자리에 정리한 뒤 이용자를 돕고 근무를 마친다. 장보기에서 손님으로 물건을 찾았다면, 여기서는 직원으로 공간을 정리하고 다른 사람이 책을 찾도록 돕는다.

첫 플레이는 5~8분 정도를 목표로 잡는다. 이 시간은 개발상의 초안으로, 실제 사용자 플레이를 보고 조정한다. 작은 도서관 한 층에서 진행하며 길찾기보다 책 확인과 업무 수행에 집중한다.

**이 직무를 고른 근거**

전주시의 2022년 발달장애인 도서관리원 공고에는 도서 대출·반납, 항균소독, 서가정리 등 사서 보조 업무가 제시돼 있다. 주 20시간 근무와 한국장애인고용공단 전북지사가 참여하는 선발·직무훈련 절차도 확인된다. 이 채용계획에 명시된 업무를 도서정리 게임의 출발점으로 삼았다. [전주시 채용공고](https://www.jeonju.go.kr/deokjingu/planweb/board/view.9is?boardUid=ff8080818990c3490189d3dfa75a116d&contentUid=ff8080818990c349018acafdf408297e&dataUid=9be517a87ddf47af017f80b7fc996e6e&page=1044)

현재 마을에는 도서관 외관이 있으며, 장보기의 이동·NPC 대화·물건 상세보기·목록 확인·선반 상호작용 경험을 연결할 수 있다. 아래의 권수, 이벤트, 성공 기준과 화면은 이번 기획에서 제안하는 내용이다.

**첫 버전의 공간과 등장인물**

- 입구 가까이에 안내데스크와 담당 사서 1명.
- 옆에 반납 처리 완료 책을 모아 둔 북카트와 작업대.
- 가운데에 세 가지 큰 분류의 서가. 서가 사이에는 충분한 이동 폭 확보.
- 담당자 확인이 필요한 책을 놓는 작은 확인함.
- 이용자 1명과 열람 테이블. 작업을 진행하면서 한 번 도움을 요청한다.

반납 전산처리가 끝난 책부터 정리하는 역할로 시작한다. 이용자가 가져온 책을 곧바로 서가에 꽂는 절차로 오해하지 않도록 북카트에 ‘반납 처리 완료’ 상태를 보여 준다.

**한 번의 플레이 흐름**

| 순서 | 플레이어가 실제로 하는 행동 | 화면과 완료 조건 |
|---|---|---|
| 1. 출근·업무 받기 | 사서에게 인사하고 오늘 할 일을 확인한다. 필요하면 다시 설명을 듣는다. | ‘책 6권 확인 → 서가 정리 → 완료 보고’가 업무 수첩에 남는다. |
| 2. 맡은 책 확인 | 북카트에서 책을 눌러 제목과 책등 라벨을 본다. 맡은 권수를 확인한다. | 책 표지 아래에 제목, 라벨 확대보기. 표지색이 같아도 서로 다른 책을 식별할 수 있어야 한다. |
| 3. 분류·예외 확인 | 정상 책을 분류하고, 라벨이 읽히지 않는 책이 있으면 사서에게 묻는다. | 예외 책은 ‘확인 필요’ 상태로 남고 담당자 확인함에 전달할 수 있다. |
| 4. 서가에 정리 | 해당 서가로 이동해 책을 선택한 뒤 알맞은 위치에 꽂는다. 잘못 놓았다면 다시 꺼내 고친다. | 책과 서가의 분류 표시를 비교한다. 선반 확대 화면에서 ‘책 선택 → 위치 선택’ 또는 드래그로 조작한다. |
| 5. 이용자 안내 | 이용자가 찾는 책의 이름을 확인하고 위치를 찾아 알려 준다. 모르면 담당 사서에게 연결한다. | 실제 위치를 확인하고 안내하거나 담당자에게 인계하면 해결된다. |
| 6. 마무리·보고 | 남은 책을 확인하고 작업대를 정리한 뒤 사서에게 결과를 말한다. | 예: ‘5권은 정리했고, 라벨이 없는 1권은 확인함에 두었어요.’ |

‘배가’는 책을 정해진 서가 위치에 꽂는 일이다. 사용자 화면에는 처음부터 ‘책 제자리에 꽂기’처럼 행동이 드러나는 말을 우선 사용한다.

**실제 한 판의 예**

사서가 “이 카트의 책 여섯 권을 정리해 주세요”라고 부탁한다. 플레이어는 여섯 권을 확인한다. 다섯 권은 위치를 알 수 있지만 한 권은 책등의 라벨이 벗겨져 있다.

플레이어가 사서에게 “이 책은 라벨이 안 보여요. 어디에 놓을까요?”라고 묻는다. 사서는 “그 책은 확인함에 놓아 주세요. 나머지 다섯 권부터 정리해 주세요”라고 답한다. 업무 수첩도 정리 5권·확인함 1권으로 바뀐다.

정리 중 이용자가 특정 책의 위치를 묻는다. 플레이어는 요청한 제목을 확인해 안내하거나 사서에게 연결한다. 이후 수첩의 남은 일을 보고 작업으로 돌아온다. 마지막에는 실제 처리 결과와 맞는 보고를 하면 근무가 끝난다.

확인함과 라벨 훼손 이벤트는 이 게임의 가상 운영 절차다. 실제 교육에 사용할 때는 협력 도서관의 처리 기준에 맞춰 명칭과 절차를 조정한다.

**책을 꽂는 규칙과 난이도**

첫 버전에서는 큰 분류의 라벨과 서가를 연결하는 기초 단계부터 제공한다. 책의 위치를 나타내는 청구기호는 확대해서 확인할 수 있게 한다. 입문 단계의 성공은 ‘분류에 맞는 서가로 가져가기’로 기록하고, 세밀한 순서까지 익혔다고 평가하지 않는다.

| 단계 | 작업 조건 | 연습할 행동 |
|---|---|---|
| 처음 해보기 | 책 3권, 큰 분류 2개, 한 단계씩 안내 | 책등 라벨과 서가 표지 대조, 책 선택·배치 |
| 기본 근무 | 책 6권, 큰 분류 3개, 확인이 필요한 책 1권 | 맡은 권수 확인, 분류, 질문, 결과 보고 |
| 다음 근무 | 한 서가 안의 순서 비교, 잘못 꽂힌 책 1권, 이용자 문의 1회 | 청구기호와 인접 책 비교, 오류 수정, 중단 후 업무 복귀 |

색·그림 표시는 글자 옆에 붙는 선택형 보조 표시로 사용한다. 색만 같으면 배치되도록 만들지 않는다. 실제 기관의 청구기호 예시와 배열 규칙을 받아서 숫자·문자·권차 비교를 단계적으로 확장한다. 도서관마다 별치·분류·배열 규칙이 다를 수 있으므로 첫 버전의 단순 규칙을 모든 도서관의 표준으로 설명하지 않는다.

**반복해도 달라지는 상황**

| 상황 | 가능한 대응 | 게임에서 확인할 것 |
|---|---|---|
| 책등 라벨을 읽기 어렵다 | 확대하기, 다시 확인하기, 사서에게 묻기 | 불확실한 상태에서 확인 행동을 선택했는가 |
| 책이 잘못 꽂혀 있다 | 주변 라벨과 비교하고 옮기기 | 오류를 발견하고 실제로 바로잡았는가 |
| 다른 일을 하던 중 이용자가 말을 건다 | 요청 확인, 안내, 사서 연결, 현재 작업 위치 기록 | 요청을 처리한 뒤 맡은 작업을 이어가는가 |
| 검색 결과에 책이 대출 중으로 나온다 | 상태를 확인해 말하고 추가 질문은 사서에게 연결 | 확인한 사실과 안내 내용이 맞는가 |
| 서가 배치가 조금 바뀐다 | 표지판·수첩으로 다시 찾기 | 이전 위치를 외운 것과 표시를 읽고 찾는 것을 구별해 관찰 |

첫 버전은 이 중 라벨 확인 이벤트 한 가지와 짧은 이용자 문의만 넣는다. 대출 중 상태와 배치 변경은 이후 확장 후보로 둔다.

**화면·조작 방향**

- 마을에서 도서관 문으로 들어가면 실제 근무 공간이 펼쳐진다. 기존 코지한 갈색 외곽선·차분한 색상을 이어간다.
- 상단에는 오늘 맡은 일과 진행 상황을 간단히 표시한다. 하단 수첩에서 전체 업무를 다시 볼 수 있다.
- 책 상세 화면은 표지, 제목, 책등 라벨을 중심으로 구성한다. 물건 가격·장바구니 합계 같은 장보기 항목은 이 직무 화면에 필요하지 않다.
- 서가 작업은 탭으로도 완료할 수 있게 한다. 드래그는 같은 작업의 추가 조작 방법으로 제공한다.
- 대화는 기존 NPC의 등장 애니메이션과 부드러운 효과음을 공유한다. 업무 중 화면을 덮는 설명 팝업의 수를 줄인다.
- 책 6권은 한 화면에서 목록을 확인할 수 있게 배치하고, 작은 청구기호는 터치하면 확대한다.

**도움을 어떻게 제공할지**

필요할 때 업무 수첩 보기, 한 단계 다시 듣기, 라벨 확대, 사서에게 묻기를 선택할 수 있게 한다. ‘안내와 함께’에서는 현재 단계만 강조하고, ‘혼자 해보기’에서는 자동 강조를 줄이되 필요한 도움 버튼은 유지한다.

도움 요청 자체에 감점을 주지 않는다. 게임이 기록할 내용은 어떤 도움을 받고 어떤 작업을 완료했는지다. 첫 버전의 완료 조건은 정확한 처리와 보고를 중심으로 하고 시간 제한은 두지 않는다. 사용자 장애명에 따라 난이도를 자동 지정하지 않고, 실제 플레이와 선택한 지원 수준으로 설정한다.

**결과 화면과 기록**

결과 예시:

- 제자리에 정리한 책: 5권.
- 담당자 확인으로 넘긴 책: 1권.
- 이용자 요청: 위치 안내 완료.
- 스스로 수정한 배치: 1회.
- 다음에 연습할 일: 한 서가 안에서 책 순서 확인하기.

처음 선택, 수정 후 결과, 도움 종류, 최종 보고를 따로 저장한다. 마지막에 정답을 맞혔더라도 처음부터 독립 수행한 것과 도움 후 수행한 것을 기록에서 볼 수 있어야 한다. 별점이나 완료 보상은 게임 경험으로 사용할 수 있으나, 이 결과로 실제 채용 적격 여부나 장애 정도를 판정하지 않는다.

AI를 붙일 경우 작업 기록을 쉬운 말로 설명하거나 추가 대화를 하는 역할부터 맡긴다. 책의 정답 위치·완료 상태는 사전에 정한 게임 규칙으로 검증한다. 첫 구현은 고정 대사와 명확한 선택지로 진행할 수 있다.

**첫 구현 범위**

- 도서관 실내 1개, 서가 3개, 작업대·북카트·확인함·안내데스크.
- 담당 사서 1명, 이용자 1명.
- 책 12종 가운데 한 판에 6권 사용.
- 업무 받기, 책 확인, 분류·배치, 질문·인계, 이용자 문의, 마무리 보고.
- 안내와 함께/혼자 해보기, 탭·드래그 조작, 결과 기록.
- 새 도서관 내부·책·북카트·사서 아트가 필요하다. 기존 플레이어·폰·수첩·대화 표현은 활용 후보이며 재사용 범위는 구현 전에 확인한다.

이번 산출물은 조사와 기획안이다. 앱 코드와 이미지는 이 기획 때문에 추가하거나 변경하지 않았다.

**구현 후 확인할 기준**

1. 폰과 태블릿에서 확대·이동·책 배치가 가능하고, 드래그 없이도 주요 작업을 끝낼 수 있다.
2. 일반 책은 지정 분류에 놓아야 완료되고, 확인이 필요한 책은 담당자에게 넘겨야 완료된다.
3. 질문하거나 작업을 중단했다가 돌아와도 맡은 책과 진행 상황이 유지된다.
4. 잘못 놓은 책을 다시 꺼내 고칠 수 있고 수정 전후 기록이 남는다.
5. 보고 내용은 실제 처리 결과와 일치해야 하며, 남은 일을 확인하고 재개할 수 있다.
6. 도서관 담당자·직무지도원에게 업무 순서를 검토받고, 발달장애 당사자의 조작 경험을 확인해 글자·설명·과제량을 조정한다. 이는 후속 현장 검증 계획이며 현재 완료된 검증은 아니다.
