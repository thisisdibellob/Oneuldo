## 새 컴퓨터의 Codex에 전달할 요청문

> 공식 저장소 `thisisdibellob/Oneuldo`의 `feat/8-시뮬레이션-게임-ui-제작` 브랜치에서 작업을 이어가 줘. 먼저 Git 상태·현재 브랜치·원격을 확인하고, 작업 트리가 깨끗할 때만 `git pull --ff-only`를 실행해. `docs/handoff/README.md`에서 연결한 최신 문서들을 읽고, 실제 코드는 `frontend/`에서 확인해. 이전 SDK 54 안내보다 현재 package.json과 잠금 파일을 기준으로 삼아. 기존 변경·플레이 기록을 지우지 말고, `backend/`, `docs/collaboration.md`, 다른 사람의 브랜치를 임의로 수정하지 마. 대화에서 요청된 사항과 코드로 확인된 완료 사항을 구분해. 주차별 일지는 `weekly-log-guide.md`와 `activity-evidence-2026-10-13.md`에 따라 근거가 있는 활동만 배정하고, 날짜·시간·실사용자 평가 결과를 추측하지 마. 다음 사용자 요청 범위 안에서 개발하거나 일지를 작성해.

## 문서를 갱신하는 방법

1. 동작이 바뀌면 담당 기능 문서의 현재 상태와 주의점을 함께 수정한다.
2. 활동 일지의 원자료에는 작업일/확인일, 목적, 구현, 검증 명령과 결과, 파일/커밋 근거를 남긴다.
3. 사용자가 제안한 기능은 구현 근거가 생길 때까지 제안/요청으로 기록한다.
4. 스크린샷·연구자료·실행 로그가 로컬에만 있으면 그 사실과 전달 가능한 요약을 기록한다. 개인 데이터나 인증정보를 Git으로 옮기지 않는다.
5. 이 문서는 **현재 게임을 인수인계하는 문서**다. 팀 전체의 운영 규정인 `docs/collaboration.md`를 대체하거나 변경하지 않는다.
