# 장보기 환경 구현 현황 · 진욱 → 정우·재현

기준일: 2026-09-11. 대상: `thisisdibellob/Oneuldo` 저장소의 `frontend/` Expo 앱.

이 문서는 최초 환경 설정, 마트 구조 개편, 반납 도움, NPC 일러스트까지 합친 **현재 팀 전달용 보고서**다. 이전 보고서와 수치가 다르면 이 문서와 [현재 AI 실행 인터페이스](../frontend/docs/market-agent-contract.md)를 우선한다.

## 그대로 읽거나 카카오톡에 전달할 설명

> 장보기 게임을 같은 조건으로 반복 실험할 수 있도록 만들었습니다. 게임 시작 전에 시드, 진열대 위치, 상품 종류와 재고, 사람과 기둥 수, 계산원 유무, 구매 조건을 설정할 수 있습니다. 현재 5개 분류에 상품 120종을 갖추었고, 분류마다 9종을 골라 12칸에 진열합니다. 사용자는 직접 담기, 제자리에 돌려놓기, 직원에게 계산이나 반납 도움 요청, 구매 확정과 재시도를 할 수 있습니다. 이 과정과 최종 결과를 설정·실제 배치와 함께 JSON으로 저장합니다. 정우·재현은 준비한 페르소나 모델을 관측·행동 인터페이스에 연결하면 됩니다. 실제 모델 실행과 분석 서버 연결은 다음 작업이며, 이번에는 그 연결에 필요한 게임 환경과 기록 규격까지 준비했습니다.

인물은 플레이어 일러스트의 선·색감·전신 비율에 맞춘 **종업원 남성 2종·여성 2종과 손님 12종**이다. 손님은 성인·노인·어린이마다 남성 2종·여성 2종이며, 어린이 그림 높이는 성인의 76%다. 역할 안에서는 외형이 중복되지 않도록 뽑는다. 종업원 3명과 계산원 2명이 모두 있으면 4개 직원 외형 중 하나는 재사용한다. [16종 모음과 제작 기록](design-concepts/2026-09-11-market-people/README.md)에서 확인할 수 있다.

## 사용자 흐름과 학습 규칙

1. **시작 전 설정:** 구매 목록과 환경을 정한다. 목록에는 사야 할 수량만 표시한다. 진행 중에 `1/2` 같은 정답 진행률이나 잘못 담았다는 안내는 하지 않는다.
2. **진열대에서 담기:** 가까운 진열대를 열어 상품명·규격·재고를 보고 담는다. 장바구니를 직접 열면 담긴 물품·수량·합계를 확인한다.
3. **직접 내려놓기:** 해당 상품의 진열대로 돌아가 그 분류의 상품을 내려놓는다. 일반 장바구니나 다른 분류 진열대, 계산대에서 원격으로 수량을 줄일 수 없다.
4. **반납 도움:** 가까운 종업원과 대화해 선택한 상품을 1개 또는 전부 돌려놓아 달라고 요청한다. 처리 수량이 원래 SKU 재고로 돌아가며 점수·구매 시도 횟수는 바뀌지 않는다. 직원은 정답 품목이나 필요한 수량을 대신 알려 주지 않는다.
5. **계산 요청:** 계산원이 있으면 해당 계산대를 이용한다. 없으면 매장 종업원을 찾아 빈 계산대 번호로 도움을 요청한다. 두 계산대는 독립적으로 관리한다.
6. **최종 구매 확정:** 계산대에 가는 것만으로는 판정하지 않는다. 사용자가 최종 구매를 확정할 때에만 구매 시도 횟수가 1 늘어난다.
7. **실패와 재시도:** 첫 실패는 실패했다는 사실만 공개한다. 두 번째 이후 실패부터 다른 품목·수량을 알려 준다. 장바구니를 유지한 채 횟수 제한 없이 다시 시도할 수 있고, 진행 중 언제든 포기할 수 있다.
8. **종료와 평가:** 성공 또는 실패(포기), 구매 시도 횟수, 점수·감점·경보 횟수를 확인한다. 난이도·흥미를 각각 1~5점으로 기록하거나 평가를 건너뛴다.

구매 판정은 `family`와 `exact`를 구분한다. 예를 들어 우유 2개 과제는 같은 우유군의 변형을 합쳐 통과할 수 있고, 저지방 우유 2개 과제는 해당 상품만 인정한다. 필요한 수량보다 많이 담거나 목록에 없는 상품을 담아도 실패한다. 가격과 합계는 표시하지만 예산 초과는 현재 별도 실패 조건이 아니다.

미결제 상품을 담고 **빨간 입구 경보기**를 매장 안에서 밖으로 통과하면 기본 10점 감점한다. 점수는 100점에서 시작하며 0점 아래로 내려가지 않는다. 작은 경계 왕복은 중복 감점하지 않고 매장 안쪽으로 충분히 돌아온 뒤 다시 통과하면 다음 경보가 발생한다. 빈 장바구니·정상 출구에는 경보기 감점이 없다. 결제 전 입구나 출구에서 나가기를 선택하면 포기로 종료한다. 구매 성공은 결제 완료와 동시에 종료되므로 이후 별도 퇴장 플레이는 없다.

## ‘환경 변수’의 의미와 전달할 설정

여기서 환경 변수는 PC의 `.env`나 비밀번호가 아니라 **게임에서 행동을 발생시키는 실험 조건**이다. 한 에피소드 도중 배치를 계속 바꾸는 방식이 아니라, 시작 전에 설정을 확정하고 그 게임 동안 유지한다.

| 설정 | 현재 허용값과 용도 |
| --- | --- |
| `seed` | 문자열 또는 유한 숫자. 같은 설정과 시드로 공간·상품·외형 재현 |
| `environment.employeeCount` | 1~3 또는 `{min,max}` |
| `environment.customerCount` | 1~5 또는 `{min,max}` |
| `environment.pillarCount` | 0~4 또는 `{min,max}` |
| `environment.cashierCount` | `0`, `1`, `2`, `'random'` |
| `environment.kioskPresent` | `false`, `true`, `'random'` |
| `environment.shelfOrder` | `produce,fresh,household,meal,drink` 각각 한 번의 배열 또는 `'random'` |
| 위치 후보 ID 배열 | 종업원·손님·기둥의 사전 정의 후보 풀 제한. 임의 좌표를 바로 입력하는 편집기는 아님 |
| `difficulty`, `objectives` | 품목군/정확 상품 판정, 필요한 상품·수량. 목표별 `match`도 지정 가능 |
| `stockPerProduct`, `stockOverrides` | 기본 재고 1~99, 상품별 재고 0~99 |
| `inventoryProductIds` | 필요한 분류의 서로 다른 9개 SKU를 직접 지정. 생략한 분류는 시드로 생성 |
| `alarmPenaltyPoints` | 경보기 감점 0~100, 기본 10 |
| `provenance` | 사람/합성 구분, 모델·페르소나·버전 등 수집 메타데이터 |
| `sessionId`, `startedAt` | 실행 식별자와 시작 시각 |

과거 `chairCount` 0~4 설정은 읽을 수 있지만 현재는 0으로 정규화하고 고정 휴게석을 사용한다. 과거 4개 분류 순서는 세 번째에 `household`를 넣어 읽는다. 새 환경은 `layoutVersion:2`이며, 에피소드의 외부 버전은 호환을 위해 `version:1`을 유지한다. 과거 좌표를 새 배치에 고정해서 쓰면 안 된다.

실행 불가능한 구매 조건은 시작 전에 오류로 반환한다. 잘못된 상품·위치, 겹치는 품목군 조건, 부족한 재고, 분류당 9종을 초과하는 필수 상품 등을 조용히 바꾸지 않는다.

## 정우·재현이 연결할 부분

[AI 인터페이스 문서](../frontend/docs/market-agent-contract.md)와 [예제 설정 JSON](../frontend/docs/market-environment.example.json)을 함께 전달한다. 핵심 진입점은 `frontend/src/game/marketSession.ts`의 `createMarketAgentAdapter(config)`다.

- `observe()`: 현재 위치·지도·구매 목록·공개된 화면 정보를 읽는다.
- `act(action)`: 이동, 진열대 열기, 담기, 직접 반납, 직원 반납·계산 요청, 구매 확정, 재시도, 포기, 별점을 수행한다.
- `exportEpisode()`: 성공 또는 포기로 종료한 뒤 전체 에피소드를 받는다. 진행 중에는 사용할 수 없다.

모델에는 `observe()`와 `act()`의 반환값을 전달한다. 전체 공간 위치는 구조화된 정보로 보이지만 상품·재고는 현재 접근해 연 진열대만 공개한다. 장바구니는 직접 열거나 직원 대화·구매 결정·종료 화면에서만 공개한다. 숨겨진 정답, 첫 실패의 세부 평가, 연구용 이벤트를 다음 행동 선택에 넘기면 안 된다. 따라서 현재 인터페이스는 실제 사람의 시야나 글자 인지까지 재현한 화면 기반 에이전트는 아니다.

이동은 한 행동당 최대 32px이며 경로 충돌과 접근 거리를 검사한다. 화면 동기화 전용 `setPosition`은 AI 어댑터에서 차단한다. 모델 실행기는 현재 환경의 접근 좌표를 사용하고, 진열대·대화·장바구니 등을 닫은 다음 이동해야 한다.

에피소드에는 설정, 실제 배치, 상품·최초 재고, 행동별 시각, 담기·수정·직원 요청, 구매별 전체 평가와 실제 공개 피드백, 재시도·포기·별점, 최종 점수·결제 여부가 남는다. 직원 반납은 `return_help_requested`와 `cart_changed.method:'employee'`로 직접 반납과 구분한다. 경보기는 `entrance_alarm`에 실제 감점을 기록한다.

AI 실행은 `source:'synthetic'` 및 실제 `agentModel`, `personaId`를 반드시 지정한다. 페르소나 버전도 보존한다. 합성 기록은 실제 장애인 참여자의 행동 자료나 임상적으로 검증된 특성으로 표시하지 않는다. 실제 수집에서는 `startedAt`과 행동의 `at`에 실행 시각을 넣는다. 생략한 시각은 재현용 논리 시계이므로 실제 반응 시간으로 해석할 수 없다.

## 저장·검증과 남은 작업

웹의 완료 기록은 해당 브라우저에 최근 최대 20회, 최대 5MiB 범위로 보관한다. 네이티브 앱은 현재 실행 중 메모리 보관이므로 앱을 완전히 종료하기 전에 JSON 공유로 별도 저장해야 한다. 자동 서버 업로드는 없다. 일반 UI 이동 로그는 일정 간격으로 표본 수집하며 매 프레임의 완전한 궤적은 아니다.

2026-09-11 NPC 적용 완료 시점의 검증 기록은 **타입 검사, Jest 21개 스위트·171개 테스트, 웹 빌드 통과**다. 최종 웹 빌드 로그 시각은 2026-09-11 16:13 KST다. 이 숫자는 해당 작업의 검증 기록이며 이 보고서 작성만으로 전체 테스트를 다시 실행했다고 주장하지 않는다. 100개 시드의 최대 밀집 배치 도달성, 5분류 카탈로그·이미지, 구매·재시도·반납·경보기 규칙, 인물 외형 선택을 포함한다. 기존 App 테스트의 비동기 `act` 경고는 남아 있다. 브라우저에서는 모바일 크기 화면과 새 NPC 이미지 로드를 확인했지만 실제 iOS·Android 기기의 최종 터치·성능은 별도 확인이 필요하다.

이번 노트북 인수인계 시점에는 headless smoke를 새로 실행해 **336개 이벤트, 구매 시도 2회 후 성공, 100점·결제 완료, 환경 버전 2와 모든 5분류의 12칸·9종**을 확인했다. 검증용 출력은 PC의 `frontend/.expo/notebook-handoff-smoke.json`이며 `.expo`는 Git 제외 대상이다. 노트북에서 같은 예제 설정으로 다시 실행할 수 있다.

모델 없이 행동 계약을 재확인하는 명령은 `frontend/`에서 다음과 같다.

```powershell
node scripts/market-agent-smoke.cjs --output .expo/market-smoke-episode.json
```

이 스크립트는 실제 페르소나 AI가 아니라 결정적 소프트웨어 검증기다. 예제 설정은 합성 출처와 검증 전용 페르소나 ID를 포함한다. 과거 `qa-purchase`, `qa-no-cashier` 브라우저 조작 기록도 실제 참여자 데이터가 아니므로 학습 자료에서 제외한다.

남은 연결 작업은 모델 관측/행동 변환, 페르소나별 반복 실행, 실행 시간·행동 수 제한, 에피소드 저장 API, 기존 분석·퀘스트 생성 결과와의 식별자 연결이다. 제한에 도달한 모델은 실행기가 `giveUp`으로 마무리하고 수집 측 종료 사유를 남겨야 한다. NPC의 자율 이동·대화 모델, 실제 결제·ATM·엘리베이터·키오스크 이용, 네이티브 영구 기록 저장은 구현 범위에 포함되지 않았다. 현재 계산원 호출은 해당 계산대의 이용 가능 상태를 바꾸는 동작이며 직원이 걸어가는 연출은 없다.
