# 마트 v7 — 직원 대화와 계산원 확인

2026-09-14 · 오늘도 프론트엔드 · `feat/8-시뮬레이션-게임-ui-제작`

직원 대화의 선택지를 마을 NPC와 같은 형태로 맞추고, 계산 요청을 하나로 정리했습니다. 계산대가 비었는지 사용자가 먼저 살핀 뒤 요청하며, 실제 배치에 따라 직원이 계산을 도와주거나 이미 운영 중인 계산대를 안내합니다.

## 요청별 반영

| 요청 | 반영 내용 |
|---|---|
| 대화 등장 때 잠깐 보이는 오른쪽 스크롤바 제거 | 스크롤바 표시와 불필요한 튕김 효과를 숨겼습니다. 실제 세로 스크롤은 유지해 작은 화면·큰 글씨·긴 반납 목록도 끝까지 볼 수 있습니다. |
| 마을 NPC처럼 선택지마다 다른 너비 | 직원 버튼의 고정 전체 폭을 없앴습니다. 마을과 같은 좌우 여백 **42**, 글줄 높이 **20**, 가운데 정렬을 적용했습니다. 짧은 문구는 좁게, 긴 문구는 부모 폭 안에서 줄바꿈하며 두 줄·큰 글씨에 맞춰 높이가 늘어납니다. |
| 마을과 같은 선택지 등장 효과 | 실제 마을 코드를 비교해 **200ms, out(cubic), 투명도 0→1, 아래 10px→제자리**의 동일한 효과를 확인했습니다. 문장이 완성되면 선택지가 나타나고, 새 답변에서는 이전 애니메이션을 멈춘 뒤 다시 나타납니다. 모션 감소 설정에서는 즉시 표시합니다. |
| 계산 요청을 한 가지 문구로 통일 | 계산원 유무에 따라 1번·2번 요청 버튼을 미리 나누던 방식을 없앴습니다. 아래 두 줄 선택지 하나를 표시하고, 선택한 뒤 실제 계산대 상태에 따라 응답합니다. |

> 계산대에 사람이 없어요,<br>
> 계산 부탁드릴게요

요청 후에는 같은 선택지를 잠시 숨겨 답변을 읽도록 합니다. 동기적으로 잠기는 ref 가드로 빠르게 두 번 눌러도 한 번만 처리합니다. 특히 첫 요청으로 계산원이 생긴 직후 두 번째 터치가 불필요한 요청으로 처리되어 감점되는 상황을 막았습니다. 대화를 닫고 다시 말을 걸면 새 요청을 할 수 있습니다.

## 계산대 상태에 따른 결과

아래의 0/1은 각 계산대의 **현재 운영 여부**입니다. 처음 배치된 계산원뿐 아니라 앞서 호출한 계산원도 포함합니다.

| 1번 / 2번 | 직원 응답과 상태 변화 | 기본 감점 |
|---|---|---|
| 0 / 0 | 요청 수락. **1번 계산대에 한 명**을 배치하고 1번으로 안내합니다. | 0점 |
| 1 / 0 | 1번에 이미 계산원이 있다고 안내합니다. 추가 배치는 없습니다. | 10점 |
| 0 / 1 | 2번에 이미 계산원이 있다고 안내합니다. 추가 배치는 없습니다. | 10점 |
| 1 / 1 | 1번 또는 2번 계산대를 이용하도록 안내합니다. 추가 배치는 없습니다. | 10점 |

거절은 오류 팝업이 아닌 정상적인 직원 대화입니다. 사용자에게 기존 계산대를 안내하고 이번 실제 감점을 보여 줍니다. 남은 점수보다 많이 차감하지 않으며, 감점 설정이 0이면 **“계산원 확인 · 감점 없음”**으로 안내합니다.

빈 계산대를 열었을 때도 무조건 직원을 부르라고 안내하지 않습니다. **계산원이 있는 계산대를 이용하고, 두 곳 모두 비어 있으면 직원에게 부탁한다**는 조건을 설명하고 **계산대 다시 살펴보기**로 돌아갑니다.

반납 도움은 무료로 유지했습니다. 반납 화면에 들어갔다 나오기, 직원 대화 닫기와 재진입, Android 뒤로가기는 답변·감점 표시·요청 처리 상태를 함께 초기화합니다. Android 뒤로가기는 반납 화면 → 직원 대화 → 매장 순으로 닫습니다.

## 설정과 팀 전달 사항

장보기 시작 전 **연습 환경 설정 → 계산원 확인 감점**에서 값을 변경합니다. **출입 경보기 감점**과는 별도 항목이며 각각 저장·가져오기할 수 있습니다.

```json
{
  "cashierRequestPenaltyPoints": 10,
  "alarmPenaltyPoints": 10
}
```

- `cashierRequestPenaltyPoints`: 정수 **0~100**, 기본 **10**. 예전 설정에서 생략해도 기본값으로 동작합니다.
- `alarmPenaltyPoints`: 기존 미결제 반출 경보기 감점입니다.
- 최종 화면은 **총 감점**, **경보기 감점·횟수**, **계산원 확인 감점**을 나누어 표시합니다. 두 항목 모두 실제 차감액으로 합산합니다.
- 가까운 직원과 대화를 열지 않은 요청 등 잘못된 행동은 기존 행동 거부로 처리하며 계산원 확인 감점을 부과하지 않습니다.

AI 실행기는 기존 `requestCashier`를 사용합니다. 공개 관측의 `cashierRequestFeedback`에서 수락 여부·직원 안내문·이용할 계산대·이번 실제 감점을 읽을 수 있습니다. 자세한 동작과 이전 입력의 호환 방식은 [환경·행동·결과 계약](../frontend/docs/market-agent-contract.md)을 확인합니다.

## 최종 검증

- TypeScript 타입 검사 통과.
- Jest 전체 **34개 테스트 묶음, 319개 테스트 통과**. 계산대 네 가지 상태, 감점 설정·점수 하한, 연타 방지, 대화 초기화와 기존 장보기 흐름을 포함합니다.
- **웹·iOS·Android 내보내기 모두 통과**.
- AI 실행기 스모크 확인: 계산원 없음·2번에만 있음·둘 다 있음의 세 환경 모두 2회 시도 후 성공, 100점을 유지했습니다.
- 브라우저에서 계산원 0·1·2명 모두 같은 요청 선택지를 확인했습니다. 0명일 때만 1번 계산대가 열리고, 1·2명일 때는 기존 계산대 안내와 함께 **100점 → 90점**으로 차감됐습니다.
- **390×844 / 844×390**에서 긴 반납 목록을 끝까지 스크롤하고 상품 한 개를 실제 반납했습니다. 반납 후 기본 선택지가 복구되고 점수는 90점으로 유지됐습니다. 브라우저 오류 로그는 없었습니다.

완료된 브라우저 확인에서는 **390×844** 화면의 선택지가 내용에 따라 **260.46px / 243.64px** 등 서로 다른 폭으로 표시되었습니다. 등장 효과는 **opacity 0·Y10 → opacity 1·Y0**, 스크롤바는 `scrollbar-width:none`을 확인했습니다. 계산원 0명 상태에서는 요청 수락 후 1번 계산대 활성화와 무감점을 확인했습니다.

화면 확인은 무음 QA로 진행했습니다. 실물 휴대폰에서의 청취·터치 검증은 이번 작업에 포함하지 않았습니다.
