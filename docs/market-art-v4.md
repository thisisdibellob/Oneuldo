# 하늘마트 비주얼 개편 보고서 · Art v4

작성일: 2026-09-13 · 대상: `Oneuldo/frontend` · 기존 공간 버전: `layoutVersion: 3`

> 이번 작업은 하늘마트가 하나의 실제 동네 마트처럼 보이도록 건물 마감, 진열 집기, 상품 표현과 화면 UI를 함께 정리한 작업입니다. 플레이어와 어울리는 섬세한 선과 차분한 색을 기준으로 빈 진열대와 계산대 이미지를 제작하고, 기존 상품 이미지를 작은 진열용 그림으로 얹었습니다. 화면 위에는 필요한 물품과 구매할 개수만 보이는 장보기 메모를 두었습니다. 앞서 확인한 입구·출구 위치, 이동·충돌, 구매·반납·재시도와 AI 실행 규칙은 그대로 사용합니다.

## 2. 마트 공간과 집기

**건축 마감:** 판매장과 로비의 바닥색을 구분하고 작은 타일 줄눈, 벽 상단과 걸레받이, 하늘마트 간판, 계산 통로 표시를 추가했습니다. 엘리베이터는 연속된 벽면에 붙이고, 공동 출입문에는 문틀·유리·환영 매트를 표시합니다. 이 그림들은 입력을 받지 않으며, 벽과 문은 기존 환경 좌표를 기준으로 그립니다.

**카메라:** 기본 확대 배율 1.3은 그대로 두고, 매장 가장자리에서 카메라가 바깥 빈 공간을 따라가지 않도록 제한했습니다. 카메라 중심·캐릭터 표시 위치·터치 좌표 변환을 함께 맞췄으며, 일반 게임과 독립 마트 화면에 공통 적용했습니다.

**일반 진열대:** 아이보리 금속, 세이지색 선반 테두리, 밝은 목재가 결합된 빈 2단 선반을 제작했습니다. 음료·간편식품·생활용품은 같은 집기 계열을 공유하면서 진열 상품으로 구분합니다.

**과일·채소:** 낮은 목재 진열대를 2단·각 단 3칸의 빈 상자로 제작했습니다. 상품 그림을 별도로 얹어 다른 집기와 재질·선 굵기를 맞췄습니다.

**냉장식품:** 같은 2단 프레임에 은색 냉장 내벽·LED 조명·하단 환기구를 넣은 전용 이미지를 제작·연결했습니다. 일반 선반과 외형은 통일하면서 냉장 구역임을 구분합니다.

**계산대:** 세로형 계산대를 아이보리·세이지색으로 다시 제작했습니다. 기존에 줄인 표시 크기와 충돌 바닥을 유지하고, 두 계산원 모두 왼쪽·고객 통로는 오른쪽인 배치를 그대로 사용합니다.

집기 두 개가 같은 상품 목록을 여는 기존 구조도 유지합니다. 두 진열대 사이에 있는 통로를 그림이나 새 터치 영역으로 막지 않습니다.

## 3. 맵 진열 그림과 실제 재고의 구분

맵에서 보이는 작은 상품 그림은 **분류를 알아보기 위한 카탈로그 예시**입니다. 진열대 한 개에 12개의 전면 상품 그림을 배치하고, 같은 분류의 두 진열대를 한 묶음으로 표시합니다. 같은 상품을 반복 진열할 수 있으며, 이 그림 자체는 구매 가능한 수량이나 이번 게임의 정확한 재고를 뜻하지 않습니다.

실제로 진열대를 열었을 때의 상품은 기존 세션이 결정합니다. **분류별 게임당 9종 선정, 4×3의 12칸 배치, seed 기반 재현과 실제 재고·구매 처리는 그대로**입니다. 정답 목록이나 장바구니 진행 상황을 맵의 장식 상품에 반영하지 않습니다.

맵에는 기존 상품 이미지에서 만든 **128×128 썸네일 60개**를 사용합니다. 작은 상품이 반복 보일 때 고해상도 원본을 계속 사용할 필요를 줄이기 위한 파일이며, 상품 데이터와 그림 원본을 유지합니다. 이후 로딩 최적화에서 상품 선택 화면은384px 실행용 파일로 전환했습니다. 제작 목록은 [썸네일 기록](design-concepts/2026-09-13-market-retail/stock-thumbnails-manifest.json)에 있습니다.

## 4. 장보기 메모와 구매 화면

- 내장 마트와 독립 실험 화면이 같은 `MarketHud`를 사용합니다. 넓은 화면에서도 HUD가 빈 가로 막대처럼 늘어나지 않도록 왼쪽 상단 최대 420px로 제한했습니다.
- 브랜드·점수 아래 종이 메모에는 **사야 할 물품과 개수만** 표시합니다. 담은 개수나 `1/2` 같은 진행 비율은 표시하지 않습니다.
- 장바구니, 도움, 포기와 내장 마트의 이동 방식 전환을 명확한 버튼으로 제공합니다. 주요 터치 영역은 최소 44px입니다.
- 시작·장바구니·계산·결과 패널과 진열대 화면에 같은 종이색, 남색 글자, 세이지색 버튼, 제목 서체를 적용했습니다. 가격표와 구매 목록에는 얇은 황동색 구분선을 사용했습니다.

최종 구매 전에는 정오를 알리지 않습니다. 상품 반납, 직원 도움, 계산원 호출, 첫 실패와 이후 재시도 안내, 결과·별점과 포기 규칙도 변경하지 않았습니다.

## 6. 유지한 실행 계약과 최종 검증

Art v4는 그림과 UI 개편의 이름입니다. 환경의 `layoutVersion: 3`을 새 공간 버전으로 올리지 않으며, 환경 설정·NPC 인원과 크기·물리 충돌·경로·경보·인벤토리·AI 관측 계약을 변경하지 않습니다. 카메라의 화면 구성만 수정했습니다. 공간 좌표와 실행 규칙은 [마트 공간 v3 보고서](market-layout-v3.md) 및 [AI 실행 계약](../frontend/docs/market-agent-contract.md)을 기준으로 합니다.

- 타입 검사: 통과.
- 전체 테스트: 24개 묶음, 197개 통과. 카메라 경계·확대 배율·터치 좌표 왕복, 기존 장보기 전체 흐름을 포함합니다.
- 웹 배포용 빌드: 최종 카메라 수정까지 포함해 통과. 로그는 로컬 frontend/.expo/market-retail-v4-build.log에 있습니다.
- AI 장보기 smoke: layoutVersion3, 상품 분류마다12칸/9종, 2회 시도 후 성공·100점·247이벤트. 합성 검증 데이터는 로컬 frontend/.expo/market-retail-v4-episode.json입니다.
- 실제 브라우저: 1280×720과375×812에서 공통HUD, 판매 구역, 계산대·입출구를 확인했습니다. 사과 담기→장바구니1개 확인→해당진열대에 반납, 계산대 오른쪽 이동과 카메라가 멈춘 구간의 터치 이동도 확인했습니다.
- 일반 앱: 홈→게임→마을→마트→냉장식품 진열대 열기 경로를 확인했습니다. 별도 실험 페이지와 같은 아트/HUD를 사용합니다.
- 정적 배경과 진열대는 memo 처리하여 이동 시 불필요한 재렌더링을 줄였습니다. 많은 실제 이동·화면 검사를 한 번에 수행하는 앱 통합 테스트 한 건의 실행 한도를15초로 지정했으며 검증 항목은 유지했습니다.
- 초기 로딩 지연에 대해 글꼴·상품·음원·캐릭터 요청을 최적화하고 서버를 재시작했습니다. 후속 변경과 실제 관측은 [로딩 최적화 보고서](market-loading-optimization-2026-09-13.md)에 있습니다. 일반 홈의 퀘스트 API 응답 오류는 별도 백엔드 연결 문제입니다.

브라우저 확인은 `?muteAudio=1`을 사용했습니다. 실제 iPhone·Android 단말의 프레임 속도와 터치 감각은 이번 데스크톱 검증에 포함되지 않습니다. 지도용 60종의 단순 RGBA 디코딩 크기는 약 165MiB에서 3.75MiB로 줄었으나 이는 이미지 픽셀 합계이며 앱 전체 메모리나 실제 FPS 측정값은 아닙니다.
