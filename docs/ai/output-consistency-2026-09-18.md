## 변경한 구조

AI-002의 원인은 같은 근거를 관찰 본문, finding의 근거 목록, `claimChecks`에 반복 작성해야 하는 구조였다. 한 부분을 수정하고 다른 부분에 이전 ID를 남길 수 있었다.

새 검토 출력 `claim-evidence-v2`는 문장과 근거를 한 묶음으로 작성한다. 예를 들어 관찰은 다음처럼 온다.

```json
{
  "observation": [
    {"text": "장바구니를 열었습니다.", "evidenceEventIds": ["E106"]},
    {"text": "장바구니를 닫았습니다.", "evidenceEventIds": ["E107"]}
  ]
}
```

서버는 이 객체에서 `(E106) 장바구니를 열었습니다. (E107) 장바구니를 닫았습니다.`라는 공개 응답과 해당 finding의 근거 목록을 구성한다. 문장 자체와 AI가 선택한 근거는 바꾸지 않는다. 해석·대안 문장의 근거도 같은 방식으로 목록에 포함한다. 서로 다른 주장에 같은 사건을 인용하는 것은 가능하지만 같은 주장의 근거를 여러 필드에 따로 생성하지 않는다.

`summary`, `observation`, `interpretation`, `alternativeExplanations`, 세션 `explanation`은 모두 문장 객체 배열이다. 한 문장도 배열로 표현하고, 여러 문장은 빠짐없이 원래 순서대로 보존한다. 공개 응답에서는 기존 문자열·문자열 배열·UUID 근거 목록 형식을 유지하므로 화면과 프로필의 응답 계약은 바꾸지 않는다. 문장별 원본 근거는 모델 응답 감사 기록에 보존한다.

다음 검사는 유지한다.

- 제공되지 않은 사건, 비어 있는 필수 근거, 잘못된 문장 객체 형식 거부.
- 근거 목록과 관찰 절의 중복·순서 역전 거부.
- 별도 `claimChecks`, finding 최상위의 별도 근거 목록, 문장 본문에 다시 쓴 E번호 거부. 충돌하는 두 출력 중 하나를 임의로 선택하지 않음.
- 최종 공개 분석에 기존 세션 참조·게임 설정·필수 필드 검사 적용.
- 실패한 초안을 승인 결과로 내보내지 않음.

행동의 의미·성패·지원 선택은 AI가 판단한다. 코드는 형식 변환과 참조 검사만 수행한다. 실제 분석은 새 형식만 사용하고, 예전 `claimChecks` 검증기는 저장된 과거 응답 재현에만 남겨 둔다.

현재 버전은 `behavior-analysis-v26-claim-arrays` / `analysis-review-v13-claim-arrays`다. 관측 단계의 요청 JSON 스키마나 학교 게이트웨이를 수정할 필요는 없다. 변경은 백엔드 재시작으로 적용한다.

## 실험 중 확인한 설계 오류와 연결 실패

첫 설계인 `analysis-review-v12-attached-evidence`는 요약·해석·세션 설명을 단일 객체로, 관찰만 배열로 구분했다. 실제 모델은 모든 문장 필드를 배열로 출력했고, 재시도에서도 `/summary`의 `INVALID_REVIEW_CLAIM_SHAPE`로 실패했다. 출력 잘림은 없었다. 전체 260.542초, 모델 응답 5회였다.

이를 통과시키려고 문장을 버리거나 첫 문장만 고르지 않았다. 계약 자체를 모든 문장 필드가 배열인 v2로 통일했다. 여러 요약·해석·세션 설명의 문장과 근거를 모두 보존하는 자동 검사도 추가했다. 첫 설계의 실패 응답은 `live-first-format.json`에 보관한다.

이어진 v13 시험은 첫 요청 연결이 세 번 시간 초과되어 59.623초에 `AI_CONNECT_TIMEOUT`으로 중단됐다. 모델 응답은 없었고 출력 검증 실패가 아니다. 이후 상태 확인 요청이 HTTP 200으로 돌아와 새 전체 시험을 시작했다. 이 기록은 `live-network-failure.json`에 보관한다. 연결 문제가 해결됐다는 뜻은 아니다.

## 자동 검사 범위

최종 분석 패키지 회귀 검사 **128개 중 109개 통과·19개 조건부 건너뜀·실패 0개**. 저장된 실제 응답을 사용하는 재현 검사도 포함했다. 네트워크가 필요한 조건부 검사를 전부 실행한 수치는 아니며, 실제 학교 모델 호출 결과는 위에 별도로 기록했다. 첫 구조 변경에서는 105개 통과·20개 건너뜀, 배열 통일 직후 핵심 검사에서는 34개 모두 통과했다.

- 단일 문장 근거로 공개 본문·근거 목록을 구성하며 원본 객체는 변경하지 않음.
- 문장의 근거 변경 시 이전 ID가 상위 목록에 남지 않음.
- 여러 요약·해석·세션 설명을 버리지 않고 보존.
- 알 수 없는 ID, 중복·역순 관찰, 빈 근거, 중복된 출력 계약, 구버전 형식 거부.
- 구체적인 문장 경로와 문제 ID를 감사 기록·재시도에 전달.
- 기존 감사 JSON 읽기와 기존 공개 응답 검증 유지.

실제 시험은 합성 로그를 사용하고 DB·사용자 프로필에는 쓰지 않는다. 구조 통과를 사실성이나 교육 효과의 입증으로 해석하지 않는다.
