# 행동·이동 기반 적응형 마트 구현 및 검증

작업일: 2026-10-12. 코드와 실제 생성·화면 플레이 검증을 완료했다. 학교 연결 복구 후 같은 플레이의 AI 최종 판정과 프로필 갱신까지 정상 완료했다. 외장하드 보관 결과는 마지막 항목과 별도 보관 확인서에 기록한다.

## 구현 범위

추천 퀘스트에 `runtimePlan`과 `observationPlan`을 추가했다. AI가 이전의 목표·행동·도움·반납·계산·실제 이동 및 배치를 함께 읽고 다음 과제의 조건과 관찰할 행동을 선택한다. 이미 만든 세 가지 배치(`classic`, `aisles`, `corner`)부터 사용하며 자유 좌표로 새 벽이나 매대를 만드는 기능은 포함하지 않는다.

| 조절 대상 | 적용 범위 |
|---|---|
| 배치 | 기존 3개 구조, 5개 상품 분류의 매대 위치 교환 |
| 사람·장애물 | 종업원 1–3명, 손님 1–5명, 기둥·의자 0–4개, 계산원 0–2명 |
| 계산 | 유인/셀프 계산대 구성, 정상·오청구·무작위 계산 내역 |
| 품절·구매 조건 | 목표 상품의 품절, 대체 허용/불가, 품절 보고, 상품별 재고, 정확한 상품/같은 종류 허용 |
| 추가 조건 | 예산 안에서 음료 선택, 제한 시간, 출입·계산원 요청 감점 |

새 AI 조건은 장보기 시작 전에만 적용한다. 사용자가 설정창에서 바꾼 항목은 다음 생성의 고정 조건으로 전달한다. AI는 그 외 항목을 정한다. 결과의 구조·범위·구매 가능성·예산·인용 이벤트 존재·수동 설정 일치 여부를 검증하고, 실제 플레이의 충돌 판정으로 목표 매대·직원·계산대 접근 경로를 확인한다.

추천 과제에서도 실제 품절·전화 상담·계산 내역 정정·셀프 계산 화면을 사용한다. 기존 추천 과제가 일반 계산 화면으로 이 기능들을 우회하던 연결을 고쳤다. 실제 적용 설정, 화면에서 미리 안내한 조건, 변경된 구매 목표, 도움·정정 행동과 결과를 원본 로그에 추가했다.

## 생성 반복 방지

- 인증된 사용자별 비동기 작업에 진행 상태를 제공한다. 같은 사용자·프로필·환경의 진행 중 요청은 공유한다.
- 새 적응형 경로는 원본 관찰 → 생성 → 검토 → 필요한 필드 수정 → 재검토의 최대 5회 AI 호출을 사용한다.
- 대기 시간을 포함한 전체 작업은 최대 300초다. 시간 초과·취소·실패가 확정되면 늦게 도착한 응답으로 성공 상태를 덮어쓰지 않는다.
- 형식이 잘못된 검토를 후보의 다른 필드 수정으로 바꿔 처리하지 않는다. 근거가 불충분하거나 제약을 통과하지 못하면 성공으로 배포하지 않는다.
- 기존 동기식 추천 경로도 생성 시도 수를 5회에서 2회로 줄이고 전체 시간 제한을 적용했다. 새 경로의 5회 상한과 구분한다.

클라이언트 HTTP 호출과 작업의 종료는 제한한다. 외부 AI 게이트웨이가 연결 종료와 동시에 GPU 추론까지 즉시 중단하는지는 이번 검사 범위에 포함하지 않았다.

## 원본 근거와 토큰

기존 사람 플레이 `03600975-65f4-4b80-85fc-a8ff0f699548`의 370개 이벤트를 재사용한다. 새 사람 플레이나 반복 학습 표본으로 세지 않는다. 219개 이동 샘플의 시각·좌표·이동 구간 값은 원본과 대조한다.

첫 관찰 요청에는 모든 위치 샘플, 실제 배치, 이동 전환, 상호작용을 전달한다. 이후 생성·검토는 모든 원본 상호작용과 이동 전환, 배치 및 AI가 인용한 위치 샘플을 사용한다. 전체 원본은 변경 없이 보존한다. 수집용 반복 메타데이터·장식 이미지 등은 목적에 맞게 투영하며, 전체 원본의 모든 필드를 모든 요청에 반복 전송한다는 뜻은 아니다.

검토 단계에서는 후보가 인용한 사건을 ID별 원문으로 펼쳐 먼저 제공한다. 배열의 행 번호와 사건 ID를 혼동하는 문제를 줄인다. 현재 원본과 같은 데이터셋·세션이 과거 이력에도 있으면 원본 참조로 대체하며, 다른 플레이는 유지한다. 품목 가격 합계는 카탈로그에서 계산한 값도 함께 제공한다.

## 검증 환경과 해석

- 학교 Qwen3.6 27B 모델, 문맥 24,576, 요청 예산 24,000 토큰을 사용한다.
- 별도 로컬 DB `oneuldo_pilot_adaptive_20261012`, 백엔드 `18170`, 앱 `18172`를 사용한다. 기존 수동 플레이 DB의 원본을 복사해 시작했다.
- 실제 화면 기능 검사는 Codex의 키·버튼·드래그 입력이다. 페르소나 실험이나 실제 사람의 학습 효과 검증이 아니다.
- AI가 제안한 조건이 실행되는지와 그 조건이 교육적으로 효과적인지는 별개다. 원인을 모르는 재방문·직원 접근을 능력 부족으로 단정하거나, 한 번의 성공으로 숙달을 판정하지 않는다.

### 실제 학교 AI 생성

최종 `market-ai-quest-v60-adaptive-world` 생성은 **156.866초, AI 3회 호출**로 완료했다. 생성 ID는 `2c6ade59-875b-4ef8-8848-5c716a350078`이다. 첫 관찰의 원본 입력은 21,778토큰이며 출력 1,200과 여유 32를 포함해 23,010으로 요청 예산 24,000 안에 들어갔다.

설정창에서 통로형 배치, 직원 3명, 손님 1명, 우유 품절, 대체 불가, 오청구를 고정했다. AI는 이를 유지하고 우유·바나나·주스 각 1개, 예산 9,000원, 제한 시간 300초, 계산원 1명, 기둥 1개, 의자 0개를 제안했다. 이 검사는 **사용자 설정을 보존하면서 나머지 조건을 생성하는 사례**다. 직원 3명이나 통로형 배치를 AI가 이동 로그만으로 자율 선택했다고 해석하면 안 된다.

개발 중 발생한 품목 수 불일치, 사건 인용 혼동, 프롬프트 초과, 수동 설정 무시, 잘못된 검토 수정 경로를 수정하고 실패 원문도 남겼다. 초기 `live-generation-6`과 v56은 READY여도 근거 해석에 문제가 있어 최종 품질 성공에 포함하지 않는다. 같은 사람 기록으로 재생성한 횟수를 새 플레이나 학습 효과로 세지 않는다.

### 실제 화면 플레이

격리한 앱에서 직접 키와 버튼으로 플레이했다. 세션은 `6e42559c-0668-44a7-9da3-e8898a91a9b6`, 데이터셋은 `1dcc0936-9bc5-461d-9541-939a6403e965`이며 원본 이벤트 **191개**, 실제 제한 시간 경과 **185.679초**를 기록했다.

- 통로형 매대, 직원 3명, 손님 1명과 우유 재고 0이 실제 게임에 반영됐다.
- 바나나 1개만 담고 계산했다. 시스템이 바나나 2개·7,200원으로 잘못 청구했고, 화면에서 정정하여 1개·3,600원으로 바뀌었다.
- 우유 품절 해결과 주스 구매는 일부러 수행하지 않았다. 원본 최종 상태에 `stockout.status=unresolved`, 제출 장바구니 `banana:1`이 남았다.
- 이 사례의 기대 결과는 “계산 정정 수행”과 “전체 장보기 목표 미완료”의 구분이다. 연결 복구 후 AI는 정정 행동을 별도 finding으로 기록하고 전체 세션을 **FAILURE(목표 미완료)**로 판정했다.

실제 분석의 두 관찰 단계는 완료됐으며 두 번째 관찰은 바나나 선택, 시스템 오청구, 정정·제출을 구분하고 우유·주스 선택 기록이 없음을 짚었다. 최종 종합 요청 중 학교 SSH 연결이 사라져 `AI_TRANSPORT_ERROR`가 발생했다. 같은 기록으로 재시도했으나 `AI_CONNECT_FAILED`로 종료됐다. 최종 요청은 입력 15,335 + 출력 3,200 + 여유 16 = 18,551토큰으로 24,000 이하였으므로 이번 중단 원인은 토큰 초과가 아니다.

기존 SSH 소켓 소실과 학교 서버·점프 서버의 SSH 시간 초과를 확인했다. 당시 Mac에는 테스트 백엔드에 연결된 `caffeinate`가 동작했다. 17:56 연결 복구 후 저장된 두 관찰 결과를 재사용해 같은 세션 분석을 재개했으며 원본 스냅샷이 로컬 원문과 동일함을 확인했다.

### 연결 복구 후 최종 분석

- 재개 작업 `eb29433d-38c2-498e-a881-8b1d1d84873a`: **READY**, 대기·프로필 포함 **297.121초(약 4분 57초)**.
- 분석 `a8f5ab26-5735-4fa6-9b9d-f707270b02c9`: **READY**, 227.451초. 관찰 캐시 2개를 사용하고 실제 AI를 4회 호출했다. 검토 응답의 잘못된 인용 표기를 한 번 수정한 뒤 검토를 통과했다.
- 프로필 `f178c588-1482-4c77-b026-f217ed58ca4d`: **READY**, 69.151초, 실제 AI 1회. 동일한 세션·데이터셋·최종 분석을 참조하는지 확인했다.
- 분석은 바나나만 담은 제출 상태와 시스템 오청구 정정을 분리했고, 세션을 **FAILURE**로 판정했다. 프로필은 우유 품절 미해결, 주스 미구매, 시스템이 주입한 오청구를 정정한 사실을 반영했다. 따라서 이 부정 사례에서 자동 성공 현상은 재현되지 않았다.
- 새 플레이를 만들지 않았고 이전 실패 원문도 유지했다. 한 번의 부정 사례로 모든 상황에서 오판이 없음을 입증한 것은 아니다.

### 분석 품질의 남은 한계

원본 행동 인용과 직원 도움·반품·계산 정정의 구분은 개선됐다. 다만 최종 추천 이유에는 “매대 순서가 같으므로 공간 기억력 변동을 분리 평가한다”는 과한 설명이 남았다. 실제 배치 구조는 바뀌었고 품절·목표 수·오청구도 함께 변했으므로 한 요인의 효과나 학습 향상을 분리해 입증할 수 없다. 이번 결과는 **환경 조절의 기능 검증**이며 학습 효과를 입증한 결과가 아니다.

기존 3개 배치와 그 안의 매대 위치 교환이 구현 범위다. 임의 좌표의 새로운 매장 구조 생성은 포함하지 않는다. 이번 미완료 사례의 최종 판정은 원본과 일치했다. 여러 조건에서의 반복 재현성은 후속 검증이 남았다.

최종 분석·프로필에는 미방문 매대를 “찾지 못했거나 방문하지 않았다”고 설명하고 다음 계획에 `NAVIGATION_ERROR`를 붙인 부분이 남았다. 원본은 미방문과 미구매를 뒷받침하지만 그 이유나 탐색 능력의 부족을 입증하지 않는다. 사실 관찰과 원인·능력 해석을 더 엄격히 구분해야 한다. 이번 운영자의 의도적 미완료 플레이를 실제 학습자의 능력 자료로 사용하지 않는다.

실제 플레이 당시 직접 키 입력에는 AGENT 태그가 없었으므로 격리 DB와 실행 설명서로 Codex 기능 검사임을 명시했다. 이후 입력 주체를 로그에 연결하는 수정과 관련 검사를 추가했고 최신 웹 빌드에 반영했다. 이 수정 전 실제 플레이 원본은 소급 변경하지 않았다.
