# 게임 NPC 대중교통 퀘스트 연동

## 1. 목적

마을의 민수 NPC가 제공하던 고정 횡단보도 2지선다 퀴즈를 제거하고,
퀘스트 탭의 `PUBLIC_TRANSPORT` 퀘스트 선택·AI 변형·수행 기록 로직을 게임 안에서 재사용한다.

이 연동의 목적은 게임 안의 짧은 상호작용도 별도 샘플 데이터로 끝내지 않고,
사용자의 추천 난이도와 행동 프로필을 갱신하는 실제 퀘스트 수행으로 처리하는 것이다.

## 2. 실행 흐름

1. 사용자가 민수의 `대중교통 안전 연습` 의뢰를 수락한다.
2. 민수와 대화를 끝내면 NPC 퀴즈 화면이 열린다.
3. 로그인 상태이면 `GET /api/quest/recommended`로 사용자 난이도에 가까운 목록을 가져온다.
4. 목록에서 첫 번째 `PUBLIC_TRANSPORT` 퀘스트를 선택한다.
5. `GET /api/quest/{questId}/detail`로 단계와 선택지를 가져온다.
6. 로그인 상태이면 기존 AI 퀘스트 생성 파이프라인으로 전체 단계를 준비한다.
7. AI 생성이 전부 성공하면 생성 단계를 사용하고, 한 단계라도 실패하면 퀘스트 전체를 DB 원문으로 되돌린다.
8. `POST /api/quest/{questId}/sessions`로 수행 세션을 시작한다.
9. 선택할 때마다 기존 FIFO 큐를 통해 수행 이벤트를 저장한다.
10. 마지막 정답 이후 `POST /api/quest/sessions/{sessionId}/complete`로 세션을 완료한다.
11. 게임 수첩의 민수 의뢰도 완료 상태로 바뀐다.

비로그인 상태에서는 공개 퀘스트 목록과 원문 퀘스트로 연습할 수 있지만,
개인 추천·AI 생성·서버 수행 기록은 적용하지 않는다.

## 3. 기록 형식

각 선택은 퀘스트 탭과 같은 필드로 저장한다.

| 필드 | 의미 |
| --- | --- |
| `sessionId` | 이번 NPC 퀴즈 수행 세션 |
| `stepId` | 현재 대중교통 퀘스트 단계 |
| `choiceId` | 사용자가 선택한 선택지 |
| `attemptNumber` | 같은 단계에서의 시도 횟수 |
| `hintUsed` | NPC 화면에서는 현재 `false` |
| `responseTimeMs` | 단계가 나타난 뒤 선택할 때까지 걸린 시간 |

오답 후 정답을 다시 선택하면 같은 `stepId`에 `attemptNumber`가 1, 2 순서로 쌓인다.
따라서 기존 정답률·독립 성공률·반응시간 기반 프로필 계산에 포함할 수 있다.

## 4. 화면 상태

- `loading`: 추천 퀘스트와 AI 변형을 준비한다.
- `question`: 현재 단계, 전체 진행도, 상황, 선택지, 피드백을 표시한다.
- `result`: 완료 단계 수와 DB 퀘스트의 보상 XP를 표시한다.
- `error`: 다시 시도하거나 마을로 돌아갈 수 있다.

AI가 만든 단계를 사용하면 `AI 맞춤 문제` 배지를 표시한다.
원문 fallback일 때는 별도 AI 배지를 표시하지 않는다.

## 5. 주요 구현 파일

- `frontend/src/game/useNpcTransportQuest.ts`
  - 추천 퀘스트 조회, AI 준비, 세션, 시도 이벤트, 완료·이탈 처리
- `frontend/src/screens/GamePrototypeScreen.tsx`
  - NPC 대화와 대중교통 퀴즈 화면 연결
- `frontend/src/game/dailyQuests.ts`
  - 민수 의뢰 제목과 설명
- `frontend/__tests__/NpcTransportQuest.test.tsx`
  - 추천 조회부터 오답·정답·완료 기록까지 검증

## 6. 제한사항

- 게임을 재실행하면 게임 수첩의 일일 의뢰 상태는 현재 메모리에서 초기화된다.
- 서버 퀘스트 세션과 이벤트는 저장되지만, 게임 수첩 상태 자체는 아직 서버 동기화 대상이 아니다.
- NPC 화면에서는 힌트 버튼을 제공하지 않으므로 `hintUsed`는 항상 `false`다.
