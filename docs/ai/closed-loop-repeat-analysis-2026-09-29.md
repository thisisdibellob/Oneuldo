### 통합 검증 실패

오류: `INVALID_AI_ANALYSIS`, 직접 원인 `EVIDENCE_NOT_IN_CHILD_INTERPRETATIONS`.

통합 입력의 앞 3개 자식에는 관찰이 비어 있고 불확실성에 사건 범위(E3112~E3307 등)가 적혀 있었다. 네 번째 자식은 E3701·E3742·E3898 등의 관찰 근거를 제공했다. AI는 앞 3개의 범위 경계까지 새 관찰의 evidenceEventIds에 넣었다. 1차와 자동 재시도 모두 이 제한을 위반했다.

이는 존재하지 않는 사건 UUID를 새로 만들었다는 의미와 다르다. **원문 범위/불확실성 언급을, 앞 단계에서 검증된 관찰 근거로 승격한 문제**다. 검증기는 자식 관찰에 인용된 ID만 통합 근거로 허용하므로 이를 차단한 것이 맞다. 검증 기준을 완화하거나 AI 출력에서 ID를 임의 삭제하지 않았다.

## 비교 결론과 후속 개선 순서

1. **전처리 개선은 효과가 있다.** 이전 동일 7,972개 입력은 20분 56초에도 준비가 미완료였고, 이번 첫 실행은 약 5분 4초에 첫 모델 호출에 도달했다. 이전 완료 시간이 없으므로 정확한 배속/절감률은 계산하지 않는다.
2. **최종 분석 신뢰성은 아직 검증을 통과하지 못했다.** 구매 규격 불일치라는 핵심 관찰은 맞았지만 통합에서 출처 범위를 잘못 인용했다. 관찰 단계의 올바른 문장을 최종 성공 결과로 포장하지 않는다.
3. **새 HTTPS 연결의 불안정이 계속된다.** 첫 긴 실행의 47개 요청은 응답했으나 이후 서로 다른 4개 분석 호출에서 각각 TCP 연결 시도 3회가 실패했다. 재시도 증대만으로 해결됐다고 할 수 없다. 서버 도달/응답 패킷을 동일 시각에 대조하는 네트워크 진단이 우선 필요하다.
4. 통합 프롬프트에 허용 근거 ID 목록을 명시하고 ‘관찰 없음’인 자식의 범위/불확실성은 새 관찰의 근거로 승격하지 않도록 안내·재시도 오류 정보를 구체화할 후보가 있다. **이번 시험에서는 프롬프트나 검증기를 바꾸지 않았다.** 수정 후 저장된 실패 통합 입력을 먼저 재검증해야 한다.
5. 원본/모델/프롬프트/토큰 설정의 지문을 확인하여 입력 분할 결과도 재사용하는 개선이 필요하다. 응답 checkpoint만 있어도 현재는 재시도 전처리가 반복된다.
6. 이후 동일 조건으로 최종 분석·프로필·AI 퀘스트 연결을 확인한 뒤 반복한다. 서로 다른 훈련 과제의 정확도/시간 차이만으로 능력 향상을 판정하지 말고 공통 사후 평가와 복수 seed가 필요하다. 현재 actor의 합성 정책 변화와 실제 참여자의 학습 효과는 계속 구분해야 한다.
