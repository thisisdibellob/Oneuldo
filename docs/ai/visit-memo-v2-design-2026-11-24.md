# 방문 메모 v2 — 칸이 있는 기억 메모와 매 방문 고쳐 쓰기 (2026-11-24)

## 왜 바꾸나

v1 방문 메모(`authoring-v5-h200-memo`, `previous-visit-memo-v1`)는 페르소나가 방문을 마치며 300자 이내 자유 서술로 남겨요. 시스템이 기억을 만들지 않고 페르소나가 직접 쓴다는 방향은 유지해요. 다만 두 가지 한계가 있었어요.

- **쌓이지 않아요.** v1 지침은 "이번 세션에서 실제로 보고 겪은 것만" 쓰라고 해요. 그래서 2회차에 다시 가지 않은 매대 같은 1회차 기억은 3회차로 넘어가지 못해요.
- **무엇을 기억해야 하는지 틀이 없어요.** 사람이 다음 방문에 쓰는 기억(경로, 예상이 빗나간 장면, 다음 계획)이 빠지거나 섞여서, 분석할 때 비교하기 어려워요.

v2는 아래 연구들을 바탕으로 칸을 정하고, 매 방문 끝에 메모를 고쳐 쓰게 해요. 칸 구분은 연구에서 정해진 기억 분류가 아니라, 연구 결과를 장보기 상황에 맞춰 묶은 **공학적 설계**예요.

## 조사한 연구와 반영한 점

| 연구 | 확인한 내용 | 메모에 반영한 점 |
|---|---|---|
| 사건 분할 이론 (Zacks 외 2007, Kurby & Zacks 2008) | 사람은 경험을 사건 단위로 끊어 기억해요. 예측이 빗나간 순간이 사건의 경계가 되고, 경계 시점이 장기 기억에 더 잘 남아요. 사건은 큰 사건 안에 작은 사건이 들어가는 계층 구조예요. | `[기억나는 장면]`에는 예상과 달랐던 순간만 최대 3개 남겨요. |
| 스크립트 이론 (Schank & Abelson 1977, Bower·Black·Turner 1979) | 사람은 일상 활동의 정형화된 순서(스크립트)를 갖고, 개별 경험을 그 틀의 빈칸을 채운 것으로 기억해요. 틀에서 벗어난 일(방해·중단)이 일상적인 행동보다 더 잘 기억된다는 요약이 있어요. 틀이 너무 경직됐다는 비판도 있어요. | `[장보기 순서]`(이 마트에서의 틀)와 `[기억나는 장면]`(틀에서 벗어난 일)을 나눠요. |
| 사례 기반 학습 이론 (Gonzalez, Lerch & Lebiere 2003) | 역동적 의사결정에서 사람은 "상황–결정–결과" 사례를 쌓고, 지금 상황과 비슷한 사례를 떠올려 판단해요. 처음엔 어림짐작으로 하다가 사례가 쌓이면 사례 기반 판단으로 바뀌어요. | 장면을 "무엇이 보였나 → 무엇을 했나 → 어떻게 됐나"로 써요. 다음 방문에서 비슷한 화면을 보면 떠올릴 수 있게 상황을 보이는 모습으로 적어요. |
| 공간 지식 (Siegel & White 1975, Montello 1998) | 공간 지식은 랜드마크, 경로, 전체 배치로 나뉘어요. 차례로 생긴다는 견해와, 함께 생겨 점점 정교해진다는 견해(Montello)가 있어요. 실제 환경과 VR에서 반복 노출로 이 지식들이 늘었다는 2025년 보고가 있어요. 길 안내 도구가 장기 공간 학습을 방해할 수 있다는 연구도 있어요. | `[장소와 길]`은 기준점·방향·움직임 순서로 쓰고 (확실)/(흐릿)을 붙여요. 시스템이 지도나 길 안내를 주지 않는 기존 원칙을 유지해요. |
| 지적장애인의 길찾기 (Courbois 외 2013, 2019 및 관련 연구) | 다운증후군인 사람은 특정 경로는 익혔지만 경로들을 전체 배치로 통합해 지름길을 찾는 것은 어려웠어요. 지적장애 참여자는 길을 주로 "왼쪽으로 돌아" 같은 행동 순서로 묘사했고, 대조군은 랜드마크를 더 언급했어요. 그래도 랜드마크 지식 자체는 좋았어요. 경로 학습의 어려움 정도는 연구마다 달랐어요. | 칸은 모든 페르소나에 같게 둬요. 장소를 랜드마크로 쓸지 움직임 순서로 쓸지, 전체 배치까지 쓸지는 페르소나가 정해요. 시스템이 장애 유형별로 칸이나 글자 수를 줄이지 않아요. |
| 실행 의도 (Gollwitzer & Sheeran 2006 메타분석) | 계획을 "만약 X 상황이면 Y를 한다"처럼 상황 단서에 묶으면, 목표만 세운 경우보다 목표 달성이 높았어요(94개 검증, d = .65). 대부분 목표만 세운 대조군과 비교한 결과예요. | `[다음엔]`을 "~이 보이면 ~한다" 형식으로 최대 2개 써요. 다짐을 실제로 지켰는지 trace에서 대조할 수 있어요. |
| 기억 재응고 (Nader 외 2000, Hupbach 외 2007, Lee·Nader·Schiller 2017 리뷰) | 기억은 떠올린 뒤 다시 바뀔 수 있는 상태가 돼요. 이때 새로 배운 것이 일화 기억을 강화하기도 하고, 틀리게 바꾸기도 해요. | 메모를 이어 붙이지 않고 매 방문 끝에 하나로 고쳐 써요. 고쳐 쓰다가 틀어지는 것도 사람다운 현상으로 허용하고, 코드가 바로잡지 않아요. |
| LLM 에이전트 기억 (Reflexion, Shinn 외 2023 / Generative Agents, Park 외 2023) | 시도마다 말로 쓴 반성을 기억에 두면 텍스트 게임 과제(ALFWorld) 성적이 올랐어요. 경험 기록에서 반성을 만들어 다시 기억에 넣고, 최근성·중요도·관련성으로 꺼내는 구조도 있어요. | 구현 선례로만 참고해요. Reflexion은 성공률 최적화가 목적이라 그대로 쓰면 사람보다 빨리 배우게 될 수 있어요. 그래서 "반성"이 아니라 "이 사람이 기억할 만한 것"을 쓰게 해요. |
| 게임 전문성 연구 (체스·스타크래프트·테트리스) | 체스 전문가는 덩어리(청크) 기억으로 판면을 잘 기억해요. 스타크래프트 연구는 주로 운동 청킹과 기록 데이터를 다뤄요. 회고형 자기 보고의 타당도가 약하다는 지적이 있어요. | 반복한 순서는 "늘 가던 길로 냉장고"처럼 짧게 묶여도 돼요. 메모는 자기 보고라서 학습의 증거가 아니라 행동과 대조할 자료로 써요. |

게임 플레이 중 상황 기억을 직접 다룬 연구는 찾지 못했어요. 그래서 근거 대부분은 일상 행동 기억, 공간 학습, 의사결정 연구에서 가져왔어요.

## 메모 구조

```
<visit-memo>
[장보기 순서]
들어가서 목록 보기 → 오른쪽 안쪽 냉장고 → 계산대(입구 옆인 것 같음)
[기억나는 장면]
- 들어가니 과일만 보였다 → 왼쪽으로 걸었다 → 벽이 나와서 한참 헤맸다. 답답했다.
- 직원이 보였다 → 우유 어디 있냐고 물었다 → 바로 알려줬다.
[장소와 길]
- 우유: 입구에서 오른쪽 벽 따라 끝 냉장고 (확실)
- 계산대: 입구 근처 (흐릿)
[다음엔]
- 들어가서 과일이 보이면 오른쪽 벽 쪽으로 간다.
[어느 마트에서나]
- 모르면 직원에게 묻는 게 빠르다.
</visit-memo>
```

| 칸 | 내용 | 형식 제한 |
|---|---|---|
| `[장보기 순서]` | 이 마트에서 내가 하는 순서 | 없음 |
| `[기억나는 장면]` | 예상과 달랐거나 인상 깊은 순간. 본 것 → 한 것 → 결과, 기억나면 느낌 | `- ` 항목 최대 3개 |
| `[장소와 길]` | 기준점·방향·움직임 순서로 쓴 장소와 길, 뒤에 (확실)/(흐릿) | `- ` 항목 |
| `[다음엔]` | "~이 보이면 ~한다" 형식의 계획 | `- ` 항목 최대 2개 |
| `[어느 마트에서나]` | 다른 마트에도 통한다고 믿는 요령 | `- ` 항목 |

## 작성 규칙 (지침 `authoring-v5-h200-memo-v2`)

1. **칸을 억지로 채우지 않아요.** 기억나지 않는 칸은 비우거나 빼요. 채우려고 지어내지 않아요.
2. **고쳐 써요.** 지난 메모가 있으면 이어 붙이거나 그대로 베끼지 않고, 지난 기억과 이번 경험을 합쳐 하나로 다시 써요.
   - 이번에 다시 확인한 장소나 길은 (확실)로 올릴 수 있어요.
   - 틀렸던 것은 고치고, 잘못 기억했었다는 사실을 남겨도 돼요.
   - 덜 중요한 것은 흐려지거나 빠져도 돼요. 장면은 모든 방문을 통틀어 가장 기억에 남는 3개만 남겨요.
3. **페르소나답게 써요.** 얼마나, 얼마나 구체적으로, 어떤 방식으로 기억할지는 페르소나가 정해요.
4. **500자 상한은 입력 보호용이에요.** 칸 머리글을 포함한 값이고, 사람의 기억 용량을 흉내 내는 값이 아니에요.
5. **기존 금지 사항을 유지해요.** 선택지 ID, 지점 ID, 상품 ID, 좌표 같은 시스템 식별자를 쓰지 않아요. 받은 결정·관찰과 지난 메모 외의 파일을 보지 않아요.
6. **메모를 읽을 때:** (확실)이라고 적힌 것도 틀릴 수 있어요. `[다음엔]`을 따를지, 메모를 얼마나 믿을지는 페르소나가 현재 화면과 대조해 정해요. 메모는 cueRef가 아니고, 선택지는 현재 메뉴에서만 나와요.

## 구현

- **지침:** `market-simulator/actor-instructions/authoring-v5-h200-memo-v2.txt`
  - v1 메모 지침과 비교해 메모 읽기 문단과 메모 쓰기 문단 두 줄만 달라요(테스트로 확인). v1 지침 파일은 고치지 않았어요.
  - 읽기 문단은 방문 횟수(`visit.number`), 메모 프로필, 지난 메모, 다른 매장 요령을 읽는 법을 설명해요.
  - 쓰기 문단은 아래 "방문이 쌓일 때의 규칙"의 칸별 고쳐 쓰기 규칙과 메모 프로필을 따르게 해요.
- **메모 공통 모듈:** `market-simulator/visit-memo.cjs`
  - `MEMO_FORMATS`로 지침마다 메모 형식을 정해요. `authoring-v5-h200-memo`는 `previous-visit-memo-v1`(300자, 자유 서술), `authoring-v5-h200-memo-v2`는 `previous-visit-memo-v2`(500자, 칸 구조)를 써요.
  - `parseVisitMemoSections`는 형식만 검사해요. 알 수 없는 칸, 중복, 순서 어긋남, 첫 칸 앞의 글, 내용이 하나도 없는 메모, 항목 수 초과를 거부해요. 메모를 고치거나 채우거나 다시 정렬하지 않아요. v1 메모는 "no section headers"로 거부해요.
  - `visitMemoMetrics`는 글자 수, 칸별 줄 수와 항목 수, (확실)·(흐릿) 개수를 세요. 내용이 맞는지는 판단하지 않아요.
  - `storeKeyOf`는 같은 매장인지 정하는 키를 만들어요. `visitMemoProfileOf`는 페르소나의 메모 프로필을 읽어요.
- **입력 생성:** `market-simulator/whole-trace-actor-input.cjs`
  - v2 지침은 `--visit-memo-chain`이 반드시 필요해요. 방문 횟수와 지난 메모를 손으로 넘기지 않고 사슬 기록에서만 가져오게 하려는 거예요. v2 지침에 `--previous-visit-memo`를 쓰면 거부해요.
  - 사슬의 페르소나 id·버전과 매장 키가 준비된 요청과 다르면 거부해요.
  - 배우 입력에 `visit`, `visitMemoProfile`, (있으면) `previousVisit`, (새 매장 첫 방문이면) `otherStoreTips`를 붙여요. bundle과 `inputHash`는 바꾸지 않아요.
  - 실행 요약의 `visitMemoChain`에 사슬 파일 SHA-256, 방문 횟수, 넘긴 메모의 SHA-256, 프로필 파일 SHA-256을 남겨요.
- **사슬 도구:** `market-simulator/visit-memo-chain.cjs` (`init`, `record`, `metrics`)
- **사용 순서 (사람 × 매장 하나):**

  ```bash
  # 처음 한 번: 사슬 만들기 (다른 매장 사슬에서 요령을 가져오려면 --carry-any-store-from <다른-사슬.json>)
  node market-simulator/visit-memo-chain.cjs init output/<실험>/memo-chain.json <slot-1>/owner/prepare-response.json

  # 방문마다: 배우 입력 만들기 → 플레이 → 배우의 마지막 답을 파일로 저장 → 기록
  node market-simulator/whole-trace-actor-input.cjs <slot-N>/owner/prepare-response.json <slot-N>/actor-input.json \
    --template authoring-v5-h200-memo-v2 --visit-memo-chain output/<실험>/memo-chain.json
  node market-simulator/visit-memo-chain.cjs record output/<실험>/memo-chain.json <slot-N> <slot-N>/actor-final-reply.txt
  #   결정이 하나도 수락되기 전에 기술적으로 실패했으면 record에 --no-visit

  # 1차 비교: 페르소나별 메모 양과 형태
  node market-simulator/visit-memo-chain.cjs metrics output/<실험>/jimin-chain.json output/<실험>/neutral-chain.json
  ```

- **검증:** 사슬 테스트 5건(`test/visit-memo-chain.test.cjs`), 입력 생성 테스트 14건, market-simulator 전체 테스트 1246건 통과, `git diff --check` 통과. 이 검사는 입력 계약과 기록 형식만 확인하고, 실제 학습 효과는 확인하지 않아요.

## 페르소나별 메모 프로필

일반 성인과 지적장애인은 기억하는 방식과 질이 달라야 해요. 다만 기억하는 양을 숫자 상한으로 정할 근거는 찾지 못했어요. 레포 근거 검토(P14)도 작업기억 결과가 과제 조건에 따라 달라서 고정 한계로 볼 수 없다고 정리했어요. 그래서 다음 순서로 진행해요.

1. **지금:** 기억하는 방식만 프로필로 다르게 해요. 양은 모든 페르소나가 같은 상한(500자, 장면 3개, 계획 2개) 안에서 스스로 정해요.
2. **1차 비교:** 두 페르소나의 메모를 `metrics`로 비교해요. 글자 수, 칸별 항목 수, 확실 비율, 장소 서술 형태, 경험하지 않은 내용이 들어갔는지를 봐요.
3. **그 뒤:** 양이 거의 같게 나오면 페르소나별 상한을 정해요. 정하더라도 세션 중 `landmarkMemory`처럼 "합성 설계값이며 실측 기억 능력이 아님"이라고 표시해요.

프로필은 `market-simulator/personas/visit-memo-profiles.json`에 있어요. 페르소나 JSON에 넣지 않고 별도 파일로 뒀어요.
- **이유:** 페르소나 JSON을 고치면 페르소나 버전과 bundle `inputHash`, 회귀 fixture가 바뀌고, `neutral-adult-control` v4 전용 길찾기 문구 조건도 다시 맞춰야 해요. 메모 프로필은 플레이 중 행동이 아니라 메모를 쓸 때만 쓰는 정보라서 배우 입력에만 붙여요.
- **버전 묶기:** 각 프로필은 작성 기준이 된 페르소나 버전을 갖고 있어요. 페르소나 버전이 바뀌면 프로필을 다시 검토하기 전까지 사용을 거부해요.
- **프로필이 없는 페르소나:** `careful-checker`, `quick-decider`는 v2 메모 사슬을 만들 수 없어요.

| 항목 | 일반 성인 (`neutral-adult-control` v4) | 지민 (`mild-intellectual-disability-adult` v6) | 근거 |
|---|---|---|---|
| 장소 쓰는 방식 `placeForm` | `area-layout`: 구역과 배치 | `route-sequence`: 움직인 순서, 전체 배치로 잘 묶지 않음 | `wayfinding.memoryForm`·`cueLevel`, Courbois 2013·2019 |
| 계획 형식 `planForm` | `conditional-short`: 조건이 있는 짧은 계획 | `next-step`: 바로 다음 한 걸음, 한 문장 | `wayfinding.planHorizon`·`thoughtForm` |
| 일반 요령 `generalTips` | `may-generalize`: 다른 마트에 통할 요령을 떠올림 | `situation-bound`: 장면·상품 표기에 묶인 구체 기억이 주가 됨 | 일반화 연구(L01·L03·L04) |
| 확실해지는 방식 `confidence` | `once-confirmed`: 한 번 직접 확인하면 확실 | `repetition-needed`: 여러 번 겪어야 확실, 안 간 곳은 빨리 흐려짐 | `wayfinding.landmarkMemory.retention`, P10 |

## 하지 않은 것

- 새 플레이 실험은 돌리지 않았어요.
- 시스템 식별자가 메모에 섞였는지 자동으로 찾지 않아요. 한국어 메모에 `900mL` 같은 정상 표기가 있어 오탐 위험이 커요. 실험 후 사람이 검토해요.
- 방문 횟수, 망각률, 칸별 용량을 장애 유형에 따라 정하지 않았어요.
- 메모 내용이 맞는지, 정답에 가까운지 판정하지 않아요.

## 방문이 쌓일 때의 규칙

### 1. 기억은 "사람 × 매장" 단위로 이어져요

매장 키(`store-key-v1`)는 배치 버전, `layoutId`, 입구 공사 여부, 세계 크기, 벽, 입구, 출구로 만들어요. 매대 순서, 상품, 사람 수는 넣지 않아서 바뀌어도 같은 매장이에요(테스트로 확인).

- 메모 사슬은 페르소나 한 명과 매장 하나마다 따로 있어요. 2회차 메모는 1회차 메모를 이어받고, 3회차 메모는 2회차 메모를 이어받아요.
- **같은 매장인지는 시스템이 정해요.** 사람도 들어가기 전에 "그 마트"에 간다는 걸 알기 때문이에요. 기준은 같은 배치(`layoutId`)와 같은 건물 구조예요.
- **같은 매장인데 매대만 바뀐 경우**는 같은 사슬로 이어요. 바뀌었다는 사실은 알려 주지 않아요. 사람처럼 가서 보고 메모가 틀렸다는 걸 알아채야 해요.
- **다른 매장**에 갈 때는 새 사슬을 시작해요. 이전 메모 중 `[어느 마트에서나]` 칸만 넘기고, 페르소나에게는 처음 온 마트라고 알려요.

### 2. 메모를 쓸 때 볼 수 있는 것

| 회차 | 메모를 쓸 때 보는 것 | 결과 |
|---|---|---|
| 1회차 | 이번 방문의 경험 | 메모 1 |
| 2회차 | 메모 1 + 이번 방문의 경험 | 메모 2 (메모 1을 고쳐 쓴 것) |
| N회차 | 메모 N−1 + 이번 방문의 경험 | 메모 N |

- 페르소나는 메모 N−2 이전의 메모나 이전 회차 로그를 보지 않아요. 사람도 지난 기억은 지금 기억하는 형태로만 갖고 있기 때문이에요. 이전 메모와 로그는 분석용으로만 보관해요.
- 페르소나는 이번이 몇 번째 방문인지 알아요("이번이 3번째"). 사람도 대략 알고 있는 사실이에요.

### 3. 칸별로 고쳐 쓰는 규칙

규칙은 두 종류예요. **"반드시"**는 코드나 기록 검토로 확인하는 규칙이고, **"할 수 있다"**는 페르소나가 판단하는 규칙이에요. 망각 속도나 삭제 기준을 시스템이 숫자로 정하지 않아요.

**`[장소와 길]`**

| 이번 방문에서 | 고쳐 쓰는 방법 |
|---|---|
| 그 장소를 다시 보았고 메모와 맞았다 | (확실)로 올릴 수 있다 |
| 가 보니 메모와 달랐다 | 반드시 이번에 본 대로 고친다. "(전엔 왼쪽인 줄 알았음)"을 남길 수 있다 |
| 이번에 가지 않았다 | 그대로 두거나, (확실)을 (흐릿)으로 낮추거나, 지울 수 있다 |
| 처음 본 곳이다 | 추가할 수 있다 |

- 반드시: 확실도는 이번 방문에서 직접 확인한 것만 올라갈 수 있어요. 가지 않은 곳이 (흐릿)에서 (확실)로 오르면 안 돼요.

**`[기억나는 장면]`** (모든 방문을 통틀어 최대 3개)

- 새 장면과 옛 장면 중 더 기억에 남는 것을 남겨요.
- 장면 뒤에 "(처음 왔을 때)", "(지난번)", "(이번)"처럼 대략의 때를 붙일 수 있어요. 회차 번호처럼 정확할 필요는 없어요.
- **장면이 지식이 되는 경우:** 같은 일이 두 번 이상 겪어져서 교훈이 굳으면, 그 교훈을 `[장소와 길]`이나 `[장보기 순서]`로 옮기고 장면은 지울 수 있어요. 예를 들어 "또 왼쪽에서 헤맸다"는 "왼쪽은 막힘"이 돼요. 사람의 일화 기억이 반복되면서 일반 지식이 되는 과정을 따른 거예요.

**`[다음엔]`** (최대 2개) — 지난번에 세운 계획마다 결과를 따져요.

| 이번 방문에서 | 고쳐 쓰는 방법 |
|---|---|
| 상황이 나왔고, 해 봤고, 잘됐다 | `[장보기 순서]`로 옮기고 `[다음엔]`에서 지울 수 있다 (습관이 됨) |
| 해 봤는데 잘 안됐다 | 계획을 고치거나 버린다. 그 일을 `[기억나는 장면]`에 남길 수 있다 |
| 상황이 나왔는데 잊었다 | 계획을 남길 수 있다. "깜빡했다"를 장면으로 남길 수 있다 |
| 상황이 나오지 않았다 | 그대로 둘 수 있다 |

- 반드시: 새 계획은 이번 방문이나 메모에 있는 경험에서 나와야 해요.

**`[장보기 순서]`**

- 지금 이 마트에서 하는 순서로 다시 써요. 반복된 단계는 "늘 가던 길로 냉장고"처럼 묶을 수 있어요.
- 이번에 다른 순서로 해서 더 잘됐다면 바꿀 수 있어요.

**`[어느 마트에서나]`**

- 자기가 직접 겪은 것만 추가해요.
- 다른 매장으로 넘어가는 유일한 칸이에요. 다른 매장에서 맞지 않았으면 "(○○에선 아니었음)"처럼 고칠 수 있어요.

### 4. 500자를 넘을 때

- 지울 것은 페르소나가 정해요. 고르는 순서의 안내만 줘요. (흐릿)하고 오래 다시 쓰지 않은 것을 먼저 지우고, 이미 다른 칸으로 옮긴 장면을 그다음으로 지우는 식이에요.
- 시스템이 메모를 잘라 내지 않아요. 500자를 넘으면 형식 검사에서 거부돼요.

### 5. 방문이 정상적으로 끝나지 않았을 때

| 상황 | 메모 처리 | 방문 횟수 |
|---|---|---|
| 포기, 실패, 200결정 도달 | 평소처럼 메모를 써요 | 올라가요 |
| 결정이 하나라도 수락된 뒤 기술적으로 중단 | 메모를 쓸 수 있으면 써요 | 올라가요 |
| 결정이 하나도 수락되기 전에 기술적으로 실패 | 빈 메모. 사람은 이 방문을 겪지 않았어요 | 그대로예요 |
| 메모가 없거나 형식이 틀림 | 고치거나 대신 쓰지 않아요. 다음 방문에는 마지막으로 유효한 메모를 넘기고, 사슬에 "빈 곳"을 기록해요 | 올라가요 |

- 빈 곳이 있는 사슬은 분석할 때 따로 표시해요. 그 방문의 기억은 사람이라면 남았을 텐데 전달되지 않았기 때문이에요.

### 6. 사슬 기록 `memo-chain.json`

사람 × 매장마다 한 파일을 둬요. 실험 폴더에 두고, 외장하드 보관 대상에 포함해요. 경로는 사슬 파일 위치를 기준으로 한 상대 경로예요.

```json
{
  "version": "visit-memo-chain-v1",
  "template": "authoring-v5-h200-memo-v2",
  "memoFormat": "previous-visit-memo-v2",
  "personaId": "mild-intellectual-disability-adult",
  "personaVersion": "6",
  "storeKey": "store-key-v1:classic:<16자리 해시>",
  "storeKeyBasis": ["world.layoutVersion", "world.config.layoutId", "..."],
  "carriedAnyStoreTips": null,
  "entries": [
    { "visit": 1, "slot": "slot-1", "actorInputSha256": "<sha>", "inputMemoSha256": null,
      "replyFile": "slot-1/actor-final-reply.txt", "replySha256": "<sha>",
      "outputMemoFile": "memos/visit-1-slot-1.txt", "outputMemoSha256": "<sha>",
      "memoStatus": "valid", "error": null,
      "metrics": { "characters": 182, "sureMarks": 0, "vagueMarks": 1, "sections": [{ "id": "places", "lines": 1, "items": 1 }] },
      "recordedAt": "2026-11-24T00:00:00.000Z" },
    { "visit": 2, "slot": "slot-2", "inputMemoSha256": "<1회차 outputMemoSha256과 같음>", "memoStatus": "valid" }
  ]
}
```

- 반드시: N회차 배우 입력의 방문 횟수와 지난 메모는 사슬이 지금 넘겨줄 값과 같아야 해요. 다르면 `record`가 거부해요.
- 메모 사본은 사슬 파일 옆 `memos/visit-<N>-<slot 이름>.txt`에 저장해요. 배우 slot 안에는 저장하지 않아요. 배우는 자기 slot에 어떤 이름의 파일이든 만들 수 있어서, 같은 이름의 파일과 충돌할 수 있기 때문이에요(2026-11-24 실험이 이 충돌로 중단됨).
- 같은 slot을 두 번 기록하거나 이미 있는 메모 사본을 다른 내용으로 덮어쓰지 않아요.
- 넘겨줄 메모 파일이 기록 뒤에 바뀌었으면(SHA-256 불일치) 다음 방문 입력을 만들지 않아요.
- `memoStatus`는 `valid`, `missing`, `invalid`, `no-visit` 중 하나예요. 퀘스트 성패와는 다른 값이에요.

### 7. 예시: 3회 방문

**1회차 뒤**

```
[장보기 순서]
목록 보기 → 여기저기 걷기 → 냉장고 → 계산대
[기억나는 장면]
- 들어가니 과일만 보였다 → 왼쪽으로 갔다 → 벽이라 한참 헤맸다. 답답했다.
- 직원이 보였다 → 우유 어디냐고 물었다 → 오른쪽 끝이라고 했다.
[장소와 길]
- 우유: 오른쪽 끝 냉장고 (확실)
- 계산대: 입구 근처 (흐릿)
[다음엔]
- 들어가서 과일이 보이면 오른쪽 벽 쪽으로 간다.
```

**2회차 뒤** — 계획이 통했고, 계산대 위치가 틀렸어요.

```
[장보기 순서]
목록 보기 → 오른쪽 벽 따라 끝 냉장고 → 계산대
[기억나는 장면]
- (처음 왔을 때) 왼쪽으로 갔다가 벽이라 헤맸다.
- (이번) 계산대가 입구 옆인 줄 알았는데 없어서 당황했다 → 안쪽 왼편에 있었다.
[장소와 길]
- 우유: 오른쪽 벽 끝 냉장고 (확실)
- 계산대: 안쪽 왼편 (확실, 전엔 입구 옆인 줄 알았음)
- 빵: 냉장고 가는 길 중간 (흐릿)
[다음엔]
- 우유를 담으면 왼쪽 안쪽으로 가서 계산대를 찾는다.
[어느 마트에서나]
- 모르면 직원에게 묻는 게 빠르다.
```

- "오른쪽 벽으로 간다"는 잘돼서 `[장보기 순서]`로 옮겼어요.
- 직원 장면은 교훈이 `[어느 마트에서나]`로 옮겨 가서 지웠어요.
- 계산대는 이번에 직접 보고 고쳤으니 (확실)이에요.

**3회차 뒤** — 같은 매장인데 매대가 바뀌었어요(페르소나는 미리 몰랐어요).

```
[장보기 순서]
목록 보기 → 오른쪽 벽 따라가며 둘러보기 → 우유 → 안쪽 왼편 계산대
[기억나는 장면]
- (이번) 늘 가던 냉장고에 우유가 없었다 → 옆 칸을 보니 있었다. 배치가 바뀐 것 같다.
- (처음 왔을 때) 왼쪽으로 갔다가 벽이라 헤맸다.
[장소와 길]
- 우유: 오른쪽 벽 냉장고 중 가운데 칸 (확실, 전엔 끝 칸이었음)
- 계산대: 안쪽 왼편 (확실)
[다음엔]
- 늘 있던 자리에 없으면 바로 옆 칸부터 본다.
[어느 마트에서나]
- 모르면 직원에게 묻는 게 빠르다.
```

- 빵은 이번에 안 가서 (흐릿)인 채로 있다가 지웠어요. 페르소나가 정한 망각이에요.
- 계산대 계획은 통해서 `[장보기 순서]`로 들어갔어요.

### 8. 분석할 때 비교할 것

메모는 매번 다시 쓰이므로 N−1과 N을 나란히 놓고 봐요.

- 항목별로 유지, 수정, 추가, 삭제된 것과 확실도가 바뀐 것
- `[다음엔]` 계획이 trace에서 실행됐는지, 그 뒤 `[장보기 순서]`로 옮겨졌는지
- 장면이 지식 칸으로 옮겨진 횟수
- 바뀐 배치를 메모에서 바로잡기까지 걸린 방문 수
- 규칙 위반: 가지 않은 곳의 확실도가 오른 경우, 경험에 없는 내용이 생긴 경우. 이건 사람이 검토해요.

## 실험할 때 볼 것

- **공간 지식의 변화:** 방문이 쌓이며 `[장소와 길]`이 랜드마크 → 경로 → 전체 배치로 바뀌는지 봐요. 지적장애 페르소나가 경로 수준에 머무는 것은 Courbois 연구와 맞는 결과일 수 있어요.
- **다짐 실행:** `[다음엔]`의 조건 상황이 실제로 화면에 나왔을 때 그 행동을 했는지 trace와 대조해요.
- **틀린 메모 대처:** 위치가 틀린 메모를 넣은 조건에서, 페르소나가 화면과 대조해 메모를 고치는지 봐요.
- **대조군:** 같은 페르소나로 메모 없이 여러 번 플레이한 조건과 비교해요. 이게 없으면 향상이 우연인지 구분할 수 없어요.
- **습득과 일반화 구분:** 같은 마트 재방문의 향상과, 다른 마트에서 `[어느 마트에서나]`가 쓰이는지를 따로 봐요.
