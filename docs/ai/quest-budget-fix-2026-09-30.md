# 추천 퀘스트 예산 오류 수정 — 2026-09-30

## 확인된 원인

직접 플레이 재시험은 분석과 프로필 갱신까지 READY였으나, 추천 생성은 상품 합계 8,600원에 예산 6,000원, 재시도에도 8,000원을 제시해 실패했다.

1. 생성 프롬프트에는 전체 상품 카탈로그와 예산 범위가 이미 있었다. 가격 데이터가 없었던 것은 아니다. 다만 전체 카탈로그가 압축된 표로 전달되고, 상품별 단가를 명확하게 찾는 별도 숫자 사전과 계산 순서 안내는 없었다. 이것이 단독 원인이라고 실험적으로 입증한 것은 아니다.
2. 코드가 합계를 계산해 검증했지만, 실패 시 모델에는 “AI 장보기 퀘스트 검증 실패: 예산”만 전달했다. 모델이 직전에 선택한 상품의 합계·단가·수량·허용 범위를 받지 못했다.
3. 감사 기록도 INVALID_AI_QUEST로만 남아, 구체적인 원인을 확인하려면 원문과 가격을 다시 대조해야 했다.
4. 검증 자체는 정상이다. 필수 상품보다 적은 예산은 수행 불가능한 과제이므로 통과시키면 안 된다.

## 변경

- 프롬프트 v8: 상품 ID → 단가 `unitPriceWon` 사전을 표 인코딩 밖에 명시했다. 상품 선택 → 단가×수량 합산 → 예산 선택 → 안내 문장 금액 일치 순서를 안내한다. “예산 압박”도 구매 불가능한 예산을 뜻하지 않는다고 명시했다.
- 예산 검증 오류에 `submittedBudget`, `objectiveTotal`, `minimumBudget`, `maximumBudget`, 상품별 `lineItems`를 담는다. 숫자는 실제 카탈로그와 AI가 제출한 유효한 상품·수량으로 계산한다.
- 고정 시나리오 계약 오류도 정확한 요구 예산과 목표 목록을 전달한다.
- 재시도에서 위 정보를 모델에 전달한다. 상품이나 수량을 바꾸면 합계를 다시 계산하고, 모든 안내 문장의 예산을 함께 수정하도록 요청한다.
- 감사 기록에 `validationDetails`를 추가했다. 기존 3필드 기록도 읽을 수 있다. DB 스키마 변경은 없고 기존 JSONB 기록 형식을 확장한다.
- 캐시 버전을 바꿔 이전 프롬프트의 추천을 재사용하지 않는다.

서버가 예산을 임의로 올리거나 상품을 대체하지 않는다. 상품·수량·난도·예산 선택과 교육적 판단은 AI가 맡고, 서버는 기존 콘텐츠의 가격 계산 및 실행 가능성만 검증한다. 룰 기반 대체 퀘스트도 만들지 않는다. 최대 2회 생성 제한과 기존 예산 허용 범위는 유지한다.

## 검증 결과

### 실제 모델의 실패 수정 시험

저장된 동일 프로필과 실제 실패 출력 두 개를 사용했다. 첫 출력은 기록된 실패 사례를 넣고, 수정 응답만 학교 Qwen 모델에 새로 요청했다. 새로운 플레이나 재분석은 아니다.

| 실패 사례 | 상품 합계 | AI가 새로 선택한 예산 | 결과 |
|---|---:|---:|---|
| 기존 6,000원 예산 | 8,600원 | 10,000원 | 통과 |
| 기존 8,000원 예산 | 8,600원 | 8,600원 | 통과 |

두 경우 모두 상품 선택은 우유·바나나·카레로 유지됐고, 안내 문장의 합계와 예산도 실제 숫자와 일치했다.

### 수정된 로컬 API의 신규 추천

로컬 격리 테스트 백엔드를 재시작해 적용했다. 같은 실제 프로필로 요청했으며 HTTP 200, source=AI, v8, 첫 시도 성공이었다. 약 24.08초(서버 기록 23.785초).

- 우유 900mL 1개: 2,200원
- 바나나 1송이: 3,600원
- 생수 500mL 1개: 800원
- 합계 6,600원, AI 선택 예산 7,500원
- 목표 품목 3개/난이도 2 유지

### 자동 회귀 검사

실제 두 실패 출력의 검증, 수량별 합계 재계산, 허용 범위 경계, 고정 시나리오 예산, 재시도 피드백, 기존 감사 JSON 읽기, 분석→추천 연결 관련 테스트를 실행했다. 최종 46개 테스트 통과, 실패·오류 0개.

## 적용 범위와 남은 한계

- 적용: 프로젝트 코드와 로컬 테스트 백엔드 18080. 격리 DB의 신규 추천 감사 기록도 확인했다.
- 학교 추론 서버의 모델/게이트웨이/방화벽 변경이나 본학습은 하지 않았다. 팀원 백엔드는 수정 코드 반영 및 재시작이 필요하다.
- 실제 모델은 실패 수정 2건과 신규 생성 1건만 확인했다. 다른 상품 조합에서 재발하지 않는다는 보장은 아니다.
- 자연어 규격/금액 설명을 전부 의미적으로 검증하는 기능은 이번 수정 범위에 포함되지 않는다.
- “규격 선택이 개선됐다”, 난도 증가의 적절성, 실제 사용자의 교육 효과는 이번 예산 검증으로 입증되지 않는다. 신규 결과는 이전 여러 실험이 있는 계정의 누적 프로필을 사용한다.
- 로컬 자동 분석 작업자는 기존처럼 꺼진 상태다. 이번 작업은 추천 API의 실패를 수정한 것이며 자동 분석 큐 설정은 변경하지 않았다.
