# 게임·공식 자료 검색 v1

2026-10-24. `KnowledgeRetrieval`은 원본 JSON에 나타난 사건·상태 키워드와 자료 주제의 겹침으로 두 컬렉션을 검색한다. 임베딩 모델이나 외부 벡터 DB를 쓰지 않는 로컬 주제 검색 RAG다. 검색 자체의 AI 호출은 없다.

- 코퍼스: `backend/src/main/resources/ai/retrieval-knowledge.json`. 게임 설명 5개, 공식 출처 요약 4개(AAIDD 2페이지와 W3C 1문서). 독립 연구 4편을 뜻하지 않는다.
- 검색: 컬렉션별 상위 3개, 동점은 문서 ID 순서. 원본에 나타난 주제만 선택하고 일반 원칙은 core 주제로 선택한다. 점수는 관련 주제 수이며 근거 신뢰도/학습자 점수가 아니다.
- 원본 로그는 검색 대상으로 대체하거나 삭제하지 않는다. 기존 관찰 구간 처리, 원본 보존, 사건 인용 검사와 세션 집계는 유지한다.
- 종합 분석(전체 원본/구간 종합 경로), 독립 검토로 전달되는 원본 프롬프트, 누적 프로필에 `retrievedKnowledge`를 포함한다. 구간별 관찰에 문헌을 반복 첨부하지 않는다.
- 문헌은 지원 제안의 참고이며 개인의 이해·동기·능력 근거가 아니다. 게임 설명보다 플레이 당시 snapshot/행동이 우선한다. 실제로 제공되지 않은 기능이나 지원 효과를 약속하지 않는다.
- 검색 기록: 코퍼스 버전·SHA-256, 관련 주제, 자료별 ID/출처/확인일/적용 한계/검색 점수. 모델 요청 원문에 보관한다. 검색됐다는 사실과 모델이 사용했다는 사실은 구분한다.
- 새 문서 ID는 기존 `usedEvidenceCardIds` 또는 사건 ID가 아니다. 필요할 때 지원 제안 본문의 `[문서ID]`로 구분한다. 현재 버전은 별도 구조화된 사용 인용 검증을 추가하지 않았으므로 결과의 실제 출처 사용은 비교 보고서에서 확인한다.
- 공식 자료 원문을 복제하거나 학습시키지 않는다. 출처 링크와 짧은 자체 요약을 제공한다. AAIDD 설명/공동 입장문과 W3C Working Group Note의 성격·한계를 보존한다. 임상 검증이나 기관 승인을 뜻하지 않는다.
- 게임 자료 변경 시 근거 파일·함수와 sourceSha256을 대조해 요약을 갱신하고 코퍼스 버전을 올린다. 이전 게임 버전은 당시 로그를 우선한다.

- 원본 해시·관찰 전체 범위와 결과 인용의 유효성은 내용 품질 전체를 보장하지 않는다. 근거 없는 원인 가설, 행동 설명 생략, 반복 추천·미지원 기능 제안은 별도 수동 검토 대상으로 남긴다.

## v108 상세 추천과 시간 검증 (2026-10-25)

- `PracticeDesignContract`는 다음 목표의 실제 상품 식별자·정확한 수량/단위, 플레이어 안내 순서와 달성 기준을 요구한다. 기존 `practicePlan` API 필드는 유지하고 `rationale`의 변경/안내/달성/확인 항목에 구체 조건을 담는다. 상품·수량·지원의 선택은 계속 모델이 한다. 이 형식 검사는 교육 효과나 내용 전체의 정답 판정이 아니다.
- `PriorAiPlanText`는 `mission`/`missionSnapshot.observationPlan`의 과거 AI 보고/가설 5개 필드만 현재 모델 요청에서 제외한다. 원본 파일은 그대로 보존하고 제외한 경로와 JSON 값 SHA-256을 기록한다. 실제 목표·제공된 브리핑/계산 안내·행동·좌표·원본 경험 보고·환경 설정은 제외하지 않는다. 원본 AI 계획 전송을 유지하는 퀘스트 생성 경로와 구별한다.
- 숫자 전송은 기존 정확한 숫자 접두/접미·열 인코딩을 최종 분석에도 적용한다. 관측 입력은 유리한 경우에만 십진수 델타 표현을 사용한다. 부동소수점 차분·반올림·좌표 샘플 생략을 하지 않고 디코딩한 모든 값과 순서를 대조한다. 인용 별칭과 읽기용 사건 순서 표는 유지한다.
- 원본 사실·판정·주체 검사와 별도 의미 검토를 유지한다. 기존 출력 형식 설명 중복만 줄인다.
- 지원 게이트웨이에서는 다음 연습 근거를 `change`, `instructions`, `successCriteria`, `nextObservation`의 네 필수 문자열로 생성한다. `ConcretePracticeSections`는 모델 문구를 변경하지 않고 기존 API의 문자열로 연결한다. 후행 JSON 쓰레기는 엄격히 거절한다. 실제 원본·성패·주체·의미 검사는 계속 별도로 실행한다.
- 정규식으로 네 항목을 한 문자열에 강제했던 v106에서 중첩 분석의 반복/잘림이 발생하여 정규식 제약을 제거했다. v107의 정상 활용 `엽니다` 오탐과 미래 안내 보정 실패는 v108에서 수정했다. 보정은 과거 행동을 추가할 수 없고, 지적된 미래 안내에 구현된 매대 열기 단계를 추가하는 것만 허용한다. `각각 1개`처럼 명시적인 공통 구매 수량도 인정한다.
- 프로필에 회원·세션 범위를 확인한 현재 목표 상품의 원본 규격·단위·가격·초기 재고를 제공한다. 초기 재고는 나중의 재고나 구매 가능성을 증명하지 않는다. 숫자 압축 후에도 원본으로 정확히 복원되는지 검사하고, 토큰 예산 검사는 네트워크 기능 조회보다 먼저 수행한다.
- 최종 비교 폴더: `output/concrete-sections-nine-20261025`. v108/프로필v53으로 같은 9건/16,102개 과거 합성 이벤트를 처음부터 실행한다. 기준은 보존된 v104/프로필v49 9건이다. v105/v106/v107 초기 시도와 실패 비용은 별도 보존하며 최종 9건으로 섞지 않는다. 새 플레이·학습 효과로 세지 않는다. 캐시 없는 실제 AI 완료 전에는 시간/추천 품질 향상을 확정하지 않는다. 런타임 입력 배치 1024→2048도 함께 바뀌므로 차이를 RAG 단독 효과로 해석하지 않는다.

## v2 검색: 게임별 선별과 사건 비중 (2026-11-15)

- 코퍼스 `dual-knowledge-20261115-v2`, 검색 `dual-rag-v2-game-prominence`. 카드 본문은 v1과 같다. 바뀐 것은 고르는 방식과 보내는 필드다.
- `games` 항목이 게임별 표식(`markers`)과 주제별 사건 이름(`topicEvents`)을 가진다. 게임 카드는 `game` 값이 원본에서 확인된 게임과 같을 때만 후보가 된다. 새 게임은 이 항목과 카드만 추가한다.
- 주제 가중치는 `1 + (그 주제 사건 수 / 전체 주제 사건 수)`이고 일반 원칙(`core`)은 0.5다. 사건 이름은 전체 이름 단위로 센다(`MOVEMENT_BLOCKED`가 `MOVEMENT_BLOCKED_REPEATEDLY`에 함께 세어지지 않는다). 가중치는 기록에 그 행동이 얼마나 많이 나왔는지일 뿐 성패·능력·난이도 판단이 아니다.
- 컬렉션별 상위 2개(이전 3개), 동점은 문서 ID 순. 모델에는 `id, title, source, summary, limitations`만 보낸다. 확인일·해시·주제는 코퍼스 버전과 SHA-256으로 추적한다.
- 같은 9건 비교(`output/analysis-efficiency-20261115`, 문맥 32768): 요청에 실린 카드 묶음이 4종 → 10종, 요청당 카드 분량 평균 3,398자 → 2,052자. 분석 시간·토큰은 차이가 없었다(양쪽 성공 7건 기준 AI 시간 +1.6%, 입력 토큰 −0.1%; 같은 코드 반복 측정의 흔들림이 ±18%다).
- 인용 0회의 이유: 종합 분석 출력 형식의 `c`(usedEvidenceCardIds)는 기존 `EvidenceIndex` 카드용이고 구간 종합 경로에서는 빈 배열만 허용한다. 검색 문서 ID(`G-…`, `O-…`)를 적을 칸이 분석 출력에는 없다. 분석 쪽 사용 기록은 여전히 구조화되어 있지 않다.
- 퀘스트 생성에는 `observationPlan.knowledgeIds`(선택 항목, 0~4개)를 추가했다. 설계·생성 요청에 같은 검색 결과를 넣고, 모델이 실제로 적용했다고 적은 문서 ID만 남긴다. 제공하지 않은 ID는 기록에서 제외한다. 검토 요청에는 넣지 않는다. 적었다는 사실은 모델의 보고이며 효과 검증이 아니다.
