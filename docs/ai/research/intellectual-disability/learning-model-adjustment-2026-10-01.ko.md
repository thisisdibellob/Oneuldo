## 적용된 실행 경로

1. **새 조건 초기화:** 민재 v2로 별도 실행 폴더를 만든다. 최초 연상은 빈 배열이다. 기존 v1 경험을 가져와 이미 학습한 상태로 시작하지 않는다.
2. **현재 관찰:** 실제 화면에서 읽은 안내·목록·상품·피드백만 기록한다. 스크린샷/접근성 텍스트의 경로와 SHA-256, 실제 시각, sessionId를 연결한다. 파일 일치는 내용의 진실성이나 이해를 증명하지 않으므로 UI와 기록을 대조한다.
3. **경험 부호화:** 배우가 지금 경험에서 남길 연상을 선택한다. 이전의 자신의 연상과 방금 관찰한 회차만 볼 수 있다. 정답 전략을 분석기나 코드가 대신 써 주지 않는다. 아무 연상을 남기지 않는 것도 허용한다.
4. **회상:** 현재 화면 단서와 자신의 연상에서 무엇이 떠오르는지 배우가 고른다. 틀린 숫자·부분적 기억·회상 없음도 형식상 유효하다. 코드는 원본의 정확한 문장으로 회상을 고치지 않는다.
5. **행동:** 현재 UI와 선택된 회상만으로 AI가 다음 동작을 고른다. 목록 재확인·도움 요청·다시 시도도 가능하다. 실행하지 않은 계획, 기술 오류, 화면에 없던 피드백은 학습 경험에 넣지 않는다.
6. **학습 확인:** 분석/추천 AI가 실제 수행과 지원을 보고 다음 안내나 과제를 고른다. 판정과 평가 조건은 배우 입력에 넣지 않는다. 실제 앱에 표시된 추천 안내만 배우가 본다. 실패 뒤 반복할지 단계를 나눌지는 AI 판단이며 성공 횟수에 따른 자동 승격은 없다.

처음의 용량·묶음 단위 어려움과 우유/바나나 취향은 **민재 개인의 가상 사례 설정**이다. 어느 논문에서 관찰된 모든 성인의 행동을 복제한 것이 아니다. 글 읽기·조작 강점, 자율적 도움 요청도 유지한다. 배우는 계속 Codex이며 학교 Qwen을 행동자로 바꾸지 않았다.

## 연습과 학습 확인을 나누는 방법

| 감사 조건 | 실제 진행 | 해석 범위 |
|---|---|---|
| `acquisition` | 목표 능력을 연습. 필요에 따라 현재 앱의 텍스트 안내, 목록, 비교 예시, 실제 피드백을 사용 | 도움을 받으며 수행할 수 있는지 |
| `independent-probe` | 같은 요구를 유지하고 추가 정답 단서를 줄여 확인. 목표 목록은 계속 이용 가능 | 지원 기록을 대조한 독립 수행. 조건 이름만으로 독립 성공을 인정하지 않음 |
| `maintenance-probe` | 실제 시간 간격 뒤 확인. 이전 관찰과 이번 관찰의 실제 간격을 기록 | 그 간격에서 유지됐는지. 몇 분의 간격을 며칠 뒤 유지로 보고하지 않음 |
| `transfer-probe` | 새 상품·표기·단위·순서·배치 중 무엇을 바꿨는지 남김 | 확인한 변화 범위의 적용. 우유 용량 성공을 바나나 묶음 학습으로 자동 확대하지 않음 |

도움은 `task-list / general-instruction / specific-cue / worked-example / corrective-feedback`로 구별하고, `displayed / opened / followed-in-action`을 따로 적는다. 이 분류는 앱의 관찰을 위한 자체 기록 체계이며 논문의 촉진 척도를 그대로 재현한 것이 아니다. 실제로 못 제공하는 영상·음성·몸을 잡아 주는 촉진은 했다고 기록하지 않는다. 속도는 도구 처리시간과 분리해서 보고하고 느림을 곧 능력 부족으로 판정하지 않는다.

## 검증과 기존 결과의 처리

구조 검증에서는 원본 에피소드/분석 필드가 행동 입력에 누출되지 않는지, AI가 틀리게 회상했을 때 정확한 원본으로 덮어쓰지 않는지, 반복만으로 자동 상승이 생기지 않는지, 다른 능력/개인/조건의 기록을 섞지 않는지 확인했다. 화면 파일의 해시와 관찰 시각이 바뀐 경우 예전 회상 입력도 거부한다. 자연어 내용의 의미까지 검사한 결과는 아니다.

검증 결과: 새 구조 8건 + 기존 직접 경험 3건 + 기존 AI 경험 경로 10건, **21건 통과**. TypeScript 타입 검사와 `git diff --check`도 통과했다. CLI 시험에서 실제 파일 바이트 변경을 감지했고 기존 v1 파일을 새 조건으로 조용히 변환하지 않는 것을 확인했다. `output/minjae-research-v2-001`에 빈 기억과 구현/출처 해시를 가진 새 조건을 초기화했다. 원본 검증 기록은 해당 폴더의 `verification.json`이다.

기존 `quest-loop-10x10-20261001` 결과는 v1 조건의 부분 실험으로 보존한다. 새 조건의 실험으로 합치거나 100회 완료로 표시하지 않는다. 이번 변경의 테스트는 **구조와 기록 경계의 검증**이며, v2 플레이 반복이나 실제 참여자의 교육 효과 검증을 완료한 것이 아니다. 다음 플레이부터 별도 v2 조건에서 시작하며, 학습 효과는 실제 수행 결과를 보고 다시 판단해야 한다.
