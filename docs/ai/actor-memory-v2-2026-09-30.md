# 관찰·작업 기억 보존과 동작 피드백 개선 — v2–v4 비교 시험

## 수정 내용

이전에는 확률 정책을 제거하면서 AI가 행동을 이어 가는 데 필요한 관찰 기억을 충분히 전달하지 못했다. 이번 변경은 행동 판단을 AI에 두고 관찰 기록 전달을 복구하는 작업이다.

- 시작 안내와 마지막으로 읽은 목록을 최근 행동 6개와 분리해 보관한다. 시작 안내의 `900mL`, `1송이`가 행동 기록에서 밀려 사라지던 문제를 줄인다.
- 내부에만 있던 발견 장소·상품·통로를 AI 입력에 포함한다. 이동 성공 때 실제 이동 연결과 방문 횟수를 갱신한다. 관찰하지 않은 지도를 가져오거나 상품 위치를 추론해 입력하지 않는다.
- 위치 단서가 언제 어디서 보였는지 현재 통로와 연결하고, 당시 방향을 현재 방향으로 오인하지 않도록 설명한다.
- AI가 정한 짧은 현재 작업 `currentTask`를 다음 요청의 `actorChosenTask`로 전달한다. 코드가 올바른 목표를 정하거나 달성했다고 판정하지 않는다.
- 프롬프트의 목록 읽기 설명을 수정해, 화면에서 목록이 사라져도 관찰 기록은 남아 있음을 명시한다. 목록 재확인을 금지하지 않는다.
- trace 생성 버전을 `episodic-choice-v2`로 구분한다. 기존 v1 trace를 읽는 계약은 유지한다.

## 학습 해석의 범위

이번 수정은 같은 과제 안에서의 관찰·작업 연속성을 확보하는 것이다. 모델의 가중치를 학습시키지 않았고 인간의 기억 용량·망각을 보정하지 않았다. 기록 보존은 실제 이해나 습득을 의미하지 않는다. 회차 간 전달은 기존의 실행 확인 경험 경로를 유지하며, 새 회차에는 과거 목표를 현재 정답처럼 복사하지 않는다.

## 자동 검증

- 읽지 않은 목록이나 숨은 정답을 주입하지 않는다.
- 읽은 목록·안내는 8개 후속 행동 뒤에도 남는다.
- 실제 성공한 이동만 방문 횟수와 이동 연결에 기록한다.
- 모델이 선택한 현재 작업이 다음 실제 요청에 포함된다.
- 다음 회차는 현재 회차 목표·작업 상태를 새로 시작한다.
- 확률 정책의 행동 선택을 AI 경로에서 사용하지 않는다.

## 실제 서버 비교 조건

직전 재시험과 같은 저장 snapshot, 인물 `mild-intellectual-disability-adult`, seed `actor-learning-v1`, 모델 `qwen3.6:27b-q4_K_M`, 30행동 상한을 사용했다. AI 모델에는 seed를 고정하지 않으므로 동일 조건이어도 결정론적 재현은 아니다. 기억과 프롬프트를 함께 바꿨으므로 개별 변경의 인과 효과를 분리한 실험은 아니다.

이 시험은 행동 계획 생성이다. 앱 재생 및 분석·추천 후 반복과 구분한다. 원본 요청/응답은 로컬 `output/actor-learning-20260930/memory-v2/`에 보존한다. 키와 인증 헤더는 저장하지 않는다.


## 첫 보완 시험에서 발견한 추가 문제

v2의 30행동 시험은 184.950초에 끝났으며 목록 6회·이동 11회·둘러보기 13회였다. 이전 목록 16회보다 줄었지만 새로운 제자리 둘러보기 반복이 생겨 전체 수행 개선으로 판정하지 않았다. 상품 선택과 앱 완료는 없었다.

원본 응답은 `Look around to identify nearby shelves or products`라고 설명했다. 그러나 해당 조작은 이동/카메라 회전 없이 기다리는 동작이다. 기존 모델 입력에는 행동 성공만 남아, 새로운 정보가 나타나지 않았다는 피드백이 부족했다.

이에 v3에서는 선택지에 실제 동작 효과를 명시하고, 대기 전후 관찰이 같은 경우에만 `Visible scene unchanged; no new location or product became visible`을 기록한다. 새 단서가 나타나면 이 문구를 기록하지 않는다. 모델의 행동을 강제로 바꾸거나 반복 조작을 금지하지 않는다. v1/v2 스키마 읽기 지원은 유지한다.


## 선택지의 관찰 이력 표시 (v4)

v3에서는 30회/198.637초, 목록 8회·이동 22회·둘러보기 0회였다. 제자리 대기는 없어졌으나 이동 목적지가 4곳에 집중됐다. 누적 이력이 있어도 모델이 이를 활용해 탐색한다고 볼 수 없었다.

v4에서는 각 이동 선택지 옆에 현재 방향·거리와 기록된 도착 횟수·현재 위치 여부를 함께 넣는다. 원래 관찰과 기억에 있던 내용을 선택지에 연결한 것이며 새로운 지도 정보를 주지 않는다. 선택지 순서와 행동 목록은 동일하고 이미 방문한 곳도 계속 선택할 수 있다. 이는 별도 해시 ID 목록을 교차 대조해야 하는 입력 부담을 줄이기 위한 변경이다. 최종 생성 버전은 `episodic-choice-v4`다.

**정보 누락과 기록 연결은 수정됐지만, 전체 수행 품질이 좋아졌다고 말할 수 없다.** 최종 목록 재확인은 16→11로 줄었으나 탐색 목적지는 14→4로 줄고 생성 시간은 약 2분 8초→3분 24초로 늘었다. 단일 표본씩이며 여러 입력 변경을 함께 적용했으므로 이 차이의 원인을 하나로 확정할 수 없다.

최종 v4의 요청 27에는 선택한 통로의 `recordedArrivals: 7`이 있었다. 응답은 `explore new areas`라고 설명하면서 그 통로를 다시 선택했다. 이것은 기록이 없던 사례와 구분해야 한다. 출력 설명은 모델이 생성한 문장이므로 실제 심리 상태를 입증하지 않지만, 제공한 방문 이력·설명·선택 사이의 불일치는 확인된다.

## 다음에 분리해서 확인할 문제

1. 동일한 관찰과 선택지에서 페르소나 지시가 있는 조건/없는 조건을 비교해 기본 탐색 수행과 페르소나 설정 영향을 분리한다.
2. 간단한 실제 관찰 기록을 주었을 때 방문 이력과 행동을 일치시킬 수 있는지 확인한다. 목록 재확인을 금지하거나 새로운 길을 코드로 대신 고르면 검증 목적이 바뀐다.
3. 기본 수행을 확보한 다음 실제 앱 재생과 분석·추천 반복을 진행한다. 현재 실패로 분석 AI나 추천 퀘스트의 교육 효과를 판단할 수 없다.

운영 모델·서버 설정을 교체하거나 배포하지 않았다. 수정 대상은 로컬 가상 행위자와 공용 trace 메타데이터 계약이다.
