## 비교 설계

기존 단일 경로 전후 비교를 중단하고, 분석 AI를 사용하는 맞춤 조건과 사용하지 않는 일반 조건으로 비교한다. 이전 실험 결과는 새 표본에 넣지 않는다.

- 새 일반 계정과 새 맞춤 계정을 격리 DB `oneuldo_pilot_20260929`에 생성했다. 과거 행동·분석·프로필은 복사하지 않았다.
- 일반 조건: S01 → S02 → S01의 사전 지정 일반 과제 3회. 분석 API를 호출하거나 분석 결과를 행위자에게 제공하지 않는다.
- 맞춤 조건: S01 → 첫 실제 분석·프로필에 연결된 AI 추천 → 두 번째 실제 분석·프로필에 연결된 AI 추천. 실패 시 일반 fallback을 맞춤 과제로 계산하지 않는다.
- 공통 최종 평가: 두 조건 모두 S03(달걀 1팩·소시지 1팩, 예산 10,000원), 같은 배치 seed `pilot-round-2`. 추천과 별개의 공통 과제로 비교한다.
- 행위자: 동일한 assistant가 직접 화면을 읽고 선택. 이전에 요청한 지민 페르소나를 사용하고 확률 정책·27B 행동 생성·강제로 설정한 실패/향상률은 사용하지 않는다.
- 성공하도록 로그를 생성하지 않고 실제 UI가 전송한 로그와 DB 수신 순번을 대조한다. 구매 규격·수량·예산의 관측값을 비교하며 인지 능력을 코드로 판정하지 않는다.
- 기록: `output/ai-vs-general-20260930/`. 비공개 계정 파일은 공유/커밋 금지.

## 중요한 비교 한계

동일 assistant의 대화 기억은 두 독립된 사람처럼 초기화되지 않는다. 과거 매장 조작 경험과 조건 간 정보가 내부 기억에 남는다. 계정·프로필 분리는 이 모델 기억의 분리를 보장하지 않는다. 첫 실행부터 기본 목록을 정확히 수행하면 정확도 향상의 천장 효과가 생긴다. 단일 가상 사용자 쌍은 통계적·임상적 효과 검증 표본이 아니다.

일반 과제에도 기존 브리핑·규격 비교 안내·장바구니 기능이 있다. 따라서 ‘지원 없음’이 아니라 ‘기본 지원 vs 분석 기반 개인화’ 비교다. 과제 시간이 다른 것은 난도·호출 묶음·도구 지연 영향도 있으므로 주효과는 공통 평가의 실제 구매·도움 사용으로 비교한다.

1. **규격 안내 누락 재현**: 새 추천은 우유·생수의 용량을 브리핑에 쓰지 않았다. UI 상단 목록에도 용량이 없어, 숨은 productId의 요구와 사용자가 읽을 수 있는 요구가 달라질 수 있다. 이전 추천에서는 900mL/500mL를 썼으므로 매번 안정적으로 명시되는 상태가 아니다. 플레이 시 과거 정답 기억으로 누락을 메우면 추천 품질 문제를 가리게 된다.
