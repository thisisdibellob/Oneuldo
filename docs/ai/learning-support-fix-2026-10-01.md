# 경험·선택지·도움 단계·누적 이력 보완과 분석 3회

2026-10-01. 행동자는 사용자가 요청한 Codex 어시스턴트 역할을 유지한다. 학교 Qwen3.6 27B Q4_K_M는 분석에만 호출했다.

## 이번 실행의 범위

새 플레이는 하지 않았다. 기존 실제 앱 로그 세 묶음의 저장된 전처리 자료를 재사용하고, 수정한 최종 검토 지침으로 분석 모델을 새로 **3회** 호출했다. 출력 상한 2400토큰, 온도 0.1이다. 응답을 고쳐 쓰거나 정해진 실패·성공 순서를 모델에 지시하지 않았다. 표의 기준 정오는 저장된 목표와 실제 제출 장바구니를 사람이 대조한 평가 기준이다.

새 누적 프로필 갱신·추천 퀘스트 생성·추천 과제 플레이는 실행하지 않았다. 따라서 아래 결과는 분석과 연습 계획의 점검이며, 변경한 추천 안내가 실제 플레이에서 구현됐거나 학습 효과가 생겼다는 검증은 아니다.

## 적용한 네 가지

1. **배우의 경험과 잠정 전략을 분리했다.** 직접 플레이용 `AssistantExperience`는 실제 실행 에피소드, sessionId, UI 관찰 파일 참조를 보관한다. 전략은 배우가 생각했을 때만 관련 에피소드와 함께 `tentative-strategy`로 기록한다. 빈 전략 배열도 허용한다. 반복 회차·성공 여부로 숙달 점수나 정답 전략을 자동 생성하지 않는다. 분석 원문과 사후 정답은 배우 맥락에 넣지 않는다. 구조 검사는 참조·형식만 검사하므로 실제 UI 관찰과 내용 일치는 별도로 확인해야 한다. 이번에는 플레이가 없어 새 경험을 만들어 넣지 않았다.
2. **규격이 비슷한 선택지를 실제 진열대에 보존한다.** 같은 종류·맛·브랜드의 다른 용량·포장 단위는 한 품목 CUSTOM에도 남긴다. 우유에는 200mL/900mL/1.8L, 바나나에는 송이/낱개, 순한 카레에는 4인분/1인분, 오렌지 주스에는 1L/250mL가 포함된다. 허용된 대체품을 오답으로 바꾸지 않으며 목표도 변경하지 않는다. 실제 화면의 12슬롯 구성과 6슬롯 미리보기를 함께 검사했다. 이전 플레이 원본의 제공 목록은 수정하지 않았다.
3. **AI가 도움 단계를 고르게 했다.** 연습 계획의 기존 `reasonCodes`와 `textSupport`를 사용한다. `GUIDED_PRACTICE/SIMPLIFIED`는 구체적 비교·수정 안내, `SUPPORT_FADING/STANDARD`는 같은 요구에서 짧은 절차 힌트, `INDEPENDENT_PROBE/REDUCED`는 목표 목록을 유지한 중립적 안내다. 성공 횟수로 자동 승급하지 않는다. 도움을 줄일 때 품목·규격·수량·예산을 동시에 어렵게 바꾸지 않도록 지시한다. 퀘스트 생성 지침도 지원 수준별로 구분했고, 모든 AI 과제에 붙던 화면의 고정 비교 힌트는 중립적인 목록 안내로 바꿨다.
4. **이전 오류를 다시 확인할 맥락을 넓혔다.** 누적 프로필·추천이 받는 서로 다른 실제 플레이 원본을 최근 3회에서 최대 12회로 확대했다. 동일 세션의 재분석은 추가 플레이로 세지 않는다. 과제에서 빠진 품목은 해결 또는 새 품목으로 간주하지 않고 미재검사 상태를 finding 또는 uncertainties에 남기도록 지시한다. 과거 AI 판정과 원본 SKU·단위가 충돌하면 원본을 우선한다. 12회는 제한된 맥락이며 영구 이력 전체가 아니다. 모델이 누적 내용을 언제나 올바르게 유지한다는 보장은 아직 없다.

새 지침 버전은 분석 v30, 최종 검토 v22, 합성 v8, 프로필 v11, 추천 v14다. 출력 스키마·학교 게이트웨이·GPU 설정을 바꾸지 않고 로컬 개발 백엔드와 프론트 코드에 반영했다. 학교 운영 서버의 추론 모델이나 가중치는 교체하지 않았다.

## 추가로 발견해서 고친 참조 순서 문제

최초 검사에서는 첫 응답만 `REVIEW_EVIDENCE_OUT_OF_ORDER`로 거절됐다. 한 문장에 인용한 근거가 `[E1141,E2]`처럼 역순이었기 때문이다. 같은 문장에 붙인 근거 집합을 원본 사건 순서로 정리하도록 바꿨다. 인용한 ID·문장·판단은 그대로 두며 근거를 새로 붙이거나 삭제하지 않는다.

서로 다른 관찰 문장이 과거 사건으로 되돌아가는 경우, 존재하지 않는 ID, 중복 ID, 다른 필드의 참조는 계속 거절한다. 첫 실패 원문과 당시 상태는 보존했다. 같은 세 응답을 수정한 검사기로 **오프라인 재검사**한 결과는 3/3 READY였고, 추가 모델 호출은 없었다. 이것은 사실성 검사의 합격률을 뜻하지 않는다.

## 남은 의미 품질 문제

- 성공 사례의 `textSupport=REDUCED`, `reasonCodes=INDEPENDENT_PROBE`와 달리 goal에는 “문자 지원(STANDARD)을 유지”라고 적었다. 구조화된 계획 값과 설명 문장의 불일치다. 추천 생성은 구조화된 지원 값을 따르도록 보완했으나 이번에는 새 퀘스트를 생성해 확인하지 않았다.
- 바나나 오류 사례의 uncertainties에는 “낱개가 송이와 물리적으로 같고 허용 목록이 누락됐을 수 있다”는 설명이 있다. 원본은 단위를 명시하므로 이 가설을 뒷받침하는 자료가 없다. 불확실성에도 근거 없는 이야기가 들어갈 수 있다.
- 첫 응답에는 “장바구니를 확인”·“규격을 구분하지 못한 것으로 보인다”라는 표현이 남았다. 실제 기록으로 확실한 것은 화면을 열고 다른 규격을 제출한 사실이다. 이해 과정 추론은 더 줄여야 한다.

이번 변경으로 선택지 제거에 따른 쉬워진 성공과 도움에 의존한 수행을 구분할 기반을 만들었지만, 이 세 분석만으로 능력 향상을 입증하지 않았다. 다음 실제 플레이에서는 같은 목표·선택지를 유지하고 AI가 고른 도움 수준만 바꿔 수행과 수정 행동을 비교해야 한다.
