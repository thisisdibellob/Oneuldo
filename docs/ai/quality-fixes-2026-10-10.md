### 개선 우선순위와 확인 방법

1. **P0 — 종료·제출과 목표 달성을 분리한다.** raw종료 값을 보존하면서 `COMPLETED`, `FLOW_FINISHED`, `EXIT_AFTER_SUBMISSION`는 흐름 상태임을 원본 의미 자료에 명시한다. AI가 각 목표의 허용SKU·수량·예산을 원문 참조와 함께 판정하고, 자기 개별 조건 판정과 전체SUCCESS가 모순되면 재검토/실패로 처리하는 일치 규약이 필요하다. 서버가 학습 능력 점수나 정답 판정을 새로 생성하는 방식은 아니다. `COMPLETED+오답`, `FLOW_FINISHED+오답`, 수정후정답 등 종료표기×구매조건 조합으로 다시 검사한다.
2. **P1 — 계획 문장까지 관찰·불확실성의 근거 경계를 적용한다.** practicePlan.rationale를 관찰된 차이, 원인 미확인, 제안할 연습으로 분리한다. “규격을 구분하지 못했다” 대신 “목표900mL와 선택200mL가 달랐다. 선택 이유는 확인되지 않았다. 다음에는 표기를 대조하는 절차를 연습한다”처럼 쓴다. 도움을 제공/열람/행동으로 사용한 기록을 구별하고, 열기1회만으로 의존·지원감소·독립숙달을 확정하지 않는다. 근거 ID추가만으로 의미 정확도가 보장되지는 않으므로 summary/findings/uncertainties/계획의 모순을 함께 확인한다.
3. **P1 — 상호작용 대상 종류를 원본에 명시한다.** 기록된 scene/registry에서 확인 가능한 door/shelf/checkout/staff를 위치값과 함께 제공한다. 원본에 종류가 없으면unknown이며 `SHELF_PROXIMITY`라는 범용 코드만으로 상품매대를 추측하지 않는다. 문 근접·상품매대 근접·매대 열기·상품선택을 따로 시험한다.
4. **P2 — 실제 제공 가능한 지원과 다음 난도의 비교 근거를 제한한다.** 문자안내/비교·수정알림/품목부담/매대순서 같은 현재 지원을 구조화하고, 미구현 시각강조는 향후 기능 제안으로 분리한다. 원본 난도/문자지원이 없으면 비교미확인으로 남긴다. 한 번의 성공이나 품목 수 감소를 독립 수행·개념 습득으로 바꾸지 않는다. 온도를 낮추는 것은 변동을 줄일 수 있지만 잘못된 기준을 안정적으로 반복할 수도 있어 주된 해결책이 아니다.

이 단계에서는 개선안을 적용하지 않았으며 확인된 실패를 그대로 보존했다. 결과: [두 실행 합동 감사](../../output/analysis-smoke-repeat-20261011/combined-quality-audit.json), [실제 요청 동일성](../../output/analysis-smoke-repeat-20261011/actual-request-equivalence.json), [이번 실패 검사](../../output/analysis-smoke-repeat-20261011/test-summary.json). 이번 기록은 지정 외장하드에 complete 상태로 16/16개 파일의 SHA-256 검증을 통과했다. 보관 스냅샷은 `50021689774e0cdf23e5eb556622aec7635431e733377f35f878cfe1d5721605`이며 [보관 확인서](../../output/.test-archives/analysis-smoke-repeat-20261011/50021689774e0cdf23e5eb556622aec7635431e733377f35f878cfe1d5721605.receipt.json)에 남겼다. complete는 기록 보관 상태이며 판정 품질 통과를 뜻하지 않는다. 로컬 원본을 보존했다.

원문: [추천](../../output/ai-quality-fixes-20261010/live-replay/timer-v26/recommended-quest.json), [후보·Review 감사](../../output/ai-quality-fixes-20261010/live-replay/timer-v26/quest-run.json), [운영자 내용 대조](../../output/ai-quality-fixes-20261010/live-replay/timer-v26/operator-quality-audit.json).

## 실제 AI 타이머 검증의 최초 실패

[최초 분석 원문](../../output/ai-quality-fixes-20261010/live-replay/timer/analysis.json)은 `FAILED / INVALID_AI_ANALYSIS`였어용. [감사 원문](../../output/ai-quality-fixes-20261010/live-replay/timer/analysis-run.json)에는 최초 작성 1회와 독립 Review 2회의 완결된 응답이 남아 있어용.

원본은 전용 기존 DB의 읽기 전용 트랜잭션으로 내보냈어용. 데이터셋·세션·원본 날짜·목표 존재·파일 SHA를 [내보내기 기록](../../output/ai-quality-fixes-20261010/live-replay/fixture-export-summary.json)에 보관했고 DB 변경·모델 호출·새 플레이는 이 내보내기 단계에서 0회였어용. 원본의 날짜 표현은 유지했고 ISO 표시는 별도 메타데이터에만 기록했어용.

일부 시작된 재생은 당시 빌드의 원본 읽기 자료 v7을 사용했을 수 있어용. 결과를 받을 때 실행 JAR SHA와 프롬프트·원본 자료 버전을 먼저 확인하고, 뒤의 변경까지 검증된 결과로 합치지 않아용. 최종 새 JAR의 결과는 Root가 원문을 대조한 뒤 이 표에 기록해용.

## 최종 갱신과 보관

최종 갱신 시에는 실제 분석·Review·프로필·추천 원문, 실행 JAR SHA·프롬프트 버전, 처음 시도와 재시도별 성패, 원본 요구·제출·도움·시간 대조 결과를 함께 기록해용. 구조 통과, 의미 일치, 전체 연결 완료를 구분하고 실패·조건부 생략도 그대로 보존해용.

로컬 기록은 `output/ai-quality-fixes-20261010/`에 유지하고 있어용. 외장하드 보관은 [테스트 기록 보관 절차](test-record-storage.md)에 따라 Root가 전체 기록을 마무리한 뒤 수행해용. **현재 이 보고서는 외장하드 보관 완료를 주장하지 않아용.** 최종 확인에는 디스크 UUID·마운트·전송 후 SHA 검증과 실제 보관 경로·확인서를 추가해야 해용.
