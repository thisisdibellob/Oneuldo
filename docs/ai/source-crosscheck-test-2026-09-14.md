# 원본 사건 대조 개선 및 실제 모델 재시험

2026-09-14. 합성 사용자의 기존 장보기 2회차 기록을 재사용했다. 실제 장애 당사자의 학습 효과 검증 결과가 아니다.

## 변경

- `behavior-analysis-v20-source-crosscheck`: 원래 타임라인을 보존하면서 상품·수량·장바구니를 사건별 객체로 추가 제공한다. 실제 전송 단계에서 이 사본이 다시 표/사전으로 압축되지 않도록 한다. 직접 분석·전체 원본 분석·구간 관찰 모두 적용한다.
- `synthesis-v4-source-crosscheck`: 최종 AI가 구간 요약과 원본 상호작용 값을 대조한다. 요약이 인용하지 않은 실제 사건도 최종 근거로 인용할 수 있다. 이벤트 발생 의미와 근거 없는 자동 기능을 가정하지 말라는 지시도 전달한다.
- `incremental-user-profile-v4-reanalysis`: 직전 프로필의 출처와 같은 세션인지 전달한다. 동일 플레이의 정정을 새 플레이나 교육 효과로 계산하지 않도록 지시한다. 프로필 근거에는 별도 `R` 번호를 쓰고 허용 목록을 제공해, 분석 문장에 남은 옛 `E` 번호와 구분한다.
- 성패, 사용자 능력, 지원 수준을 코드로 결정하는 규칙은 추가하지 않았다. 결과 형식과 실제 사건 ID 유효성은 계속 코드로 검증한다.

## 실제 모델 결과

노트북 서버의 `qwen3.6:27b-q4_K_M`를 HTTPS 게이트웨이로 호출했다. 컨텍스트 18,432, 요청 예산 18,000, 출력 상한 1,800을 유지했다. 실제 사용자 DB에는 테스트 결과를 저장하지 않았다.

| 시험 | 이전 | 수정 후 |
|---|---|---|
| 같은 153개 사건 구간 관찰 | 사과 선택 기록 없음 | 사과 수량 0→1→2, 장바구니 사과 2개를 정확히 확인 |
| 구간 관찰 시간 | 429.159초 | 366.180초 |
| 최종 분석: 잘못된 기존 요약 3개를 그대로 입력 | `UNDETERMINED` | 원본 값을 근거로 `SUCCESS` |
| 최종 분석 시간 | 273.664초 | 211.973초 |

최종 단계 첫 수정 시험도 `SUCCESS`였으며 260.085초 걸렸다. 근거 없는 자동 기능 설명이 남아 최종 지시를 보강하고 한 번 더 호출한 결과가 표의 211.973초다. 이미 통과한 구간 관찰은 전송 JSON 및 시스템 지시의 동일성을 검사한 뒤 재사용했다.

새 구간 관찰의 모델 보고 입력 토큰은 15,629개(이전 14,934개), 최신 최종 출력은 별도 원시 보고서에 보관한다. 입력을 늘렸지만 한 번의 실행 시간이 줄었다는 사실만으로 지속적인 성능 개선을 주장하지 않는다. 위 시간은 해당 단계의 호출 시간이며 **전체 318개 사건의 처음부터 끝까지 재분석 시간은 아니다.**

최신 최종 분석의 실제 요약:

> 사용자는 사과 2개와 생수 1개를 장바구니에 담고 결제를 완료했습니다. 초기 미션 확인 후 과일 선반에서 사과를, 음료 선반에서 생수를 선택했으며, 중간 이동과 대기 시간이 관찰되었습니다.

여기서 ‘결제 완료’는 모델의 표현이다. 원본으로 직접 확인되는 것은 게임의 장바구니와 제출 이벤트이며 실제 금전 결제를 검증한 것은 아니다.

## 남은 오류: 전체 의미 품질 통과로 보지 않음

- 자동 이동 이벤트인 `ITEM_SEARCH_STARTED`의 발생 의미를 전달했는데도 최종 결과가 자동 기록 여부를 불확실하다고 표현했다.
- 시선·미세 동작을 관찰하라는 지원을 제안했으나 게임이 그 정보를 측정하지 않는다.
- 문장에서는 다음 품목 수 3개를 제안하면서 구조화된 계획은 2개를 출력했다.
- 21초 대기를 과일과 음료 선반 사이 탐색으로 설명했다. 해당 대기는 생수 선택 이후에 기록돼, 단계 연결도 추가 검토가 필요하다.
- 구간 관찰에서도 자동 팝업·오류라는 근거 없는 대안이 남았다.

상품 선택 누락에 의한 핵심 오판은 재현 시험에서 개선됐다. 형식·근거 ID 검증 통과는 위 문장 오류까지 잡았다는 뜻이 아니다. 다음 개선에서는 AI가 지원 제안의 실행 가능성과 사건 순서를 명시적으로 재검토하는 검증 단계를 시험할 필요가 있다.

## 프로필 단계에서 추가로 발견한 참조 오류

첫 프로필 시험(v3)은 두 번 모두 `INVALID_USER_PROFILE`로 실패했다. 총 463.640초(7분 44초)이며 개별 호출은 256.490초, 207.133초였다.

원인은 본문에 남은 `E105`, `E257`, `E318` 등을 모델이 `evidenceEventIds`로 복사한 것이다. 프로필 요청은 UUID들을 새로 `E1`~`E11`로 별칭화했기 때문에 `E105` 등은 이번 요청의 유효 근거가 아니다. 내용의 옛 번호와 현재 구조화된 번호가 같은 접두사를 사용해 혼동을 유발했다. 허용되지 않은 번호는 서버 검증에서 거절됐으며, 검사를 우회하지 않았다.

v4는 프로필 전용 `R` 별칭과 허용 목록을 도입했다. 이전 단계 본문의 `E` 표기는 그대로 보존하되 인용에는 사용하지 않도록 명시한다. 회귀 테스트는 `R1`의 원래 UUID 복원과 옛 `E105`의 거절을 모두 검사한다. 또한 입력 이름을 `newSessionAnalysis`에서 `currentAnalysis`로 바꿔 같은 세션 정정을 새 플레이로 오해하지 않도록 했다.

v4 실제 시험은 **첫 호출에서 READY**, 모델 호출 132.963초, 서비스 처리 전체 133.530초였다. 사과 선택·수량 조정·제출의 실제 UUID 인용이 복원됐으며, ‘사과 선택 기록 없음/과일 선택 어려움’이라는 기존 해석이 새 프로필에 남지 않았다. 같은 플레이 정정을 새로운 학습 성과로 주장하는 문장도 나오지 않았다.

단, 프로필에도 자동 이동 이벤트에 대한 잘못된 불확실성과 ‘지원 문장 3품목 / 구조화 계획 2품목’의 불일치가 남았다. 최종 프로필의 난이도는 AI가 1, 품목 수는 2로 제안했다. 실행·근거 검증은 통과했지만 전체 의미 품질은 아직 개선이 필요하다.

최종 추가 검사 6개(원본 사본·실제 전송 동일성·프로필 근거 분리·동일 세션 구분·실제 프로필 호출)는 모두 통과했다. 앞의 분석 회귀 검사와 일부 중복이 있으므로 고유 테스트 수로 합산하지 않는다.

## 반영 상태와 원문 결과

- 현재 맥북의 백엔드를 새 코드로 재시작했다. 진행 중 분석 작업이 없는 상태에서 교체했으며 `/api/quest` HTTP 200, 합성 사용자 로그인 및 현재 프로필 조회를 확인했다.
- 기존 DB 프로필·분석은 보존했다. 화면의 과거 결과가 자동으로 새 결과로 바뀌지는 않으며 다음 분석 요청부터 새 코드가 적용된다. 노트북의 모델·게이트웨이 바이너리 변경은 필요하지 않았다.
- [분석·프로필 원문 결과와 호출별 시간](source-crosscheck-results-2026-09-14.json)을 별도로 보관한다. 실패한 두 프로필 응답도 포함하며 프롬프트 전체와 API 키는 포함하지 않는다. 격리된 테스트 결과의 새 UUID는 실제 DB 레코드 ID가 아니다.
- 이번에 새 퀘스트를 생성해서 3회차를 플레이하거나, 전체 구간 관찰부터 개인화까지 재실행하지는 않았다. 교육 효과 검증으로 해석할 수 없다.
