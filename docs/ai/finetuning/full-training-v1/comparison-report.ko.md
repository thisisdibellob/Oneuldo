# 첫 27B QLoRA 본학습·전후 평가 결과

작성: 2026-09-25 KST. **학습 실행은 성공했으나 품질 비교는 악화됐다. 이번 최종 어댑터는 운영에 적용하지 않는다.** 기존 Ollama 모델과 게이트웨이를 복구했고, 공개 HTTPS를 통한 인증 및 실제 AI 응답까지 확인했다.

## 실행 결과

- 학습 전 원본 평가 25건 완료. 이전 시도에서 생성한 결과를 재사용했다. 입력·프로토콜·추론 코드·결과 파일 해시와 실행 환경을 검사하고, 원본 E01을 재생성해 출력 토큰 전체가 일치함을 확인했다.
- 학습 예제 60개를 원본에서 새 LoRA로 초기화해 한 번씩 학습했다. 성공한 optimizer update 60회, 누락 0개, 수치 오류 재시도 0회다. 이전 실패 시도의 12회 갱신은 포함하지 않았다.
- 10/20/40/60스텝 어댑터를 서버에 저장했다. 최종 파일의 모든 텐서를 메모리 값과 비교하고 디스크에서 재적용한 뒤 다시 일치하는지 확인했다.
- 동일 평가 입력 25건을 최종 어댑터로 생성했다. 응답 수정·재생성·JSON 강제 없이 원문을 보존했다.
- 실제 프로젝트 파서와 세션/프로필 검증기로 전후 50건을 검사했다. `FinetuningMatchedComparisonTest`는 실제 활성화되어 실행됐으며 tests=1, skipped=0, failures=0이다. 이 테스트는 결과를 집계하는 도구이므로 테스트 성공이 모델 50건 통과를 뜻하지 않는다.

## 원문을 대조한 품질 결과

25건 모두 입력과 학습 전후 출력을 읽어 검토했다. `semantic-review.json`에는 인용문·근거·판단 이유를 각각 남겼다. 개발자의 정성 검토이며 독립 전문가 평가나 임상 검증은 아니다.

| 정성 검토 분류 | 학습 전 | 학습 후 |
|---|---:|---:|
| 명확한 내용/계약/기능 오류 확인 | 8 | 13 |
| 추가 검토가 필요한 해석·설명 | 11 | 6 |
| 주요 오류를 식별하지 못함 | 6 | 6 |

이 분류는 정확도 점수나 임상적 유효성 수치가 아니다. 개선과 퇴행이 함께 나타난 사례도 있어 단순히 오류 건수 차이를 개선률로 계산하지 않는다.

대표적인 퇴행:

- **E04: 존재하는 기록을 없다고 판단.** E2에는 양파3·생수2, 총액5100원이 명시돼 있고 예산6000원을 충족한다. 학습 후에는 “생수는 기록이 없다”고 하여 SUCCESS를 UNDETERMINED로 바꿨다.
- **E07: 세션별 목표 혼동.** S2의 실제 목표는 달걀1·우유1이고 제출도 일치한다. S1의 우유2 목표를 가져와 S2를 실패로 판단했다.
- **E11: 중간 장바구니를 완료로 판단.** 제출이 없는 두 장바구니 스냅샷 중 앞선 것만으로 성공을 확정했다. 원본은 성패를 유보했다.
- **E09: 잘못된 과거 분석 복사.** 부분 구간과 “피곤해 보일 수도”라는 보고만 있는데, “피로 때문에 과제를 하지 못했다”는 기존 요약을 사실처럼 복사했다.
- **E08/E21: 프로필의 중요한 정보 누락.** 같은 난이도를 원하는 사용자 보고의 근거가 빠졌고, 같은 플레이 파일의 재수집이라는 관계가 누락됐다. E21은 교육 효과를 직접 주장하지는 않았지만 독립 수행 횟수로 오해할 수 있게 됐다.
- **E03/E12/E14/E17: 필드 역할 약화.** 관찰 사실을 기술명·해석·지원·불확실성·다음 과제에 반복했다. 특히 E03은 반복 때문에 JSON을 끝내지 못했다.

개선 또는 유지된 부분:

- E02/E16: 근거 없이 특정 훈련이 필요하다고 단정하는 표현을 줄이고 관찰용 과제로 제안했다.
- E24: 아동 집단에 관한 잘못된 과거 문구로 34세 합성 사용자를 기억력이 낮은 유형으로 분류하던 내용을 제거했다.
- E10/E13: 서로 다른 목표 수량의 구분, 제출이 없는 단일 스냅샷의 성패 유보를 유지했다.
- E20: 제출 뒤 USER_ABORTED 종료를 실패로 판단하지 않았고, 인지·동기 추정도 줄었다.
- E06: S1 성공 판정을 바로잡았지만 S2 누락이 새로 생겼다. E01도 품목 수 설정은 고쳤지만 미기록을 미수행으로 단정했다. 이런 사례는 단순 개선으로 세지 않았다.

## 원인에 관해 확인한 것과 아직 모르는 것

메모리 부족이나 실행 중단은 이번 결과의 직접 원인이 아니다. 학습 60회가 완료됐고 손실·기울기 검사를 통과했다. 이전에 실패했던 T43도 재시도 없이 통과했다. 따라서 새 수치 오류 복구 로직은 GPU 단위 검사에서는 검증됐지만, 이번 실제 27B 실행에서 발동해 복구한 것은 아니다.

학습 예제의 문체 다양성은 낮다. 세션 예제 40개 중 34개는 finding이 1개였고, “장보기 수행과 근거 범위”라는 기술명이 34회 사용됐다. 39개는 지원 문장과 다음 과제 목표가 완전히 같다. 이 사실은 `training-style-audit.json`에 기록했다. 필드 간 반복을 모델이 강화했을 가능성은 있지만 **반복 생성의 원인으로 확정하지 않는다**.

데이터 구성, 60스텝 학습 강도, 적용 모듈 범위, 학습/추론 구현의 영향은 분리 시험하지 않았다. rank8·alpha16·학습률1e-5·batch1 조건으로 언어층의 attention/linear-attention/MLP에 58,363,904개 LoRA 파라미터를 학습했다. 손실이 유한하거나 낮아졌다는 사실만으로 일반화·출력 안정성을 보장하지 않는다.

## 다음 보완 순서

1. **이번 60스텝 어댑터를 운영에 적용하지 않는다.** 원본 운영 모델을 유지한다.
2. **다음 실험에서 저장된 10/20/40스텝 어댑터를 비교한다.** 같은 오류가 언제부터 나타나는지 확인하면 학습 강도의 영향과 데이터 문제를 좁힐 수 있다. 이 문서를 작성한 시점에는 중간 어댑터의 품질 평가는 하지 않았다.
3. **학습 60개를 다시 검토한다.** 기술명·관찰·해석·지원·한계·목표·이유의 역할을 분리하고, 반복 문장을 줄인다. 복수 세션 전체 출력, 서로 다른 목표, 미기록/미수행 차이, 잘못된 과거 요약 정정, 선호·재수집 정보 보존을 균형 있게 다룬다. 정답 출력은 AI가 판단한 근거를 담되 운영에 룰 기반 판정을 추가하지 않는다.
4. **한 번에 한 조건만 바꾸어 재시험한다.** 먼저 학습량을 비교하고 필요하면 학습률이나 LoRA 적용 범위를 줄인다. 개선 여부를 손실 대신 형식·사실·정보 보존·실행 가능한 퀘스트·시간으로 판단한다.
5. **개발 평가와 독립 평가를 구분한다.** 현재 25건은 이미 검토한 합성 개발 사례이며 학습과 시나리오 계열이 겹친다. 수정 후 최종 판정에는 별도의 미공개 사례와 전문가 검토가 필요하다. 이 실험은 지적장애 사용자의 실제 교육 효과를 입증하지 않는다.

위 보완 실험과 재학습은 아직 실행하지 않았다. 이번에 요청받은 원본 평가·60개 학습·후평가의 결과를 보존한 상태다.
