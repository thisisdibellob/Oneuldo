# 학습 목적과 다음 데이터 설계

정리일: 2026-09-29. 사용자와 합의한 목표 및 후속 설계 방향이다. **아래 데이터 개편·추가 학습·실제 사용자 효과 검증은 아직 실행하지 않았다.**

## 최종 목표

AI가 플레이 기록을 타당하게 분석하고, 그 분석을 근거로 사용자가 연습할 다음 퀘스트를 만든다. 사용자가 퀘스트를 반복해서 플레이한 후 목표 수행이 향상됐는지 확인한다. 파인튜닝은 분석 및 퀘스트의 품질을 높이기 위한 수단이다.

분석의 JSON 형식, 근거 ID, 논리적 일관성은 필요한 조건이지만 교육 효과를 증명하지 않는다. 기존 실험은 이 부분에 집중했고 퀘스트의 교육적 품질과 실제 효과는 충분히 평가하지 못했다. 앞으로는 다음 연결 전체를 다룬다.

**관찰된 수행 → 근거와 불확실성 → 연습/확인할 목표 → 퀘스트와 지원 → 후속 관찰 → 다음 조정**

## 데이터에 담을 것

| 구성 | 필요한 내용 |
|---|---|
| 관찰 | 실제 기록의 목표·선택·수량·제출·조건과 시간 순서. 보고와 직접 관찰을 구분 |
| 해석 | 무엇을 설명할 수 있고 무엇은 미확인인지. 장애명이나 집단 특성만으로 개인의 원인을 단정하지 않음 |
| 학습 목표 | 다음에 연습하거나 확인할 구체적인 수행. 단일 오류만으로 능력 부족을 확정하지 않음 |
| 문헌 근거 | 연구 대상, 과제, 교육·지원 방법, 측정 결과, 한계, 원출처와 해당 절/쪽수 |
| 퀘스트 | 목표와 연결되는 품목·수량·예산·안내 구성, 선택 이유 및 관찰할 항목 |
| 후속 결과 | 실제로 관찰한 수행과 도움 수준. 합성 결과는 합성으로 명시하며 교육 효과의 증거로 사용하지 않음 |
| 다음 조정 | 이전·현재 조건을 비교해 유지·변경할 부분과 아직 판단할 수 없는 부분 |

예를 들어 수량이 맞지 않는 제출만으로 수 개념 부족을 진단하지 않는다. 목표 읽기, 수량 조작, 제출 전 확인 등 가능한 설명을 현재 기록으로 얼마나 구분할 수 있는지 살핀다. 정보가 부족하면 과제를 통해 추가로 확인할 것을 제안한다. 이는 모델과 예제의 설계 목표이며 서버에 새 규칙 기반 판정을 추가한다는 뜻이 아니다.

## 모은 연구 자료의 활용 방향

1. 기존 자료 중 **교육·중재 방법과 수행 변화**를 보고한 연구를 추린다. 행동 특징 설명 자료와 중재 효과 자료를 구분한다.
2. 원문을 확인한 범위와 초록만 확인한 범위를 구분하고, 대상·환경·측정·결과·한계를 출처와 함께 정리한다. 확인하지 않은 결과나 쪽수를 생성하지 않는다.
3. 논문에 무엇이 있는지 설명하는 질문·답변과, 그 근거를 현재 로그에 어디까지 적용할 수 있는지 판단하는 사례를 구분해 작성한다.
4. 연구에서 관찰한 효과, 작성자가 제안한 퀘스트, 실제 사용자에게 확인된 효과를 별개로 표시한다. 연구의 집단 결과를 개인의 능력이나 행동 원인으로 바꾸지 않는다.
5. 모델이 인용할 원문/근거를 입력에서 확인할 수 있게 하는 구성도 검토한다. 문헌 이름을 기억하는 것만으로 출처 정확성을 보장하지 않는다.

논문 본문 자체의 추가 학습도 별도 선택지이지만, 이번 작업에서는 수행하지 않았다. 이전 60개 실험을 논문 전체로 지식을 학습한 실험이라고 설명하지 않는다.

## 검증을 두 단계로 분리

### 모델 및 퀘스트 품질

- 사실·세션별 목표·근거를 맞게 읽고 중요한 선호와 조건을 보존하는가.
- 제안한 퀘스트가 분석과 구체적으로 연결되며 게임에서 구현 가능한가.
- 다음에 무엇을 관찰할지 명확하고, 연구 근거와 작성자의 가설이 구분되는가.
- 필수 출력 형식과 모든 세션을 보존하는가.
- 연구 범위를 넘는 원인·능력·교육 효과 단정을 피하는가.

현재 앱 설정만으로 표현하거나 로그로 관찰할 수 없는 항목은 설계 문서에 남긴다. 새로운 필드를 학습 예제에 넣기 전에 실제 입력/출력 계약과 수집 경로부터 확인해야 한다.

### 실제 사용자의 수행 변화

목표에 맞는 정확도, 필요한 도움, 다른 품목·조건에서의 수행, 시간이 지난 뒤 유지 여부 등을 관찰할 수 있는지 설계한다. 어떤 지표가 적절한지는 실제 과제와 수집 가능성에 맞춰 검토한다. 쉬워진 과제나 늘어난 안내 덕분의 성공과 독립적인 수행 향상을 혼동하지 않도록 조건·도움 수준을 함께 기록한다.

같은 사용자의 전후 차이가 보여도 퀘스트의 인과적 교육 효과로 바로 확정하지 않는다. 평가 계획과 관련 전문가 검토가 별도로 필요하다. AI 페르소나로 만든 로그나 합성 성공 사례는 시스템의 논리/형식 점검에는 활용할 수 있지만 실제 사용자의 향상 증거가 아니다.

## 다음 실행 순서

1. 현재 실패 결과와 원본 운영 모델을 보존한다. 첫 최종 어댑터는 배포하지 않는다.
2. 저장된 10/20/40스텝 어댑터를 같은 조건으로 비교해 퇴행 시점을 확인하는 실험을 준비한다.
3. 기존 문헌에서 교육·지원 방법과 관찰 결과를 추려 출처를 확인한다.
4. 학습 후보 60개를 새 버전으로 개편한다. 문헌 이해, 사실 분석, 근거 있는 퀘스트, 후속 결과 해석의 구성을 먼저 정하고 각 출력 필드가 같은 문장을 반복하지 않게 검토한다. 이 문서는 새 60개를 작성했다는 뜻이 아니다.
5. 기존 개발 평가 25개는 동결해 이전 결과와 비교한다. 새 교육 목적의 평가 범위는 별도로 설계하고, 최종 성능을 판단할 미공개 평가와 구분한다. 기존 결과를 본 뒤 평가 답변을 수정해 점수가 오른 것처럼 보고하지 않는다.
6. 전문가 검토와 실제 사용자 평가 계획을 마련한 뒤, 관찰된 수행 변화로 실제 효과를 확인한다.

데이터·학습량·학습률·LoRA 적용 범위를 한 번에 바꾸지 않는다. 이번 결과만으로 데이터 편향, 학습 강도, 구현 영향 중 하나를 원인으로 확정하지 않는다.
