# 학습 후보 보완 v3 — 2026-09-24

학습 후보는 **60개(세션 40·프로필 20)**, 평가 후보는 **기존 25개 그대로**다. 18개 반복 세션 사례와 6개 프로필 사례를 재작성하고 3개 사례의 설명을 일부 정리했다. 기존 native-v2 전체 파일과 평가 JSONL 바이트를 보존했다.

## 바뀐 내용

| 다음 연습 계획 항목 | v2 | v3 |
|---|---|---|
| 품목 종류 | 2종 59 / 3종 0 / 4종 1 | 2종 35 / 3종 14 / 4종 11 |
| 수량 복잡도 | LOW 58 / MEDIUM 2 | LOW 49 / MEDIUM 11 |
| 예산 압박 | LOW 58 / MEDIUM 2 | LOW 50 / MEDIUM 10 |
| 문자 지원 | SIMPLIFIED 54 / STANDARD 6 | SIMPLIFIED 37 / STANDARD 21 / REDUCED 2 |
| 난이도 | 1단계 5 / 2단계 54 / 3단계 1 | 1단계 5 / 2단계 50 / 3단계 5 |

숫자를 균등하게 만드는 것이 목적은 아니다. 세/네 종류의 실제 **합성 입력 조건**과 대응하는 관찰·계획을 함께 작성했다. 네 종류 과제도 항상 3단계로 올리지 않으며, 긴 소요 시간이나 부분 기록만으로 난이도를 줄이지 않는 사례를 포함했다. 현재 분포가 실제 사용자 분포를 대표한다는 의미는 아니다.

- **T28:** 사용자가 이번에 계산 도움을 받았다고 보고했는데 상위 AI는 독립 계산 숙달을 주장한다. 목표 제출은 보존하되 독립 수행·교육 효과라는 주장을 철회하고 사용자가 요청한 짧은 목록을 유지한다.
- **T25:** 이전 네 종류 제출은 보존하고, 새 중간 장바구니 발췌만으로 실패라는 현재 AI의 단정을 확정하지 않는다.
- **T29:** 새 네 종류 제출을 과거부터 항상 성공·무지원 수행했다는 주장으로 확장하지 않는다. 일반 목록을 원하는 현재 보고를 반영한다.
- **T55:** 이전 결과가 없는 상황에서 이전 실패·읽기 기능 회복을 만들어내지 않는다. 설명을 줄이고 품명·수량을 남겨 달라는 요청을 별도로 기록한다.
- **T56:** 실제 입력의 두 세션을 열 차례 성공으로 늘리거나 교육 효과로 단정하지 않는다. 수량이 다른 네 종류 제출과 명시적 목록 선호를 유지한다.
- **T09/T20/T40:** 제출 근거를 설명에 보강하고 일부 내부 처리 표현을 정리했다. T20의 공격 문구와 이를 근거로 진단하지 않는 방어 사례 자체는 유지한다.

품목 종류 수와 낱개 합계를 구분한다. 예를 들어 T45는 세 종류·총 여섯 단위다. 이것을 기억 용량으로 해석하지 않는다. 새 사례에 장애명을 원인으로 행동을 고정하는 설정을 넣지 않았다.

## 검증 결과

- 실제 운영 프롬프트 생성기·참조 인코더·파서·검증기로 **85개 모두 왕복 통과**. 별도 참조 삭제 및 동일 세션 검사까지 Java 테스트 3개 통과.
- 새 데이터 테스트 **6개 통과**: 입력의 목표 답변 비의존성, 숫자·제출 조건, 인접 근거 참조, 60/25 개수, 이전 버전 및 평가 보존.
- 실제 고정 토크나이저로 **85개 assistant-only 경계·종료 토큰 확인**, 잘라낸 사례 없음. 학습 세션 최대 3,557토큰, 학습 프로필 최대 2,206토큰. 가장 긴 학습 정답은 T56의 496토큰이다.
- 정규화한 정확한 입력 중복 0개, 학습/평가 간 정확한 입력 중복 0개. 유사한 시나리오 계열은 남아 있다.
- 평가 JSONL은 재직렬화하지 않았다. Java의 map 순서가 달라질 수 있어 재생성 평가의 JSON 의미를 대조하고 원래 바이트를 유지했다.

이 검증은 자료 형식·산술·참조·보존 범위에 대한 검사다. **계획의 교육적 효과, 실제 장애인의 행동 분포, 임상적 타당성, 모델 품질 향상을 검증한 것은 아니다.** 프로필의 도움·선호 보고는 저자 작성 합성 상위 분석 입력이며 실제 앱 수집기에 새로 구현했다는 뜻이 아니다.

원문 논문을 복사해 정답으로 넣지 않았다. 신규 대체 사례의 직접 인용 source_card_ids는 비워 두었고 작성한 사실·가설·계획을 의학적 연구 결과로 취급하지 않는다. domain expert/자료 이용 조건 검토 상태는 이전과 같이 미완료다. 평가 결과를 이미 읽고 자료를 보완했으므로 이 25개는 개발 평가이며, 이후 성능을 독립 평가의 일반화 성능처럼 보고하면 안 된다.
