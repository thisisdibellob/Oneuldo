# 초안 작성·검토 기록

작성일: 2026-09-24 · 작성자: Codex · 전문가 검토: 미실시

## 후속 내용 검토 (2026-09-24)

학습 후보 T01~T60을 모두 대조하고 14개를 교정했다. [내용 검토 결과](content-review.ko.md), [사례별 검토·해시](content-review.json), [변경 전후 기록](content-review-changes.json)을 추가했다. 평가 후보 25개는 해시 기준 변경이 없다.

불가능한 예산 조건 2건, 참조 누락 4건, 중복 관찰 3건, 근거 부족한 품목 확대 1건, 문헌 연결 보완 3건 등을 수정했다. 문제 유형 간 사례 중복이 있으므로 합계는 수정 사례 14개와 다르다. T47은 라벨 의미 검토를 보류 항목으로 남겼다.

아래 작성 당시의 한계 중 이용 조건 확인은 일부 진전됐다. M01·P27·P40의 라이선스 표기를 확인했으며, 적용 조건과 나머지 자료의 확인은 남아 있다. 전문가 검토·학습 승인 상태는 변경하지 않았다. 2종 품목·간단한 문자 지원으로 치우친 분포와 실제 서비스 입력 차이도 여전히 남는다.

## 수행한 작업

- 기존 자료 목록과 후속 원문 확인 기록에서 18개 자료를 골라 확인 범위·한계를 유지했다.
- 세션 분석 40개와 프로필 갱신 20개를 새로 작성했다. 실제 계정·개인정보·서버 로그는 사용하지 않았다.
- 별도 문헌과 시나리오로 평가 사례 25개를 작성했다.
- 실제 앱에서 확인했던 오류 유형은 과제로 반영했지만 당시 사용자의 실제 로그를 학습 데이터로 복사하지 않았다.
- 출력 계약을 현재 Java 분석 도메인과 프로필 프롬프트에 대조했다. 입력은 간단한 검토용 형식이며 운영 입력과의 차이를 README에 명시했다.
- 사건 참조, 세션별 판정 참조, 계획이 참조하는 finding, 문헌 카드 참조, 합성 표시와 미승인 상태를 자동 검사했다.
- 다른 세션의 근거를 섞거나, 같은 플레이 재분석을 새로운 플레이로 표시하는 구조 오류를 검사했다.
- 지원 문장과 계획의 명시적 품목 수, 허용 난이도와 출력 열거값을 검사했다.

## 작성 과정에서 확인·보완한 내용

1. 모든 답변을 한 가지 finding이나 빈 대안 배열로만 구성하지 않도록, 별도 근거가 있는 다중 관찰과 근거 있는 대안 설명을 포함했다.
2. 프로필 입력의 새 분석을 목표 프로필 그대로 복사하지 않고 새 세션 중심의 별도 입력으로 작성했다. 이전 오류를 정정하는 목표 답변을 분리했다.
3. 성공을 무조건 보류하는 방향으로 치우치지 않도록 명확한 성공과 실패를 함께 포함했다.
4. UI 지연이 직접 기록된 경우와 원인을 알 수 없는 지연을 분리했다. 기록이 없는데 기술 오류를 대안으로 지어내지 않았다.
5. 외부 진행자의 촉구는 합성 상황의 명시적 맥락으로만 썼다. 앱에 음성·영상·직원 호출 기능이 존재한다고 제안하지 않았다.
6. 실제 결제와 게임 제출을 구분하고, 성공을 일상생활 능력·진단·교육 효과로 확대하지 않았다.

## 남은 한계

- 목표 답변은 모델이 작성한 초안이며 전문가가 보증한 정답이 아니다. 구조 검사 PASS가 의미 정확성을 보장하지 않는다.
- 합성 로그는 짧고 정규화돼 있다. 실제 322개 이상 사건, 중복·순서 오류·장문 입력의 난도까지 대표하지 않는다.
- 문헌은 카탈로그와 확인 기록을 재사용했다. 초록 중심 자료가 포함되며 이용 조건도 미확인이다.
- 사례별 문헌 연결과 지원 제안이 타당한지 관련 분야 사람이 검토해야 한다. 문헌이 가상 개인의 원인을 증명하지 않는다.
- 이전 프로필 입력은 단순화했고 일부는 의도적으로 잘못된 해석을 담았다. 실제 프롬프트와 동일한 입력은 아니므로 학습 전에 맞춰야 한다.
- 장보기 제출을 게임 과제 달성 기준으로 삼는 범위의 예시다. 실제 구매나 수행의 독립성을 뜻하지 않는다. 중단·부분 기록의 판정은 평가 기준을 별도로 합의해야 한다.
- 학습용·평가용 문헌 ID와 URL은 분리했지만 문헌들의 인용 관계 중복까지 조사한 것은 아니다.
- 자동 검사는 행동 판단 규칙을 추가하지 않는다. 현재 모델의 재추론·LoRA 학습·학교 서버 메모리 시험은 수행하지 않았다.

## 검토할 때 볼 질문

각 목표 답변을 문장 단위로 확인한다.

1. 실제 입력의 어떤 사건이 이 문장을 뒷받침하는가?
2. 사실과 추측을 구분했는가? 대안 설명도 실제 맥락에 근거하는가?
3. 문헌의 대상·과제·확인 범위를 벗어나 개인에게 적용하지 않았는가?
4. 성공 판단, 요약, 불확실성, 지원 계획이 서로 모순되지 않는가?
5. 재분석을 새 학습 효과로 세지 않았는가?
6. 다음 연습이 현재 게임의 기능으로 가능한가?

이 질문은 데이터 검토용이다. 사용자 능력을 자동 판정하는 룰이나 실제 임상 평가 기준으로 사용하지 않는다.

## 60개·25개 확장 기록

기존 학습 30개와 평가 10개를 보존하고 학습 30개(분석 20·프로필 10), 평가 15개(분석 10·프로필 5)를 추가했다. 식별자는 T01~T60, E01~E25이다.

추가 예제는 별도 `additional_cases.py`에 작성했다. 금액·목표 충돌, 대리 조작, 기록 유실·재수집, 지원 선호와 실제 제공 조건 등 서로 다른 오류 상황을 포함했다. 학습과 평가의 문헌 분리를 유지했으며 생성 UUID를 무시한 동일 상황의 분리 여부도 검사한다. 이 검사는 의미적 유사성이나 독립 임상 타당성을 보증하지 않는다.

T50과 E16에는 실제 선택 근거가 부족하여 findings와 targetFindingIds가 빈 사례를 넣었다. T47은 무촉구 조건이 목표에 명시된 특수 사례로, 도움을 받은 모든 사용자를 실패로 판정하는 규칙이 아니다. E21은 ID가 달라도 재수집된 같은 플레이임을 기록이 명시하는 경우로, 단순 플래그보다 원본 맥락을 보도록 작성했다.
