## 측정 범위와 한계

1. 정규화한 합성 입력으로 모델을 직접 호출했다. 실제 앱의 청크 분할·압축 출력·운영 검증기·재요청·프로필 저장을 함께 실행한 시험이 아니다. 24/25는 이번 평가 도구의 구조 검사 결과이며 앱 안전 검증 통과율이 아니다.
2. system/user만 보냈다. 정답 assistant, rubric, 검토 기록은 모델에 보내지 않았다. 평가 원본과 요청별 SHA-256을 보존했다.
3. `temperature=0`, `num_ctx=18432`, `num_predict=1800`, `think=false`, `stream=false`, 동시 요청 1개로 고정했다. 펼친 출력의 format 스키마는 보내지 않았다. 게이트웨이의 스키마 제한과 실제 서비스 입력 차이는 [프로토콜 설명](README.ko.md)을 참고한다.
4. 모델 태그는 응답과 일치하지만 서버의 현재 원본 digest와 GPU 상태는 이번에 직접 확인하지 않았다. 동일한 이름이 영구적으로 같은 가중치를 보장하지 않는다.
5. 평가 전 별도 `/api/tags` 연결은 12초 제한으로 실패했다. 본 실행은 연결 하나를 재사용해 25회 성공했다. 학교/집/팀원 네트워크 전체의 연결 문제 해결을 의미하지 않는다.
6. 각 사례는 1회만 실행했다. 온도 0도 완전한 재현성을 보장하지 않으며, 동시 사용자 지연이나 반복 변동은 측정하지 않았다.
7. 이 25개는 실제 장애인 자료나 교육 효과 검증 자료가 아니다. 결과를 바탕으로 수정하면 개발 평가셋이 되므로, 최종 성능 확인에는 미사용 사례가 따로 필요하다.

## 다음 작업

**다음 3번은 학습 자료를 실제 운영 입력·출력 형식에 맞추는 작업이다.** 현재의 펼친 합성 JSON을 그대로 학습한 뒤 운영의 압축 형식에서 같은 성능이 나올 것이라고 가정하면 안 된다.

- 학습할 단계를 먼저 고정하고 해당 단계의 실제 프롬프트·참조 인코딩·출력 계약에 연결한다.
- 60개 학습 후보에서 이번에 드러난 맥락 연결·근거 없는 대안·설명/설정 불일치 유형과 지원 계획 편향을 점검한다. 평가 정답 자체를 학습에 복사하지 않는다.
- 실제 원본 모델과 토크나이저를 확인하고 입력 길이·잘림을 측정한다. 내용 검토에서 보류한 T47의 라벨 정의도 먼저 정한다.
- 그 뒤 GPU 1에서 소수 스텝으로 메모리·호환성을 확인하고, 실제 학습 후 동일 조건의 별도 결과 폴더로 비교한다.

이번 작업은 운영 판단용 규칙을 추가하지 않았다. JSON 구조·참조 검사와 내용 검토를 분리했으며, 학습이나 서버 설정 변경도 실행하지 않았다.
