# 파인튜닝 전 기준 모델 평가 v1

**25개 실행 완료:** [평가 결과](report.ko.md) · [실제 응답 25개](model-responses.ko.md)

평가 대상은 학교 서버의 `qwen3.6:27b-q4_K_M`이다. 이 평가는 정규화한 합성 입력에 대한 **현재 모델의 응답**을 측정한다. 앱의 청크 분할·분석 검증기·재요청·프로필 저장까지 포함한 종단간 시험은 아니다.

## 고정한 조건

- `eval.frozen.jsonl`: E01~E25, 분석 17개·프로필 8개. 기존 평가 초안과 동일한 바이트를 보존한다.
- `protocol.json`: 평가 파일 해시, 요청별 해시, 모델 이름과 생성 조건.
- 입력은 각 행의 system/user 메시지만 전달한다. assistant 정답, rubric, 검토 메모는 전달하지 않는다.
- 사례당 1회, 순차 호출. temperature=0, num_ctx=18432, num_predict=1800, think=false, stream=false.
- 게이트웨이 코드상 top_p=0.8, keep_alive=10m. 이 두 값은 서버 코드와의 실시간 동일성까지 검증한 값은 아니다.
- 게이트웨이는 이 평가의 펼친 출력 스키마를 format으로 허용하지 않으므로 format을 넣지 않는다. 요청 본문의 출력 계약을 따르는지 평가한다.
- JSON 수리, 내용 재작성, 실패한 답을 받은 뒤의 재생성을 하지 않는다. 출력 한도 도달도 그대로 기록한다.
- 연결을 맺기 전 실패만 최대 3회 시도한다. 요청 전송 후 상태가 불확실하면 중단하여 중복 추론을 피한다.
- 같은 HTTPS 연결을 가능한 한 재사용한다. 따라서 25회의 독립 네트워크 접속 안정성을 측정하는 시험은 아니다.
- 온도 0이어도 완전한 결정성을 보장하지 않으며 단일 회차로 변동성을 측정할 수 없다.

공개 `/api/tags`는 게이트웨이의 고정 모델 이름을 반환한다. 현재 원본 모델 digest나 GPU 상태는 이 API로 확인할 수 없으므로 `model_digest_verified=false`로 기록했다. 이전 서버 설치 기록을 이번 실시간 확인으로 바꾸어 쓰지 않는다.

## 파일

| 파일 | 용도 |
|---|---|
| `responses/E*.json` | 키 없는 요청 본문, 응답 원문, 상태, 시각, 왕복 시간 |
| `structural-results.json` | 엄격한 JSON·필드·허용값·사건 소속 검사와 시간/토큰 수 |
| `semantic-review.json` | Codex가 입력과 답변을 읽고 기록한 의미 검토. 임상 전문가 평가가 아님 |
| `report.ko.md` | 전체 호출과 내용 검토가 끝난 뒤 작성하는 결과 보고서 |

원본 응답은 보존한다. 구조 검사 통과는 문장이 올바른 사건을 인용했거나 해석이 타당하다는 뜻이 아니다. 참조 ID가 존재하더라도 주장과 연결되지 않는 문제는 의미 검토에서 따로 표시한다.

성공·실패 라벨의 초안 일치율은 참고값이다. 초안도 모델이 작성했으므로 불일치를 곧 오답률이라고 부르지 않는다. 특히 미완료 과제와 관찰 불가능한 수행을 어떤 라벨로 표시할지 합의가 필요한 경우를 구분한다.

## 재현

프로젝트 루트에서 실행한다. 키는 기존 소유자 전용 로컬 파일에서 읽고 출력·산출물·명령 인수에 키 값을 저장하지 않는다.

```bash
python3 docs/ai/finetuning/run_baseline.py
python3 docs/ai/finetuning/run_baseline.py --run
python3 docs/ai/finetuning/check_baseline.py
python3 -m unittest discover -s docs/ai/finetuning -p 'test_baseline_tools.py' -v
```

성공 응답이 이미 저장된 사례는 다시 호출하지 않는다. 실패·상태 불명 사례가 있으면 자동으로 재전송하지 않으므로 원인을 확인해야 한다. 새 모델이나 별도 반복 측정은 `--out`으로 새 디렉터리를 지정하고 동일한 평가 파일·프로토콜 조건을 유지한다.

평가 결과를 보며 학습 자료나 프롬프트를 수정하면 이 25개는 개발 평가셋이 된다. 최종 성능 주장에는 별도의 미사용 사례가 필요하다.
