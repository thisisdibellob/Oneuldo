# 분석 출력 제한과 단계별 복구 — 2026-09-08

556개 사건을 11개 구간으로 분석한 뒤 중간 요약 단계에서 응답이 두 번 모두 900토큰에 도달해 `finishReason=length`로 종료됐다. 최종 분석과 프로필 갱신은 완료되지 않았다.

## 변경

- 일시적으로 1,800토큰으로 높였으나 공급자가 보고한 분당 출력 1,000토큰 제한을 고려해 기본값을 900으로 복원했다.
- 중간 요약이 재시도까지 `length`로 실패하면 4개 묶음을 2개씩 나눠 처리한다. 홀수 묶음의 남은 1개는 원래 요약을 그대로 넘긴다.
- 2개 묶음도 잘리면 두 자식 입력을 모두 유지하고 핵심 관찰 1~2개와 요약 한계를 명시하는 짧은 JSON을 AI에 요청한다. 서버에서 텍스트나 JSON을 자르지 않는다.
- 최종 출력이 잘리면 저장된 구간 해석을 중간 요약으로 줄인 뒤 최종 분석을 다시 시도한다. 하나의 요약까지 줄여도 실패하면 오류로 종료하며 무한 재시도하지 않는다.
- 입력과 예약 출력의 합산 예산은 기존 7,000토큰을 유지한다.
- 환경변수 `AI_ANALYSIS_CHUNK_OUTPUT_TOKENS`, `AI_ANALYSIS_FINAL_OUTPUT_TOKENS`로 재설정할 수 있다.
- 프로필 갱신은 최종 출력 예산 설정을 공유한다. 퀘스트 생성의 별도 출력 설정과 사용자 판단 기준은 변경하지 않는다.

## 한계

429 응답의 `retry-after`에 따라 기존 공유 대기 로직으로 재개한다. 이는 공급자 할당량을 늘리는 기능이 아니다. 대기가 너무 길거나 반복 실패하면 작업은 실패하며 기존 프로필은 유지된다.

성공한 구간·중간 요약은 체크포인트로 보존한다. 동일 입력·시스템 프롬프트·출력 상한일 때만 재사용한다. 900토큰 기본값 복원으로 기존 구간 결과를 재사용할 수 있다. 새 요약에는 추가 시간·토큰이 필요하다.

## 검증

자동 테스트는 최종 출력 잘림 → 4개 요약 잘림 → 2개 요약 잘림 → 간결 요약 → 최종 완료를 강제로 재현한다. 원본 관찰 6개를 다시 호출하지 않는지와 근거 ID 검사, 체크포인트 재개, 429 대기를 함께 검사한다. 관련 테스트 30개가 통과했다.
