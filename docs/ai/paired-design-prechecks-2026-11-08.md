# 쌍 설계 시작 전 점검 A·B 결과 (2026-11-08)

[쌍 설계 계획](teacher-paired-design-plan-2026-11-08.md) 5절의 점검이에요. 모델 호출 없이 실험 1~6 기록만 읽었어요. 완료 실험 폴더는 고치지 않았어요.

- 도구: [`scripts/experiments/route_metrics.py`](../../scripts/experiments/route_metrics.py) (감독 전용, 읽기 전용)
- 범위: 여섯 실험의 회차 288개 (처음·연습·마지막 시험 전부)

## 점검 A — 실험 4(중간+, 50%)와 실험 6(상중, 92%)은 왜 달랐나

### 두 실험에서 같았던 것
| 항목 | 결과 |
|---|---|
| 시험 매장 (매대·지점 그래프·손님·공사·기둥) | **같음.** 감독 전용 `world-reference`가 config 표기만 빼고 해시까지 같아요. |
| 손님 수 | **둘 다 4명.** 실험 4는 손님 수가 "1~5 무작위"였는데, 고정 시드(`v2executor-s01`)로 4명이 뽑혔어요. 실험 6의 "손님 4명 추가"는 실제로는 아무것도 바꾸지 않았어요. |
| 장보기 AI가 받은 시작 묶음 (`actor-bundle.json`) | **같음.** 다른 건 입력 해시뿐이에요. |
| 장보기 AI 안내 (`actor-brief.md`)와 시작 지시문 | **같음.** 지시문 틀이 글자 단위로 같고, 모델 지정도 둘 다 `sonnet`이에요. |
| 실행기 코드 (`Oneuldo-merge-v2`) | **바뀌지 않음.** 실험 4 이후에 수정된 파일이 없어요. |
| 다른 점 | 준비 시드 문자열(`constructionprobe-…` vs `highmidprobe-…`)과 실행 날짜(11-04 vs 11-07)뿐이에요. |

### 행동에서 달랐던 것
| | 실험 4 처음 시험 | 실험 6 처음 시험 |
|---|---|---|
| 성공 | 6/12 | 11/12 |
| **표지를 하나도 못 보고 50단계 전에 스스로 그만둠** | **6명** (25~45단계, 걷기 17~35번) | **0명** |
| 표지를 본 사람의 첫 표지 결정 번호 | 23~50 | 20~64 |

- 실험 4의 처음 시험 실패 6명은 **모두 일찍 포기한 경우**예요.
  - 이 매장에서는 첫 시험 매대 표지가 보통 20~60번째 결정에서 처음 보여요.
  - 그래서 30~40번째 결정 전에 그만두면 표지를 한 번도 보지 못해요.
- 실험 6에서는 이렇게 포기한 사람이 없었어요.
- 6/12 대 0/12는 서로 독립인 우연이라면 p ≈ 0.014(Fisher)예요.
- 여섯 실험 전체에서 "표지를 못 보고 일찍 포기"는 12번이에요.
  - 실험 4가 7번(처음 시험 6번 + 연습 1번)이에요.
  - 실험 2 참가자 1이 4번이에요("오래 헤매면 그만둬" 메모가 이어진 경우).
  - 나머지 1번은 실험 5의 기록 오류예요.

### 결론
- **매장, 입력, 지시문, 코드는 같았어요. 차이는 장보기 AI가 일찍 포기했는지 여부 하나예요.**
- 그 원인은 기록만으로는 가를 수 없어요.
  - 우연일 수 있어요.
  - 같은 날 같은 시간대에 돌린 묶음 효과일 수도 있어요. 예를 들어 `sonnet` 이름 뒤의 실제 모델 상태가 달랐을 수 있어요. 이건 확인할 방법이 없어요.
- 이 때문에 성공률만으로 매장 난이도를 정하는 건 믿기 어려워요.

### 쌍 설계에 반영할 점
1. 쌍 설계가 맞는 방향이에요. 같은 r0를 두 교사 갈래가 이어받으면 이런 묶음 차이가 두 갈래에 똑같이 들어가요.
2. **"표지를 못 보고 일찍 포기"를 보조 지표로 추가**해요. 실험 기간 사이 흔들림을 감시하는 용도예요.
3. 시범과 본실험 처음 시험은 같은 기간에 돌려요. 같은 시간대에 몰지 않고 몇 번에 나눠 돌려요.
4. "손님 수 4명"처럼 고정 시드에서 원래와 같게 뽑히는 설정은 바뀐 조건으로 세지 않아요. 바꾸려는 설정은 `world-reference` 해시로 정말 달라졌는지 확인한 뒤 써요.

## 점검 B — 최단 경로와 통로형

### 최단 경로 계산
- 방법
  - 감독 전용 `world-reference`의 지점 그래프를 써요. 장보기 AI가 고르는 `walk/W…` 선택지와 같은 그래프예요.
  - 출발 → 시험 매대 전부(순서 무관) → 계산대까지 걷기 횟수의 최솟값을 계산해요.
- 288개 회차 모두 계산됐어요. 모서리형 1개는 지원하지 않아 제외했어요.
- 매장마다 최단 걷기 횟수
  | 매장 | 최단 걷기 |
  |---|---|
  | 기본형 | 8~18번 (실험 3~6 시험 매장은 17번) |
  | 기본형 + 공사 | 17번 |
  | **통로형** | **15~43번** (실험 2 시험 매장은 37번, 연습은 대부분 33~43번) |

### 장보기 AI가 실제로 걷는 양
- 기본형 성공 233번을 보면 다음과 같아요.
  - 걷기는 최단의 **3.2배**예요(중앙값, 사분위 2.8~3.8배).
  - 걷기가 아닌 행동(목록 읽기, 매대 열기, 담기, 장바구니, 계산)이 약 25번이에요.
- 이 비율을 통로형 최단 37~43번에 적용하면 **약 145~165번 행동**이 필요해요. 행동 한도는 100번이에요.

### 통로형 회차 26개
- 성공 4번
  - 최단이 15번인 쉬운 통로형 2번
  - 최단 40번을 걷기 55번, 63번(1.4~1.6배)으로 아주 효율적으로 간 2번
- 실패 22번
  - 대부분 75~99단계에서 스스로 그만두거나 계산했어요.
  - 표지는 기본형과 비슷한 시점(중앙값 30번째 결정)에 봤어요.
  - 그래서 표지가 안 보여서가 아니라, 길이 길어서 행동이 부족했던 거예요.

### 결론
- **통로형은 풀 수 있는 매장이에요.** 경로가 있고 성공한 사례도 있어요.
- 다만 이 실행기에서는 기본형보다 2~3배 많이 걸어야 해요. 행동 100번 안에 끝내려면 기본형 때보다 2배 이상 효율적으로 걸어야 해요.
- 즉 통로형의 어려움은 상당 부분 **MCP 지점 그래프의 경로 길이 × 행동 100번 한도**에서 나와요. 페르소나의 특성 때문은 아니에요.
- 앞 답변의 "막다른 길" 설명은 일부만 맞아요. 더 큰 원인은 경로 길이예요.
- 실제 앱에서 사람이 통로형을 몇 번의 이동으로 지나가는지는 확인하지 않았어요.

### 쌍 설계에 반영할 점
1. **통로형은 시험 매장 P·Q 후보에서 빼요.** 최단이 15번 안팎인 통로형만 예외로 둘 수 있어요.
2. 주 지표 "헤맨 걸음 = 걷기 − 최단"은 계산된다는 것을 확인했어요. 매장마다 최단이 다르니 **걷기 ÷ 최단 비율**도 함께 보고해요.
3. 첫 표지 결정 번호는 장보기 AI가 저장한 응답 파일에서 읽어요. 그래서 2개 회차(실험 5 g8 r0, 실험 3 g3 r5)는 값이 비었어요. 본실험에서는 실행기 기록에서 직접 읽도록 바꿔요.
