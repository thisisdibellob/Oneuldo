# 페르소나의 추천 과제 학습 효과: 재검증 및 선행 조건

## 검증하려는 질문

동일한 가상 사용자가 실제 플레이하고, 그 로그에서 나온 AI 분석·추천 과제를 수행한 뒤, 목표 상품의 규격·수량 선택과 자기수정 행동이 달라지는지를 확인한다. 안내에 따른 수행과 안내 없이 유지되는 전략을 구분한다. 합성 행위자의 결과는 실제 지적장애인의 교육 효과를 입증하지 않는다.

## 이전 비교에서 확인한 문제

1. 기존 반복 기록의 `generationPolicy`는 `stochastic`이었다. LLM이 각 행동을 결정하는 실험이 아니었다.
2. `ActorObservation`에 앱의 `briefing`, `description`, `checkoutDialogue`가 없었다. 추천의 목표 상품은 바뀌지만 교육적 안내는 행위자에게 전달되지 않았다.
3. 재방문 경험은 실행된 조작·구매 상품의 기억을 보존했다. 새로 습득한 비교 전략이나 이해를 보존하는 구조가 아니었다. 반복에 따라 오류율을 줄이는 방식으로 이 공백을 메우면 개선을 실험자가 미리 넣는 셈이 된다.
4. 이전 2~3회차는 유효한 퀘스트가 만들어지지 않아 실행되지 않았다. 3품목 계획에 2품목 고정 S01을 선택한 것이 직접 원인이었다.

따라서 기존 성공률·시간 차이는 추천에 따른 능력 향상의 증거로 사용할 수 없다. 특히 10분 29초 → 3분 31초 변화는 실행 대기 시간을 압축한 효과이며 학습 성과가 아니다.

## 이번 수정

- 앱에서 실제 표시하는 설명·브리핑을 시작 직후 AI 관찰에 전달하고, 결제 안내는 결제 단계에만 전달한다. 숨은 정답·분석 보고서·전체 지도는 전달하지 않는다.
- 기존 OpenAI 방식 외에 학교 서버의 인증된 `/api/chat`을 지원한다. 사고 과정 출력 없이 JSON 행동을 요청하고, 실패 시 확률 행동으로 조용히 대체하지 않는다.
- 긴 기존 페르소나 문서를 유지하기 위해 학교 서버가 지원하는 18,432 컨텍스트를 사용한다. 첫 8,192 요청은 `CONTEXT_LIMIT_EXCEEDED`로 거절됐다.
- 행위자가 사용할 수 있는 주의 상태 값과 관찰 단서 식별자를 구체적으로 제공한다. 실제 모델의 잘못된 상태 이름·식별자 응답이 먼저 확인됐다.
- 외부 AI가 선택한 탐색 행동도 초기 탐색 횟수를 소모하도록 수정했다. 종전에는 확률 정책의 `next()`에서만 이 값이 줄어 AI 모드에서는 초기 상태가 남았다. 확률 정책의 행동 경로는 바꾸지 않았다.
- 퀘스트 v7 입력에 계획의 품목 수와 호환되는 시나리오 ID를 제공한다. 사용자 능력이나 과제 내용을 코드로 대신 판단하지 않고, 콘텐츠의 고정 품목 수 충돌만 예방한다.

시작 안내를 한 번 전달한 것만으로 장기 기억·이해가 생겼다고 가정하지 않는다. 현재 단계는 AI 행위자 실행의 사전 검증이며 교육 효과가 확인된 상태가 아니다.

## 완료 조건

1. AI 행위자가 같은 입력 계약에서 정상적으로 한 과제를 실행할 수 있어야 한다. 형식 오류·통신 실패·탐색 정지는 별도 기술 실패로 기록한다.
2. 실제 앱 재생 완료와 DB 로그가 확인된 회차만 분석에 사용한다. 계획 생성·텍스트 답변은 실제 플레이로 집계하지 않는다.
3. 과제 안내를 본 뒤 AI가 스스로 남긴 기억을 별도 추적해야 한다. 답안이나 분석 결론을 행위자 기억으로 주입하지 않는다. 현재 발견/조작 기억만으로는 학습 지속성을 검증할 수 없다.
4. 동일 난이도의 구매 단위 오류, 수량 오류, 최초 선택, 자발적 수정, 목록·도움 사용을 비교한다. 속도 압축 시간은 능력 지표에서 제외한다.
5. 안내를 줄이고 상품을 바꾼 전이 과제에서 유지되는지 확인한다. 3회 결과는 탐색적 사례이며 효과의 확증으로 쓰지 않는다.
6. 분석/추천 변경은 실제로 전달된 안내와 관찰 결과의 연결에 근거한다. 행위자 구현 오류를 분석 AI의 오류로 돌리지 않는다.

## 다음 수정 우선순위

1. AI 행동 JSON을 스키마로 제한하거나, 같은 관찰에서 형식 오류만 되돌려주는 제한된 교정 절차를 마련한다. 게임 행동을 임의로 대신 고르지 않는다. 현재 실험은 지원되지 않는 출력에서 중단하는 방식이다.
2. AI가 관찰·안내로부터 스스로 작성한 짧은 전략 기억을 별도로 설계하고, 실제 완료된 플레이에서 나온 것만 다음 회차에 전달한다. 기억이 틀리거나 전략을 적용하지 않는 경우도 그대로 남긴다. 현재 조작/상품 경험과 이 기억을 구분한다.
3. 같은 행위자 버전으로 새 기준 과제부터 시작해 추천 후 3회와 안내 없는 전이 과제를 실행한다. 이전 stochastic 플레이와 LLM 플레이를 전후 비교군으로 섞지 않는다.
4. 그때 목표 오류가 반복되면 분석의 원인 해석·추천의 구체성·과제 난이도 변경을 각각 점검한다. 현재 자료로 분석 AI의 교육 효과를 긍정/부정 판정하지 않는다.

변경은 로컬 개발 코드와 격리 테스트 백엔드에 반영했다. 학교 서버 배포/운영 모델 교체, Git 커밋·푸시는 하지 않았다.
