# 이동 로그 수집 v2

## 수집 방식

`frontend/src/behavior/movementLogReducer.ts`를 실시간 수집과 과거 기록 변환에서 함께 사용한다.
프레임 좌표는 축약기에 모두 전달하고, 근접/구간 이벤트 계산만 기존 250ms/12단위 기준으로 제한한다.

- 일정한 이동은 시간별 선형 보간 오차 0.5 게임 좌표 단위 이내에서 중간 샘플을 생략한다.
- 연속 관측의 보존점 간격은 최대 1초다. 원래 1초 넘게 관측이 없었다면 그 구간을 연결하지 않는다.
- 각 축의 방향 반전, 정지/재이동, 급격한 속도·방향 변화, 막힘·조작 방식 변경을 보존한다.
- 다른 행동 직전에 보류 좌표를 확정한다. 저장 타이머, 앱 백그라운드, 세션 종료에서도 보류 좌표를 저장한다.
- 생략 구간 끝에는 시작 시각, 관측 샘플 수, 관측 거리 합, 실제 최대 보간 오차를 `marketContent.movementSpan`으로 기록한다.
- `sampleCount`는 시작점 이후 구간 끝까지의 원본 샘플 수다. 행동 횟수나 충돌 횟수가 아니다.
- 연속 막힘은 `MOVEMENT_BLOCKED` 시작과 `MOVEMENT_UNBLOCKED` 종료/지속 시간으로 기록한다. 반복 막힘 수는 서로 분리된 막힘 시작 횟수다.

0.5는 수집 위치 오차 한도이지 능력 판정 기준이 아니다. 원본은 기존 수집기와 같은 소수 첫째 자리 좌표이며,
보간 오차는 이 좌표에 대해 계산한다. 새 수집기에서 생략한 프레임 좌표는 서버에 저장되지 않는다.

## 2026-09-07 로컬 플레이 변환

사용자가 요청한 최근 플레이 두 건을 저장된 v1 샘플로 재처리했다. 새 프레임이나 행동은 생성하지 않았다.

| 플레이 | 전체 이벤트 전→후 | 이동 이벤트 전→후 |
| --- | ---: | ---: |
| 9월 7일 23:01 플레이 | 108 → 81 | 71 → 44 (38.0% 감소) |
| 9월 5일 16:47 플레이 | 246 → 179 | 169 → 102 (39.6% 감소) |

비이동 사건과 남긴 좌표의 시각/위치/ID를 유지한다. 현재 로그의 순번과 stepOrder는 다시 연속 번호를 부여하고
세션 무결성도 갱신했다. 두 세션 모두 COMPLETE, 누락 0이다. SESSION_STARTED에 변환 출처를 기록한다.
좌표계 정보가 없던 옛 로그에 진열대 좌표 등을 새로 추정해서 넣지 않는다.

원본 로그 JSON, 적용 SQL, 변환 결과와 전체 DB 백업은 아래 Git 제외 디렉터리에 보관한다.

`.tools/movement-replay/2026-09-07T14-25-27-748Z/`

기존 분석 입력 스냅샷 JSON과 실패 분석 기록은 당시 입력을 보존하기 위해 수정하지 않는다.
삭제한 이동 행의 정규화 데이터와 관계 링크는 FK cascade에 따라 제거되며, 원본 DB 백업에 함께 보존된다.
다음 세션 분석은 변경된 로그 ID 집합/개수를 기준으로 새 입력 스냅샷을 생성한다.
이 작업에서 외부 AI 재분석은 실행하지 않았다. 최종 통합 입력 한도 초과 문제는 별도 수정이 필요하다.

## 유지보수 도구

`node scripts/replay-movement-logs.mjs <session UUID> ...`는 미리보기만 생성한다.
`--apply`를 추가하면 DB 백업 후 하나의 트랜잭션으로 적용한다. 적용 시 서버를 중지하여 진행 중 분석/정규화와 충돌하지 않게 한다.
명시된 완료 세션만 처리하고, 순번 누락·이미 변환된 세션·별도 검토가 필요한 과거 막힘 이벤트는 거부한다.
변환 전후 원본 행 대조와 모든 생략 좌표의 오차 검증을 수행한다.

## 검증

- 프론트 13개 테스트: 일정 직진, 짧은 왕복, 꺾임, 정지/속도 변화, 막힘/조작 전환, 시각 역전/누락,
  무작위 곡선 오차, 상호작용/저장/백그라운드/종료 시 보류 좌표 보존과 순번 연속성.
- TypeScript 검사 통과.
- 백엔드 이벤트 레지스트리 및 정규화 파이프라인 테스트 통과. 막힘 종료가 새 충돌로 집계되지 않는지 검사.
- 실제 변환 데이터의 이벤트 수, 보간 오차, 세션 무결성 확인.

로그 감소율은 위 두 플레이에서의 결과다. AI 처리 시간과 판단 품질 개선 비율을 뜻하지 않는다.
