# 이동 근거 보존과 AI 입력 최적화

## 적용 결과

기본값은 모든 원본 위치점·시각을 전달하는 무손실 모드다. 초기 관측 요청에도 `LosslessEventColumns`를 적용하여 반복 속성을 한 번만 표현한다. UUID 별칭 변환을 먼저 수행하므로 열/접두어 압축 후에도 실제 사건 ID를 정확히 복원한다. 표현 후보는 Qwen 토크나이저로 비교하여 더 작은 것을 선택한다.

이벤트 수를 절반씩 나누던 분할에는 상호작용 경계 우선과 인접 구간 재결합을 추가했다. 요청 한도에 맞지 않으면 더 나누며 어떤 사건도 잘라내지 않는다. 단일 사건 자체가 한도를 넘는 경우는 기존처럼 명시적으로 실패한다.

## 경로 축약 모드

`AI_MOVEMENT_MAX_ERROR=0`이 기본이며 이때 모든 위치점이 유지된다. 양수는 게임 내부 좌표 단위의 허용 오차이며, 제품 검토를 통해 결정한 값만 설정한다. 픽셀 수나 축약 목표 비율을 임의로 기본값으로 지정하지 않았다.

새 수집기가 기록한 `movementContext`가 있고 좌표계가 명확한 연속 이동 이벤트만 대상이다. 과거 기록처럼 좌표계 정보가 없는 경우 전체 좌표를 전달한다.

- 일반 행동 사건은 모두 유지한다. 해당 사건 앞뒤 이동은 구간 경계가 되어 남는다.
- 지원/오류/안전/유효성/종료 정보가 있는 사건, 첫 행동, 막힘, 진열대 반경과 오차 여유폭 내 좌표는 축약하지 않는다.
- 순번 누락, 1초 초과 관측 간격, 시각 역전, 환경·조작 방식 변경에서 구간을 나눈다. 1초는 능력 판정 기준이 아니라 보수적인 구간 분리 기준이다.
- 정지와 각 축의 방향 반전은 크기에 관계없이 보호한다.
- 생략한 관측점의 원래 시각에서 보간한 위치와 원래 위치 사이의 오차를 검사한다. 단순한 직선 거리만 검사하지 않는다.
- 축약 선분이 새로 진열대 영역을 통과할 우려가 있으면 해당 구간은 원본으로 되돌린다.
- 원본 관측점 거리 합, 시각 범위, 유지 이벤트 ID, 샘플 수, 최대 시간별 위치 오차와 공간 오차 상한을 프롬프트에 기록한다.

정확한 원본 이벤트 목록은 `MovementProjection.Segment.sourceEventIds`에 유지한다. 원본 스냅샷과 버전·오차 설정으로 재구성할 수 있다. 현재 별도의 구간 DB 테이블은 만들지 않고 기존 스냅샷/분석 시도/체크포인트 저장을 이용한다.

## 원본 추가 확인

부분 분석 JSON에 선택 필드 `requestedSegmentIds`를 추가했다. 구간 ID는 첫 원본 이벤트 UUID에 대응하는 짧은 E 별칭이다. 요청은 현재 투영에서 실제 축약된 구간만 최대 8개 허용한다. 다른 데이터셋/세션 또는 존재하지 않는 구간은 거부한다.

요청된 구간의 모든 원본 이벤트를 복원하여 한 번 더 관측한다. 추가 요청의 입력/출력 토큰과 전체 호출 예산을 검사한다. 추가 요청에서 재귀 요청은 허용하지 않는다. 예산 부족 시 확인하지 못한 해석을 확정하지 않고 관측을 비우고 불확실성을 기록한다.

근거 이벤트는 해당 요청에 실제 전달한 사건만 허용한다. 최종 통합에서도 실제 제공한 원문 근거 ID인지 검사한다. 축약/추가 확인 제한이 있으면 최종 결과의 `uncertainties`에 안내를 추가하고 기존 분석 탭의 ‘아직 알 수 없는 부분’에 표시한다. 이 안내는 의료/능력 판정이 아닌 데이터 처리 범위다.

## 캐시와 실행

프롬프트 버전은 `behavior-analysis-v11-movement`다. 압축·투영 버전과 오차 설정을 재사용 키에 포함하여 이전 방식의 완료 결과를 새 방식으로 오인하지 않는다. 체크포인트는 실제 요청 프롬프트 단위로 기존 검증을 거쳐 재사용한다.

백엔드를 같은 환경변수가 설정된 터미널에서 재시작하면 기본 무손실 최적화가 적용된다.

```sh
./gradlew bootRun --args='--spring.profiles.active=local'
```

프론트 변경은 JavaScript이므로 Metro 새로고침으로 반영된다. APK 재빌드나 DB 마이그레이션은 필요 없다. 실행 중인 서버를 이번 수정 작업에서 자동 재시작하지 않았다.

분당 토큰 제한 및 약 61초의 대기 정책은 유지한다. 화면 진행률을 위한 영속 백그라운드 작업 API는 이번 입력 최적화에 포함하지 않는다. 서버 로그에는 구간 번호/전체 구간 수, 원본/전달 사건 수, 축약 구간 수를 출력한다.

## 검증과 실제 측정

2026-09-07 로컬에 이미 저장된 **228개 이벤트 스냅샷**으로 외부 AI 호출 없이 측정했다. 이전 대화의 467개 이벤트 스냅샷과 다른 자료이므로 결과를 혼동하지 않는다.

| 측정 항목 | 기존 별칭+혼합 배열 | 무손실 열 압축+구간 결합 |
| --- | ---: | ---: |
| 전체 사용자 입력 토큰 | 43,711 | 27,464 |
| 7,000토큰 요청 예산의 관측 구간 | 17 | 10 |
| 원본 이벤트 | 228 | 228 |

전체 사용자 입력 토큰 약 37.2%, 관측 구간 수 약 41.2% 감소했다. 최종 통합/재시도 호출은 표에 포함하지 않는다. 전체 입력 토큰은 분할 요청들의 총 토큰과 다르다. 실제 소요 시간 및 모델 판단 품질이 같은 비율로 개선됐다는 뜻은 아니다.

벤치마크는 원본 시각/순서/좌표/막힘/조작 방식을 복원해 비교한다. 별도의 무손실 인코더 테스트는 누락/null/0/false/빈 값/문자열 정밀도를 검사한다. 경로 테스트는 직선·속도 변화·멈춤·작은 왕복·무작위 경로·시간 역전·상호작용·누락·진열대 주변을 다룬다. 모의 공급자 테스트로 원본 추가 조회와 미제공 근거 거부를 검증한다.

오프라인 재현은 원본 `BehaviorAnalysisInput` JSON 파일 경로를 지정한다. 원문은 콘솔에 출력하지 않는다.

```sh
MOVEMENT_BENCHMARK_SNAPSHOT=/absolute/path/snapshot.json ./gradlew test --tests '*MovementInputBenchmarkTest'
```

실제 AI 결과의 관찰 누락/오판 여부와 원본 경로 재생에 대한 사람의 비교 검토는 아직 수행하지 않았다. 따라서 경로 축약은 기본 비활성 상태로 제공한다. 장애물 경계 전체에 대한 기하학적 보존 증명과 앱의 실시간 진행률 표시는 별도 확장 사항이다.
