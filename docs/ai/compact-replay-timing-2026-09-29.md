# 시뮬레이터 빠른 재생 시간 설정

## 변경 목적과 범위

기존 10분 29초 플레이는 행동 전 대기에 약 6분 33초, 이동에 약 3분 25초를 사용했다. 특히 이동 96단계마다 대기가 반복됐다. 사용자의 요청에 따라 일반적인 시험을 약 3~5분 내로 줄이는 `compact` 모드를 기본값으로 추가했다.

- 연속된 이동 단계 앞의 반응 대기: 0ms
- 이동을 새로 시작할 때의 반응 대기: 최대 350ms
- 나머지 행동 전 반응 대기: 최대 1,500ms
- 이동 속도: 기본 걷기 속도의 최소 75% (기존 시험은 50%)
- 실제 읽기·관찰·드래그 동작 시간은 유지한다.

전체 행동 계획을 먼저 생성한 후 시간 설정만 변환한다. 경로, 행동 순서, 상품 ID/수량, 도움 요청, 구매 오류, 포기 여부, 난수 시퀀스와 계획 기억을 바꾸지 않는다. 로그 timestamp는 실제 앱 실행 시각이며 사후 축소하지 않는다. 무조건 5분에 종료하거나 짧은 과제에 대기를 추가하지 않는다.

`generateTrace`와 CLI/MCP `generate_trace`의 기본값은 compact다. 기존 조건은 `timingProfile: original`로 재현한다. 저장된 기존 trace는 그대로다. 새 trace에는 `generation.timingProfile: compact-v1`, `sourceTraceId`를 남기고 새 ID/hash를 부여한다. 실제 사람의 인지 속도를 재현하는 설정이 아니므로 이전 속도와의 시간 차이를 학습 효과로 판단하지 않는다.

## 검증

- 생성/스키마/서버/경험 이월 관련 테스트 34개 통과.
- 시뮬레이터 TypeScript 검사 통과.
- 과거 완료 7개 계획을 변환하여 행동 동일성 및 실제 공통 검증기 통과 확인.
- 과거 실행 시간에서 이동 속도 비율과 대기 차이를 대입한 추정: 약 1분 49초~4분 45초. 이는 재실행 실측이 아니며 네트워크 대기와 런타임 차이는 보장하지 않는다.
- 이번 실제 재생은 기존 122단계 계획과 같은 snapshot을 사용한다. 구매 정답을 맞추도록 수정하지 않았다.
- 첫 재생 요청은 개발 서버가 이전 JSON 스키마를 제공해 step 0에서 거절됐다. 실패 기록을 보존하고 개발 서버 캐시를 갱신한 뒤 같은 trace로 재시험했다.

증거 경로: `output/compact-timing-20260929/`. `*.private.json`은 연결 정보이므로 공유 대상이 아니다.

## 실제 앱 재생 결과

**10분 29초 → 3분 31초**, 약 66.4% 단축했다.

| 항목 | 기존 | 빠른 모드 실측 |
|---|---:|---:|
| 전체 재생 | 628.879초 | 211.160초 |
| 행동 단계 | 122 | 122 |
| 이동 단계 | 96 | 96 |
| 실제 구매 | 우유 1개 + 낱개 바나나 1개 | 동일 |
| 금액 | 3,200원 | 3,200원 |
| 실제 수집 로그 | 6,829개 | 4,889개 |

같은 seed의 같은 전체 행동 계획을 사용했고, 단위가 틀린 바나나 구매도 유지됐다. 빠르게 성공하도록 행동을 바꾼 결과가 아니다. 4,889개 로그의 순번/이벤트 ID는 중복 없이 연속이며 종료 이벤트 1개, 시간 역전 0, 이동·입력 위반 0이다. 로그 개수 차이는 실제 재생 속도와 런타임 수집에서 발생했다. 원본 로그를 삭제하거나 시간을 사후 수정하지 않았다.

실제 재생은 한 사례를 검증했다. 모든 미래 과제가 반드시 5분 내 완료된다는 보장은 아니다. AI 분석 worker는 꺼진 상태를 유지했고 새 분석은 호출하지 않았다. 앱에서 분석 접수까지는 기록되어 해당 시험 작업은 QUEUED다.
