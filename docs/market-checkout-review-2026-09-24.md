# 장보기: 계산 내역 확인과 수량 정정 요청

2026-09-24 / 8번 프론트엔드 브랜치

## 사용자가 하는 일

유인 계산대에서 상품별 수량과 금액을 확인하고, 실제 담은 물건과 다르면 계산원에게 확인을 요청합니다. 예를 들어 우유를 두 개 담았는데 계산 내역에는 세 개로 찍힌 상황입니다.

1. 계산원이 있는 계산대에 접근해 POS의 계산 내역을 엽니다. 상품명·단가·수량·금액이 열로 정렬되고 아래에 합계금액이 고정됩니다.
2. **장바구니 확인**으로 실제 담은 물건과 수량을 살펴봅니다.
3. 확인할 **상품 줄을 바로 누릅니다**. **개수가 잘못된 것 같아요**에서 상품을 선택하는 방법도 있습니다.
4. 실제 담은 수량을 −/+로 정하고 **확인 부탁드려요**를 누릅니다.
5. 계산원의 답변 후 **계산 내역 다시 보기**로 돌아가 수정된 수량·금액을 확인하고 **이대로 결제하기**를 누릅니다.

유인 계산대는 사용자가 제공한 한국 마트 POS 사진과 [이노페이 마트POS 공식 화면](https://web.innopay.co.kr/martpos/)을 참고해 파란 제목 표시줄, 회청색 상품 표, 노란 선택 행, 짙은 회색 바탕의 큰 노란 합계 숫자로 구성했습니다. 숫자와 상품명은 실제 게임 데이터로 표시합니다. 노란 행은 마지막으로 표시되거나 선택된 상품이며, 계산 오류 여부를 나타내지 않습니다.

**이대로 결제하기**와 **다시 고르기**는 같은 크기의 큰 버튼입니다. 계산 화면의 **그만두기**는 제거했습니다. 다시 고르기는 결제를 취소하고 장보기를 계속하는 기능입니다. 상품 줄에서 들어온 수량 확인 화면은 뒤로가기를 누르면 POS로 바로 돌아갑니다. 장바구니를 확인하고 돌아와도 선택한 상품과 수량이 유지됩니다. 짧은 화면은 머리글과 합계 영역을 줄이고 상품 목록을 스크롤하며, 결제 금액과 버튼은 고정합니다.

기존의 둥근 초록 모니터 테두리·크림 화면·받침·나무색 상판은 **키오스크**로 이전했습니다. 상품은 큰 그림을 중심으로 가로로 나열합니다. 그림을 스캐너로 끌어오거나 상품명 버튼을 눌러 한 개씩 스캔하고, 화면 확인 후 결제합니다. 그림 모서리의 숫자는 아직 스캔하지 않은 수량입니다. 상품명·목록의 빈 공간을 좌우로 밀면 가로 목록을 넘길 수 있습니다.

스캔·결제 확인·다시 스캔 단계에서 모니터와 아래 상판의 크기·위치를 동일하게 유지합니다. 화면 크기가 작은 기기에서는 전체 비율을 줄이고 받침을 숨깁니다. 모바일에서는 상품 그림에 손가락이 닿는 순간 드래그 입력을 확보하고 목록 스크롤을 잠급니다. 모바일 웹은 포인터 캡처와 그림 영역의 기본 터치 스크롤 방지를 사용하며, 취소·종료 시 입력과 스크롤을 복원합니다.

결과 화면의 난이도·흥미 별점은 제목·별·설명을 가운데 정렬합니다. 미선택 별은 배경보다 약간 어두운 베이지색의 채운 별, 선택한 별은 기존 금색입니다. 평가 저장과 건너뛰기 동작은 동일합니다.

화면 예시: [유인 POS](images/market-checkout-pos/pos-mobile.png), [키오스크](images/market-checkout-pos/kiosk-mobile.png), [상품 수량 확인](images/market-checkout-pos/quantity-mobile.png). 예시는 별도 테스트 장바구니를 사용해 실제 컴포넌트를 렌더링한 결과입니다.

맞는 수량을 말하면 해당 상품의 청구 수량만 바로잡습니다. 다른 수량을 말하면 다시 확인해 달라는 답변이 나오며 내역은 그대로입니다. 정상적으로 계산된 상품을 확인해 달라고 요청해도 감점하지 않습니다. 수량 입력의 시작값은 항상 1이며, 실제 수량을 자동으로 채워주지 않습니다.

## 테스트와 환경 설정

마트 시작 화면의 **연습 환경 설정 → 계산 내역 확인 연습**에서 선택합니다.

| 설정 | 동작 |
| --- | --- |
| 항상 정상 계산 | 실제 장바구니 수량대로 계산합니다. |
| 계산 실수 있음 | 비어 있지 않은 장바구니에서 상품 하나가 한 개 더 찍힙니다. |
| 계산 실수 랜덤 | 정상 또는 추가 청구를 각각 50% 확률로 결정합니다. |

일반 UI에서 새로 시작하는 게임은 랜덤입니다. 기존 JSON 설정은 이 항목을 생략하면 정상 계산을 유지합니다. 실수를 확실하게 시험하려면 **계산 실수 있음**을 선택하고 유인 계산대를 이용합니다. 계산원이 없다면 기존 직원 호출 기능으로 요청할 수 있습니다.

기존 환경 JSON의 `learning` 객체에 다음 필드를 추가하면 됩니다.

```json
{
  "learning": {
    "checkoutReviewMode": "overcharge"
  }
}
```

가능한 값은 `normal`, `overcharge`, `random`입니다. 동일한 시드와 동일한 장바구니에서는 같은 계산 내역이 생성됩니다. 계산대를 옮기거나 실패 후 재시도해도 같은 장바구니의 내역과 이미 끝낸 정정을 유지합니다. 물건을 추가하거나 돌려놓아 장바구니가 바뀌면 다음 계산 때 새 내역을 만듭니다.

## 성공 판단과 기존 기능

- 계산원 실수가 있어도 구매 확정 버튼을 사용할 수 있습니다. 틀린 상품을 미리 강조하거나 정정 요청을 강제하지 않습니다.
- 첫 구매 확정 실패에는 일반 안내만, 두 번째부터는 구체적인 차이를 알려줍니다. 재시도와 포기를 유지합니다.
- 최종 성공에는 사야 할 품목·수량·예산 충족과 정확한 계산 내역이 모두 필요합니다.
- 정정 요청 자체는 구매 시도 횟수를 늘리지 않습니다. 장바구니, 진열대 재고, 부탁 목록도 바꾸지 않습니다.
- 정정은 실제 담은 수량을 기준으로 합니다. 두 개를 부탁받았는데 세 개를 담았다면, 계산 내역을 세 개로 정정해도 장보기 과제는 실패합니다.
- 무인 계산대에는 이 실수를 주입하지 않습니다. 기존 스캔·확인·결제 흐름을 유지합니다.
- 계산 내역에는 청구 총액을 표시하며, 별도로 여는 장바구니에는 자동 총액을 추가하지 않았습니다.

## 정우·재현 전달: 기록과 AI 연동

새 행동은 `viewCheckoutCart`와 `requestCheckoutCorrection`입니다. 정정 요청에는 `productId`와 정수 `quantity`(1~99)를 전달합니다. 실제 유인 계산대에서 계산원이 있고 계산 내역을 연 상태에서만 허용됩니다.

관찰의 `checkoutReview`에는 청구 목록 `chargedCart`, 청구 총액 `total`, 계산원 답변 `response`만 제공합니다. 어느 상품에 오류를 주입했는지 나타내는 `injectedError`는 에피소드 내보내기의 감사용 정보입니다.

| 이벤트 | 기록 내용 |
| --- | --- |
| `checkout_bill_generated` | 최초 청구 내역과 시스템이 넣은 오류 |
| `checkout_cart_viewed` | 계산 중 장바구니 확인 행동 |
| `checkout_correction_requested` | 선택한 상품, 주장한 수량, 이전 청구 수량 |
| `checkout_bill_corrected` / `checkout_bill_rechecked` | 실제 수량과 일치했는지, 수정했는지, 응답과 내역 |
| `checkout_bill_invalidated` | 장바구니 변경으로 이전 내역 무효화 |
| `checkout_review_submitted` | 계산 내역의 정확성, 장보기 충족 여부, 최종 성공 여부 |

`purchase_submitted.evaluation`은 기존의 구매 목록 평가를 유지합니다. 계산 정확성은 `checkoutReviewEvaluation`, 최종 성공은 `purchaseSuccess`로 추가 기록합니다. 계산원 실수에는 `origin: system-cashier`를 기록하므로 사용자에게서 비롯된 상품 선택 오류와 구분할 수 있습니다.

현재 AI 관찰의 실제 `cart`는 기존 설계대로 계산 단계에서도 제공됩니다. 사람 UI는 별도 장바구니 확인 버튼을 사용합니다. 따라서 사람과 AI의 ‘장바구니를 열어 본 횟수’를 직접 비교할 때는 이 정보 제공 방식의 차이를 고려해야 합니다.

## 구현과 검증

- 상태·판정: `frontend/src/game/marketCheckoutReview.ts`, `marketSession.ts`, `marketLearning.ts`
- 화면: `frontend/src/components/game/MarketStaffedCheckout.tsx`, `MarketKioskCheckout.tsx`, `MarketSetupPanel.tsx`, `frontend/src/screens/MarketSimulationScreen.tsx`
- 확인 항목: 정상·오청구·잘못된 정정·정상 상품 재확인·시드 재현·재시도 유지·장바구니 변경·잘못된 호출 거부·기록 분리·무인 계산대 유지·화면 뒤로가기.
- 기존 마을 대화의 애니메이션과 비프음을 재사용하며, 모션 감소 설정과 테스트용 `muteAudio=1`을 유지합니다.
- POS·키오스크 변경 검증: 유인 POS·마트 화면 통합·키오스크 UI·키오스크 환경 4개 테스트 파일의 64개 테스트 통과, 타입 검사·웹 빌드 통과. 별도 브라우저 테스트에서 모바일 375×667, 상단 44px/하단 34px 안전 여백을 적용한 375×480의 12종 상품 목록, 태블릿 768×1024를 확인했습니다. 두 결정 버튼의 같은 크기·포기 제거·상품 직접 선택 → 장바구니 확인 → 수량 정정 → 결제, 키오스크의 실제 마우스 드래그 스캔 → 버튼 스캔 → 화면 확인 → 결제, 긴 목록 스크롤을 확인했습니다. 휴대폰 Expo Go 실기기 터치 검증은 별도입니다.
- 별점·모바일 드래그 후속 변경: 마트 화면 통합 36개와 키오스크 UI·환경 12개 테스트 통과. 타입 검사·웹 빌드 통과. Chromium 모바일 터치 입력으로 스캔·취소·가로 스크롤·결제를 확인하고, 각 단계에서 모니터·상판·스캐너의 실제 좌표와 크기가 같은지 비교했습니다. 375×480 안전 여백 화면, 375×667 모바일, 768×1024 태블릿을 캡처하고 별점 중앙 정렬·선택 색상을 확인했습니다. Expo Go 실기기에서의 직접 터치 검증은 수행하지 않았습니다.
