# 마트 실행 에셋 로딩 최적화

2026-09-13. 앱 진입과 장보기 화면에서 내려받는 이미지·음원의 용량을 줄였다. 첫 화면 글꼴, 캐릭터 프레임 요청, 개발용 무음 처리도 조정하고 Expo 서버를 재시작했다. 아래 시간은 로컬 개발 환경의 관측이며 휴대폰 LTE 성능을 뜻하지 않는다.

## 변경 규모

| 대상 | 이전 전송 파일 합계 | 변경 후 | 절감 |
| --- | ---: | ---: | ---: |
| 상품 상세 PNG 120개 | 51,691,584바이트 | 16,665,189바이트 | 67.8% |
| NPC PNG 16개 | 1,672,679바이트 | 1,435,965바이트 | 14.2% |
| 배경음악 apple-cider | 35,251,380바이트 | 3,350,934바이트 | 90.5% |

이미지 두 종류 합계는 53,364,263 → 18,101,154바이트다. 상품 이미지를 모두 디코딩할 경우 RGBA 메모리 합계도 251,624,832 → 70,778,880바이트로 줄었다. 모든 파일이 첫 화면에서 동시에 다운로드된다는 뜻은 아니다.

## 첫 화면과 캐릭터 로딩

- 웹 글꼴 11개를 같은 글리프·윤곽·메트릭을 보존한 WOFF2로 변환했다. 19,418,688 → 7,449,340바이트(61.64% 감소). 네이티브 앱은 원래 OTF/TTF와 같은 폰트 이름을 사용한다.
- 온보딩에서 실제 사용하는 세 글꼴만 먼저 기다린다. 웹의 첫 화면 대기 대상은 1,314,268바이트로 기존 전체 글꼴 대비93.23% 감소했다. 첫 화면이 그려진 뒤 나머지를 준비하고, 홈·마트는 필요한 글꼴 준비 이후 표시해 서체가 바뀌는 현상을 피한다.
- 로딩이 실패하거나 지연되면 재시도 버튼을 제공한다. 폰트를 다른 서체로 대체하지 않는다.
- 플레이어의 80개 애니메이션 이미지를 동시에 마운트하던 구조를 현재 방향·동작의2개(대기) 또는8개(걷기)로 줄였다. 애니메이션 프레임 간격과 이동 규칙은 유지한다.
- 무음 미리보기인 muteAudio=1에서는 배경음악과 대화음 네 개의 오디오 소스를 null로 전달한다. 재생뿐 아니라 파일 다운로드·디코딩도 시작하지 않는다.

## 이미지 경로와 원본 보존

- 실행용 상품: `frontend/assets/images/game/market/products/runtime/product_*.png` 120장, 모두 384×384. 전체 정사각형 캔버스를 균일 축소한 뒤 무손실 PNG로 인코딩했다. 크롭, 배경 제거, 색상 팔레트 양자화, 그림 재생성은 하지 않았다.
- 원본 상품: 기존 `frontend/assets/images/game/market/products/product_*.png`에 그대로 보관한다. `frontend/src/game/marketProductImages.ts`의 120개 정적 require만 runtime 폴더를 참조한다. 상품 ID·API·시드 재고 데이터는 유지한다.
- 상세 상품은 `MarketShelfScene`에서 최대 156 논리 픽셀, 드래그 미리보기는 96픽셀로 표시한다. 384픽셀은 최대 상세 크기의 2배 이상이며 모바일의 더 작은 표시 크기도 지원한다. 네이티브와 웹 모두 명시한 width/height 및 contain을 사용하므로 PNG 메타데이터의 384픽셀이 게임 좌표나 터치 영역으로 전환되지 않는다. 캔버스 비율과 내부 여백도 유지한다.
- 맵용 128×128 상품 썸네일과 상품 배치 메타데이터는 변경하지 않았다.
- NPC는 기존 `people/*-v1.png` 16장을 256×512 그대로 무손실 재압축했다. 원본과 디코딩한 모든 RGBA 픽셀이 동일하다. 외형 크기·신발 좌표·콜리전 메타데이터를 바꿀 필요가 없다. 고해상도 `people/illustrations/`도 보존했다.

## 배경음악

- 원본 `frontend/assets/audio/apple-cider.wav` 보존.
- 실행용 `frontend/assets/audio/apple-cider.m4a`: AAC-LC, 목표 128kbps, 44.1kHz, 스테레오.
- `GamePrototypeScreen.tsx`의 BGM require 경로만 바꿨다. 개발용 무음 조건, downloadFirst, loop, 볼륨과 오디오 처리 로직은 유지한다.
- 원본 길이 199.837505669초, MP4 표시 길이 199.838초로 차이는 1ms 미만이다. AAC 인코더 지연을 보정하는 MP4 edit list가 있고 moov 헤더를 앞에 둬서 스트리밍 시작을 돕는다.
- 임시 폴더에 설치한 imageio-ffmpeg만 변환에 사용했다. 프로젝트 의존성·잠금 파일은 변경하지 않았다.

## 검증

- 상품 120개 정적 경로와 파일 존재 확인.
- 상품 전체의 크기·투명도·축소 후 PNG 재인코딩 픽셀 일치 확인.
- NPC 16개 모든 RGBA 픽셀의 원본 일치 확인.
- 대표 상품 이미지 시각 검수 완료.
- 변환 AAC 전체를 소리 출력 없이 FFmpeg로 디코딩해 오류 없음 확인. MP4 코덱·시간 정보·앞쪽 moov 확인.
- 실제 브라우저에서 일반 앱의 로그인→홈 진입과 마트 이미지 전체 표시를 확인했다. 테스트 URL은 모두 muteAudio=1로 실행했다.
- 기존 Expo 프로세스에서 /status 응답은 1.6~9.2초, 캐시된 웹 번들 응답은 약14초였다. 동일 프로젝트·캐시로 재시작 후 /status는4ms, 외부 Expo manifest는 약1.1초/HTTP200으로 확인했다. 지연된 프로세스의 세부 원인은 단정하지 않는다.
- 재시작 뒤 같은 브라우저의 일반 앱 새 탭은 관측3.3초 이내 로그인 화면이 표시됐고, 마트 탭은 재로드4.7초·7.1초 시점에 시작 화면이 보였다. 캐시를 비우고 측정한 정식 벤치마크는 아니며 휴대폰·회선별 시간은 다를 수 있다.
- 기기별 실제 로딩 시간과 AAC 반복 재생 청감 확인은 별도 검증 항목이다. 이번 작업은 스피커 출력을 사용하지 않았다.

## 후속 진단: localhost 지연의 실제 원인과 수정

사용자가 시간이 지나면 이미지가 나타난다고 알려 준 뒤, 이미지 크기 대신 실제 HTTP 응답 대기와 살아 있는 Expo 프로세스의 CPU를 측정했다.

- 마트 건물 PNG는664,995바이트다. 파일 직접 읽기·MD5는 약0.7~1.1ms, Metro의 getAsset 함수 직접 실행은0.4~3ms였다. PNG 디코딩도 정상이다.
- 같은 이미지의 HTTP 첫 응답 대기는3,926ms였고 전송 완료는3,927ms였다. 다른 동시 측정에서는9,815ms까지 기다렸다. 파일 전송 속도보다 서버가 요청을 처리하기까지의 대기가 문제였다.
- Expo 프로세스 CPU 프로파일10.36초 중 FallbackWatcher의 unregisterDir6.466초, processChange2.152초가 관측됐다. 약83%가 파일 변경 감시 처리에 쓰였다.
- 디버거로 감시 대상 경로를 한 번 확인했다. 빌드 결과인 frontend/dist/assets/... 아래 Windows 확장 절대 경로 알림을 기존 감시 디렉터리와 다시 합친 잘못된 경로가 들어왔다. lstat 실패 후 등록된18,977개 디렉터리 목록을 훑는 코드로 진행했다. 감시 처리와 HTTP 응답이 같은 Node 이벤트 루프를 사용해 이미지·상태 요청이 밀렸다.

frontend/metro.config.js에서 프로젝트 루트의 dist만 resolver.blockList에 추가했다. Windows/POSIX 절대 경로 및 상대 경로를 모두 처리한다. src, 원본 assets, node_modules 패키지 내부 dist, 기존 기본 제외 규칙과 WOFF2 설정은 유지했다. 설치된 Expo 코드나 게임 그림을 추가로 수정하지 않았다.

검증:

- scripts/check-metro-watch-boundaries.test.cjs:3개 검사 통과.
- dist 아래 별도 임시 디렉터리에 파일300개를 생성·삭제한 뒤4회 측정: 마트 PNG 첫 응답1~2ms, 전체 수신2~3ms. 테스트가 만든 파일만 정리했다.
- 실제 Expo 웹 export 통과 후 같은665KB 이미지3회 측정: 전체 수신14ms,2ms,1ms. 재빌드 뒤에도 수 초 단위 지연이 재현되지 않았다.
- 현재 서버로 외부 manifest HTTP200, SDK57 및 기존 Expo 계정 확인. 서버 실행 주소와 QR은 재생성했다.
- CPU 프로파일과 측정 원본은 로컬 frontend/.expo/slow-asset.cpuprofile, slow-asset-timing.json, watcher-fix-timing.json, watcher-fix-final-verification.json에 있다.

이전의 로컬 로그인 화면3초 관측만으로 전체 로딩 문제를 해결했다고 판단한 것은 충분하지 않았다. 앞서 수행한 폰트·이미지·음원 축소는 별도 최적화이며, 이번에 측정으로 확인한 수 초 지연의 직접 원인은 위 파일 감시 처리다.
