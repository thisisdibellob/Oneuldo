# 장보기 시뮬레이션 미세행동·이동 로그 설계

> 정규화 규칙: [2. 행동 로그 데이터 정규화](./2.행동_로그_데이터_정규화.md)  
> 프로파일 규칙: [3. 행동로그 근거자료 프로파일 설계](./3.행동로그_근거자료_프로파일_설계.md)  
> 적용 대상: 장보기 시뮬레이션의 계획, 이동, 탐색, 관찰, 선택, 수정, 결제 행동

## 1. 목적

이 문서는 장보기 시뮬레이션에서 사용자의 최종 성공 여부뿐 아니라 성공 또는 실패에 도달하기까지의 작은 행동 흐름을 수집하기 위한 이벤트 후보를 정의한다.

수집한 이벤트는 다음 목적으로 사용한다.

- 목록 이해, 공간 탐색, 상품 구별, 수량 조절, 예산 관리, 자기수정과 지원 활용 패턴을 관찰한다.
- 같은 최종 결과를 만든 서로 다른 수행 과정을 구분한다.
- 다음 장보기 시뮬레이션의 상품 수, 공간 복잡도, 유사 상품, 수량, 예산과 지원 방식을 조정할 근거를 만든다.
- 이후 다른 시뮬레이션에서도 세션, 전달, 오류, 지원, 유효성 처리를 공통으로 재사용한다.

이벤트는 관찰 가능한 사실만 표현한다. `집중력 부족`, `기억력 저하`, `길을 잃음`, `충동적 선택`처럼 원인을 단정하는 코드는 원본 이벤트에 사용하지 않는다.

## 2. 수집 구조

### 2.1 3단계 구조

```text
클라이언트 원시 상태
├── 캐릭터 좌표, 속도, 방향
├── 진열장·구역과의 거리
├── UI 열기·닫기·터치
└── 장바구니 상태 변경
        ↓
의미 이벤트
├── 목표 진열장 통과
├── 같은 진열장 재방문
├── 무관 구역 체류
├── 수량 초과 후 자기수정
└── 실패 후 관련 진열장 복귀
        ↓
세션·사용자 프로파일
├── 경로 효율
├── 목표 진열장 통과율
├── 재방문 간격
├── 독립 자기수정률
└── 지원 후 성공률
```

캐릭터 좌표를 매 프레임 서버로 전송하거나 LLM에 직접 전달하지 않는다. 클라이언트는 좌표를 짧은 간격으로 임시 관찰하고, 구역 전환과 이동 구간 요약 등 의미 있는 상태 변화만 행동 이벤트로 만든다.

### 2.2 공통 처리와 장보기 전용 처리

| 계층 | 책임 |
|---|---|
| 공통 `BehaviorTracker` | 세션 ID, 이벤트 ID, 순번, 발생시각, 로컬 큐, 재전송, 중복 방지, 앱 중단, 종료 처리 |
| 공통 이동 수집기 | 좌표 샘플링, 거리 누적, 정지·재개, 방향 변경, 충돌, 구역 진입·이탈 계산 |
| 장보기 행동 어댑터 | 목표 진열장, 남은 상품, 수량, 예산, 결제 상태를 사용한 의미 판정 |
| 서버 정규화 | 이벤트 코드와 payload 검증, 공통 행동·결과·오류·측정값 생성 |
| 프로파일 집계 | 여러 세션에서 반복되는 패턴과 지원 전후 변화를 계산 |

## 3. 이벤트 공통 필드

기존 `BehaviorLogRequest`의 공통 문맥을 유지하고 다음 연결 필드를 추가하는 것을 권장한다.

| 필드 | 타입 | 설명 |
|---|---|---|
| `clientEventId` | `UUID` | 재전송 중복 제거용 이벤트 ID |
| `sessionId` | `UUID` | 한 번의 장보기 수행 ID |
| `eventSequence` | `Long` | 세션 안에서 증가하는 순번 |
| `occurredAt` | `Instant` | 행동이 실제 발생한 시각 |
| `eventCode` | `String` | 관찰된 행동 코드 |
| `microActionId` | `String` | 수행 중인 세부 목표 또는 행동 ID |
| `phase` | `String` | `BRIEFING`, `SHOPPING`, `CHECKOUT`, `RESULT` |
| `visitId` | `UUID` | 한 번의 구역 또는 진열장 방문 묶음 |
| `searchEpisodeId` | `UUID` | 특정 목표 상품을 탐색한 과정 |
| `decisionEpisodeId` | `UUID` | 상품 관찰·비교·선택 과정 |
| `errorEpisodeId` | `UUID` | 오류 발생부터 해결·포기까지의 과정 |
| `supportEpisodeId` | `UUID` | 지원 제공부터 후속 행동까지의 과정 |
| `causedByEventId` | `UUID` | 현재 사건과 직접 연결되는 이전 사건 |
| `targetItemId` | `String` | 현재 탐색하거나 판단하는 목표 상품 |
| `zoneId` | `String` | 현재 구역 또는 진열장 ID |
| `remainingObjectiveCount` | `Integer` | 이벤트 시점에 남은 목표 종류 수 |
| `remainingUnitCount` | `Integer` | 이벤트 시점에 남은 총 수량 |
| `cartTotalAmount` | `Long` | 이벤트 시점의 장바구니 총액 |
| `remainingBudgetAmount` | `Long` | 이벤트 시점의 남은 예산 |
| `controlMode` | `ControllerMode` | 조이스틱, 터치, 스위치 등 실제 조작 방식 |
| `thresholdRuleVersion` | `String` | 통과·배회·정지 등을 판정한 규칙 버전 |

모든 이벤트에 모든 필드를 넣지는 않는다. 해당 행동을 해석하는 데 필요한 최소 문맥만 포함한다.

## 4. 세션·미션·목록 행동

| 이벤트 코드 | 수집 행동 | 주요 payload |
|---|---|---|
| `SHOP.SESSION_STARTED` | 실제 조작 가능한 장보기 화면 시작 | 목표 수, 예산, 난이도, 맵 버전 |
| `SHOP.SESSION_RESUMED` | 중단된 앱 또는 세션으로 복귀 | 중단시간, 복귀 단계 |
| `SHOP.MISSION_PRESENTED` | 미션 내용이 실제 화면에 노출 | 지시 콘텐츠 ID, 제시 방식 |
| `SHOP.BRIEFING_ADVANCED` | 안내를 다음 단계로 넘김 | 안내 순번, 열람시간 |
| `SHOP.BRIEFING_REOPENED` | 플레이 중 안내를 다시 확인 | 재확인 횟수, 직전 행동 |
| `SHOP.BRIEFING_SKIPPED` | 허용된 경우 안내를 건너뜀 | 건너뛴 단계 수 |
| `SHOP.LIST_OPENED` | 목록을 실제로 열거나 확대 | 열람 횟수, 남은 목표 수 |
| `SHOP.LIST_CLOSED` | 목록을 닫음 | 열람시간 |
| `SHOP.LIST_ITEM_FOCUSED` | 목록에서 특정 상품을 선택·강조 | 상품 ID, 목표 수량 |
| `SHOP.LIST_REOPENED_AFTER_ERROR` | 오류 이후 목록 재확인 | 오류 종류, 오류 이벤트 ID |
| `SHOP.LIST_REOPENED_AFTER_IDLE` | 긴 무행동 이후 목록 재확인 | 직전 무행동 시간 |
| `SHOP.LIST_REOPENED_BEFORE_CHECKOUT` | 계산대 접근 직전 목록 재확인 | 남은 목표 수, 현재 총액 |
| `SHOP.FIRST_MOVE_STARTED` | 지시 종료 후 첫 이동 시작 | 시작 지연시간 |
| `SHOP.FIRST_TARGET_APPROACH_STARTED` | 처음으로 특정 목표 구역 방향 이동 | 목표 상품·진열장 ID |
| `SHOP.OBJECTIVE_COMPLETED` | 특정 목표 상품과 수량을 충족 | 상품 ID, 충족까지 시간·행동 수 |
| `SHOP.ALL_OBJECTIVES_COMPLETED` | 모든 목표 상품과 수량을 충족 | 총 수행시간, 총 행동 수 |

## 5. 기본 이동·조작 행동

| 이벤트 코드 | 수집 행동 | 주요 payload |
|---|---|---|
| `SHOP.MOVEMENT_STARTED` | 정지 상태에서 이동 시작 | 시작 좌표 구역, 이동 방식 |
| `SHOP.MOVEMENT_STOPPED` | 이동하다 정지 | 이동시간, 이동거리, 종료 구역 |
| `SHOP.MOVEMENT_SEGMENT_SUMMARIZED` | 한 방향 또는 한 구역 안의 이동 구간 종료 | 거리, 시간, 시작·종료 구역, 평균속도 |
| `SHOP.DESTINATION_SELECTED` | 터치 이동 목적지 선택 | 목적지 구역, 목표 관련 여부 |
| `SHOP.DESTINATION_CHANGED` | 도착 전에 다른 목적지 선택 | 이전·새 목적지, 변경까지 시간 |
| `SHOP.DESTINATION_CANCELLED` | 목적지 이동 취소 | 취소 위치, 이동거리 |
| `SHOP.CONTROL_MODE_CHANGED` | 조이스틱·터치 이동 방식 전환 | 이전·변경 후 방식 |
| `SHOP.MOVEMENT_SPEED_CHANGED` | 달리기 등 의도적인 속도 변경 | 이전·변경 후 속도 단계 |
| `SHOP.MOVEMENT_BLOCKED` | 장애물 때문에 이동하지 못함 | 장애물·구역 ID, 시도 방향 |
| `SHOP.MOVEMENT_BLOCKED_REPEATEDLY` | 짧은 시간에 같은 장애물 충돌 반복 | 충돌 횟수, 누적시간 |
| `SHOP.BOUNDARY_REACHED` | 맵 외곽에 도달해 이동 제한 | 경계 방향, 반복 횟수 |
| `SHOP.INVALID_DESTINATION_SELECTED` | 이동 불가능한 위치를 목적지로 선택 | 위치 유형, 재시도 여부 |
| `SHOP.DIRECTION_CHANGED` | 이동 방향을 크게 변경 | 변경 각도, 직전 방향 유지시간 |
| `SHOP.DIRECTION_CHANGED_REPEATEDLY` | 짧은 시간 안에 큰 방향 변경 반복 | 변경 횟수, 관찰 구간 |
| `SHOP.MOVEMENT_PAUSED_NEAR_OBSTACLE` | 장애물 근처에서 이동 중단 | 정지시간, 장애물 ID |
| `SHOP.MOVEMENT_RECOVERED_AFTER_BLOCK` | 충돌 후 이동 가능한 경로로 전환 | 회복시간, 추가 충돌 수 |
| `SHOP.ACCESSIBILITY_MOVE_ACTION_USED` | 접근성 이동 명령 사용 | 명령 종류, 이동 성공 여부 |

`MOVEMENT_BLOCKED_REPEATEDLY`, `INVALID_DESTINATION_SELECTED`는 공간 탐색 능력보다 조작 접근성 또는 UI 문제일 수 있으므로 기본적으로 능력점수에서 제외하고 유효성 문맥으로 사용한다.

## 6. 구역·진열장 접근과 통과

| 이벤트 코드 | 수집 행동 | 주요 payload |
|---|---|---|
| `SHOP.AREA_ENTERED` | 상품 구역에 진입 | 구역 ID, 이전 구역, 방문 순번 |
| `SHOP.AREA_EXITED` | 상품 구역에서 이탈 | 체류시간, 이동거리, 선택 수 |
| `SHOP.AREA_REVISITED` | 같은 상품 구역에 재진입 | 방문 순번, 이전 방문과의 간격 |
| `SHOP.SHELF_PROXIMITY_ENTERED` | 진열장 상호작용 반경 진입 | 진열장 ID, 최소 시작거리 |
| `SHOP.SHELF_PROXIMITY_EXITED` | 진열장 반경 이탈 | 근접시간, 최소거리, 열람 여부 |
| `SHOP.SHELF_APPROACH_ABORTED` | 진열장 방향으로 접근하다 반경 진입 전 이탈 | 최근접 거리, 방향 변경 위치 |
| `SHOP.TARGET_SHELF_APPROACHED` | 남은 목표 상품이 있는 진열장에 접근 | 진열장 ID, 관련 목표 목록 |
| `SHOP.TARGET_SHELF_PASSED` | 목표 진열장 근처를 지나갔지만 열지 않음 | 최소거리, 통과시간, 방문 순번 |
| `SHOP.TARGET_SHELF_REVISITED` | 목표 상품이 남은 상태로 같은 진열장 재방문 | 방문 순번, 재방문 간격 |
| `SHOP.TARGET_SHELF_LEFT_WITHOUT_SELECTION` | 목표 진열장을 열었지만 목표 상품 없이 이탈 | 노출 목표, 열람시간 |
| `SHOP.COMPLETED_SHELF_REVISITED` | 해당 구역 목표를 이미 충족한 뒤 재방문 | 충족 후 경과시간, 방문 횟수 |
| `SHOP.NON_TARGET_AREA_ENTERED` | 남은 목표가 없는 구역 진입 | 구역 ID, 남은 목표 구역 |
| `SHOP.NON_TARGET_AREA_EXITED` | 목표 없는 구역 이탈 | 체류시간, 이동거리, 상호작용 여부 |
| `SHOP.NON_TARGET_SHELF_OPENED` | 남은 목표가 없는 진열장 UI 열기 | 진열장 ID, 방문 순번 |
| `SHOP.NEAR_TARGET_HESITATION` | 목표 진열장 근처에서 이동·상호작용 없이 체류 | 체류시간, 목표까지 거리 |
| `SHOP.CHECKOUT_PROXIMITY_ENTERED` | 계산대 근처 진입 | 목표 충족 여부, 장바구니 총액 |
| `SHOP.EARLY_CHECKOUT_APPROACH` | 미완료 상태로 계산대 근처 진입 | 누락 목표, 예산 상태 |
| `SHOP.CHECKOUT_LEFT_WITHOUT_SUBMIT` | 계산대 접근 후 제출 없이 이탈 | 체류시간, 이탈 당시 상태 |

### 6.1 `TARGET_SHELF_PASSED` 권장 판정

다음 조건을 모두 만족할 때 한 건을 생성한다.

1. 해당 진열장에 아직 충족하지 못한 목표 상품이 있다.
2. 캐릭터가 진열장 근접 반경에 들어왔다가 나간다.
3. 근접 방문 동안 진열장 UI를 열지 않았다.
4. 최소 체류시간 또는 최소 통과거리를 충족한다.
5. 반경 경계 떨림으로 중복 생성되지 않도록 하나의 `visitId`로 묶는다.

근처를 지나간 사실만으로 사용자가 진열장을 보았다고 기록하지 않는다.

## 7. 경로·배회·되돌아감 행동

| 이벤트 코드 | 수집 행동 | 주요 payload |
|---|---|---|
| `SHOP.ROUTE_REVERSED` | 최근 이동경로를 일정 거리 이상 되돌아감 | 되돌아간 거리, 반전까지 시간 |
| `SHOP.BACKTRACK_STARTED` | 이전 방문 구역 방향으로 되돌아가기 시작 | 출발·목적 구역, 목표 관련 여부 |
| `SHOP.BACKTRACK_COMPLETED` | 이전 위치 또는 구역으로 복귀 | 되돌아간 거리·시간 |
| `SHOP.ROUTE_LOOP_DETECTED` | `A-B-A` 또는 `A-B-C-A` 형태의 순환 | 구역 순서, 순환거리·시간 |
| `SHOP.REPEATED_ROUTE_LOOP` | 유사한 순환 경로가 반복 | 반복 횟수, 누적거리 |
| `SHOP.REPEATED_ZONE_TRANSITION` | 같은 두 구역을 반복 왕복 | 구역 쌍, 왕복 횟수 |
| `SHOP.OFF_TARGET_MOVEMENT_STARTED` | 모든 남은 목표에서 멀어지는 이동 시작 | 기준 목표, 시작 거리 |
| `SHOP.OFF_TARGET_MOVEMENT_ENDED` | 목표와 멀어지는 이동 종료 | 지속시간, 이동거리 |
| `SHOP.OFF_TARGET_DWELL` | 남은 목표와 무관한 구역에서 장시간 체류 | 체류시간, 구역 ID |

### 7.1 배회 판정 원칙

`사용자가 맴돈다`는 단일 원본 이벤트로 단정하지 않는다. 서버는 다음 관찰값을 저장하고, 일정 구간이나 세션 요약에서 조합한다.

- 목표 없는 구역 체류 비율
- 목표까지 거리가 감소하지 않은 시간
- 실제 이동거리 대비 목표 진행량
- 순환 경로와 동일 구역 왕복 횟수
- 목표 진열장 통과·재방문 횟수
- 짧은 정지와 방향 전환 반복

이 중 하나만 발생한 경우에는 정상적인 탐색, 상품 비교, 조작 문제 또는 자유 탐색일 수 있다.

## 16. 이동 이벤트 판정 기준

### 16.1 좌표 샘플링

- 이동 중에만 200~500ms 간격 또는 일정 게임 거리 이상 변화했을 때 샘플링한다.
- 좌표는 게임 월드 내부 좌표이며 실제 위치정보를 수집하지 않는다.
- 서버 전송은 구역 전환, 방문 종료, 정지 종료처럼 의미 이벤트가 완성된 시점에 수행한다.
- 원시 경로가 디버깅에 필요하면 짧은 기간만 보관하고 LLM 입력에서는 제거한다.

### 16.2 경계 떨림 방지

진열장 반경 경계에서 `ENTERED`와 `EXITED`가 반복되지 않도록 서로 다른 진입·이탈 반경을 사용한다.

```text
진입 반경: interactionDistance 이하
이탈 반경: interactionDistance + hysteresis 이상
방문 병합: 이탈 후 mergeWindowMs 안에 재진입하면 동일 visitId
```

현재 장보기 화면의 `MARKET_INTERACTION_DISTANCE`는 105 게임 단위이지만, 분석 규칙은 화면 구현 상수가 아니라 버전이 있는 설정값으로 관리한다.

### 16.3 재방문

한 번의 방문은 `SHELF_PROXIMITY_ENTERED`부터 `SHELF_PROXIMITY_EXITED`까지로 본다. 병합 시간 이후 동일 진열장에 다시 진입하면 `SHELF_REVISITED`를 생성하고 다음 값을 저장한다.

- `visitIndex`
- `intervalSinceLastVisitMs`
- `previousVisitDurationMs`
- `previousShelfOpened`
- `previousSelectionMade`
- `objectiveStateChangedSinceLastVisit`

### 16.4 무행동과 맴돌기

- 무행동은 이동, 화면 조작, 상품 조작이 모두 없는 시간으로 계산한다.
- 앱 백그라운드 시간과 화면 잠금 시간은 무행동에서 제외한다.
- 무관 이동은 남은 목표 진열장과 거리가 증가하거나 목표가 없는 구역 안에서 발생한 구간으로 계산한다.
- 자유 탐색이 허용된 미션에서는 무관 이동을 능력 근거가 아닌 문맥으로만 사용한다.

### 16.5 경로 순환

- `A-B-A`와 `A-B-C-A` 같은 구역 시퀀스를 기본 후보로 탐지한다.
- 동일 구역 안의 작은 좌표 흔들림은 순환으로 보지 않는다.
- 최소 이동거리와 최소 지속시간을 충족해야 한다.
- 상품 선택, 목록 확인, 장바구니 수정처럼 진행을 만든 행동이 중간에 있으면 정상 재방문과 구분한다.

## 18. LLM 입력 권장 형태

LLM에는 원시 좌표와 전체 이벤트 배열을 기본 입력으로 전달하지 않는다. 서버가 결정적 규칙으로 계산한 요약과 반복 근거를 전달한다.

```json
{
  "shoppingBehavior": {
    "evidenceSessionCount": 5,
    "navigation": {
      "pathEfficiencyMedian": 0.58,
      "targetShelfPassRate": 0.32,
      "offTargetDurationRatioMedian": 0.24,
      "routeLoopSessions": 2,
      "blockedMovementRate": 0.03
    },
    "search": {
      "targetShelfRevisitRate": 0.41,
      "averageRevisitIntervalMs": 36000,
      "targetVisibleWithoutSelectionRate": 0.18
    },
    "selection": {
      "firstSelectionAccuracy": 0.78,
      "firstQuantityAccuracy": 0.52,
      "independentSelfCorrectionRate": 0.71
    },
    "support": {
      "hintRequestRate": 0.20,
      "hintFollowRate": 0.83,
      "laterIndependentCompletionRate": 0.60
    }
  }
}
```

서버는 최소 세션 수, 서로 다른 미션 수, 최근성, 제외율과 조작 유효성을 함께 제공한다. 단일 세션의 이동 패턴으로 사용자의 능력을 확정하지 않는다.

## 19. 패턴과 콘텐츠 조정 예시

| 반복 관찰 근거 | 다음 콘텐츠 조정 후보 | 해석 제한 |

| 피드백 후 관련 진열장 복귀가 안정적 | 결과를 직접 알려주기보다 오류 종류만 안내 | 수정 성공과 지원 수준을 함께 기록 |
| 특정 조작 방식에서만 충돌·무효 터치가 많음 | 조작 방식·터치 영역 조정 | 인지·공간 능력 근거에서 제외 |

- 조이스틱·터치 조작별 유효성 비교

## 21. 최소수집·해석 제한

- 실제 위치정보, 기기 고유 식별자, 자유 음성·대화 원문을 행동 로그에 저장하지 않는다.
- 게임 월드 좌표는 의미 이벤트 계산에 필요한 범위에서만 사용한다.
- 이동이 느리다는 이유만으로 실패 또는 낮은 능력으로 평가하지 않는다.
- 반복 방문은 기억 문제뿐 아니라 가격 비교, 확인 습관, UI 문제일 수 있다.
- 목표 진열장 통과는 진열장을 실제로 보지 못했다는 증거가 아니다.
- 무행동 시간은 앱 백그라운드, 기술 오류, 화면 로딩과 분리한다.
- 조작 실패와 렌더링 오류가 있는 세션은 평가 유효성을 낮추거나 제외한다.
- AI는 프로파일에 포함된 관찰 요약만 사용하고 원본 좌표에서 새로운 심리·의학적 의미를 추론하지 않는다.
- 임계값, 맵 구조와 이벤트 정의는 버전으로 관리하여 서로 다른 버전의 값을 그대로 비교하지 않는다.
