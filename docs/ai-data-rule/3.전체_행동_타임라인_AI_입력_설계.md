# 전체 행동 타임라인 AI 입력 설계

## 결론

백엔드가 성공률, 강점, 어려움 같은 사용자 프로파일을 미리 계산하지 않는다. AI에는 지정 기간의 **모든 원본 행동 로그**를 시간순으로 전달하고, 정규화 결과는 원본을 대체하지 않는 보조 정보로 붙인다.

현재 입력 스키마는 `behavior-analysis-input-v1`이다.

API 요청·응답 구조는 [4. 전체 행동 타임라인 API 계약](./4.전체_행동_타임라인_API_계약.md)을 따른다.

## 데이터 원칙

- `behavior_logs`에 저장된 이벤트는 우선순위, 결과, 정규화 성공 여부로 제외하지 않는다.
- 세션이 진행 중이거나 순번 누락 상태여도 이벤트를 포함한다.
- `NORMALIZED`, `QUARANTINED`, `FAILED` 상태와 정규화되지 않은 이벤트를 모두 포함한다.
- 원본 payload와 모든 context를 그대로 유지한다.
- 정규화 행동 유형, 결과, 플래그, 이슈, measurement는 선택적 annotation으로 붙인다.
- AI 입력 생성 시 기술별 점수, 성공률, 지원 효과, 강점·약점을 계산하지 않는다.
- 이름, 이메일 같은 직접 식별정보는 보내지 않고 member ID는 salt 기반 SHA-256 가명 ID로 바꾼다.

## 저장 구조

```text
behavior_logs
  └─ normalized_behavior_events (선택)
       └─ normalized_behavior_measurements (선택)

behavior_analysis_input_snapshots
  └─ behavior_analysis_input_event_links
       ├─ behavior_log_id (필수)
       └─ normalized_event_id (선택)
```

스냅샷은 실제로 AI에 전달할 JSON을 불변 데이터로 보관한다. 이벤트 링크는 입력에 포함된 모든 원본 로그를 추적하므로 학습 데이터 재현과 감사에 사용한다.

## 타임라인 순서

1. 사용자의 지정 기간 로그를 모두 조회한다.
2. `sessionId`별로 묶는다.
3. 세션 안에서는 `eventSequence`, 동률이면 `occurredAt` 순으로 정렬한다.
4. 세션은 최초 `occurredAt` 순으로 정렬한다.
5. 각 이벤트에 세션 시작 이후 경과 시간 `elapsedFromSessionStartMs`를 함께 기록한다.

## 정규화가 없는 이벤트

정규화가 아직 끝나지 않았거나 레지스트리에 없는 이벤트도 제거하지 않는다. 해당 이벤트는 `normalization: null`로 전달되며 원본 action, context, payload는 그대로 남는다.

## 프론트 수집 및 전송

- 이동 좌표는 렌더링 프레임마다가 아니라 250ms 또는 유의미한 거리 변화 기준으로 `SHOP.MOVEMENT_SAMPLED` 이벤트를 만든다.
- 의미 이벤트와 원시 이동 샘플을 같은 영구 Outbox에 추가한다.
- 이벤트 20개 이상이면 비동기 flush를 시작하고, 한 HTTP 요청에는 최대 50개를 보낸다.
- 서버 ACK가 `ACCEPTED` 또는 `DUPLICATE`인 이벤트만 Outbox에서 제거한다.
- 네트워크 실패 시 `offlineQueued=true`로 유지하고 다음 flush에서 재시도한다.
- 큐 용량을 이유로 낮은 우선순위 이벤트를 폐기하지 않는다.

## 기존 프로파일 방식의 폐기

`BehaviorProfileSnapshot`, 근거별 성공률 계산, `LlmSimulationGenerationInput` 조합 방식은 더 이상 사용하지 않는다. AI가 전체 행동 맥락을 직접 판단하도록 원본 중심 입력으로 대체한다.
