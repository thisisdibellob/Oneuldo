# 전체 행동 타임라인 API 계약

## API

인증된 사용자는 자신의 데이터만 생성하고 조회할 수 있다.

```http
POST /api/behavior-analysis-inputs
Content-Type: application/json

{
  "analysisFrom": "2026-09-01T00:00:00Z",
  "analysisTo": "2026-09-02T00:00:00Z"
}
```

기간을 생략하면 최초 시점부터 요청 시각까지의 전체 로그를 사용한다.

```http
GET /api/behavior-analysis-inputs/latest
GET /api/behavior-analysis-inputs/{datasetId}
```

## 최상위 응답

```text
BehaviorAnalysisInputResponse
├─ id
├─ schemaVersion
├─ generatedAt
├─ sessionCount
├─ eventCount
└─ input
```

응답의 `id`는 `input.datasetId`와 같은 값이다. 분석 기간은 `input.analysisWindow.from`과 `input.analysisWindow.to`에 들어간다.

`input.sessions[].events[]`에는 선택 기간의 모든 원본 로그가 들어간다. 각 이벤트는 다음 정보를 포함한다.

- 원본 로그·클라이언트 이벤트·배치 식별자
- 세션 내 순번, 발생 시각, 서버 수신 시각, 세션 시작 후 경과 시간
- 앱·콘텐츠·이벤트 스키마 버전과 오프라인 여부
- task와 action 전체 필드
- accessibility, presentation, taskResult, error, support, safety, validity, simulation, sessionEnd, userExperience context
- 타입이 유지된 원본 payload
- 존재할 경우에만 정규화 버전, 상태, 행동 유형, 결과, 유효성, 플래그, 이슈, measurement

## AI 전달 시 주의사항

- `input`을 다시 요약하거나 일부 이벤트만 선별하지 않는다.
- 대용량 입력은 모델 한도를 넘지 않도록 세션 경계에서 lossless chunk로 나눌 수 있지만 이벤트를 버리지는 않는다.
- chunk에는 동일한 `datasetId`, 가명 사용자 ID, 스키마 버전과 chunk 순서를 포함해야 한다.
- 모델 응답과 학습 데이터셋은 사용한 `datasetId`를 함께 저장해 재현 가능하게 한다.
- 직접 식별정보나 인증정보는 별도로 결합하지 않는다.
