# 블라인드 행동 판별 안내

이 안내는 특수교사·직업재활사 등 전문가가 합성 장보기 행동 기록을 독립적으로 읽기 위한 것이다. 기록은 모델이 만든 계획이며 실제 이용자의 수행 기록이 아니다. 특정 장애나 진단을 맞히는 검사가 아니며 실제 지적장애인과의 유사성이나 임상적 타당성을 입증하지 않는다.

## 판별 전 확인

진행자는 trace 생성에 참여하지 않은 판별자에게 공개된 평가 안내와 해당 판 파일만 전달한다. 여러 판별자는 서로 답안을 의논하거나 다른 판별자의 결과를 읽기 전에 각각 제출한다. `reviewerKind:"expert"`는 자기 신고이며 자격이나 독립성을 도구가 확인한다는 뜻이 아니다. 생성에 관여했거나 정답 자료를 보았다면 진행자에게 알리고 독립 판별로 해석하지 않는다.

`reviewerId`에는 실제 이름 대신 `expert-01` 같은 식별자를 쓴다. 한 판별자는 A/B에서 같은 ID, 종류, 세션 라벨을 유지한다. 새 ID는 다른 독립 판별자를 위한 것이며 채점한 답안을 고치는 용도로 사용하지 않는다. 모델 판별자는 `reviewerKind:"llm"`과 모델·세션 라벨을 함께 기록한다.

| 읽을 자료 | 읽지 않을 자료 |
| --- | --- |
| 공통 성향 모드: `traitRubric`, `publicStyles`, 요청한 A 또는 B 판 파일 | 인물별 성향 설정, 원본 trace, manifest, 측정값, 다른 판별자 답안, `blind-key.json` |
| legacy 모드: `publicProfiles`, 요청한 판 파일 | 정답 인물과 익명 ID의 연결, 채점 결과, 위 원본·측정 자료 |

공통 유형 설명(`publicStyles`)은 이번 표본의 정답 목록이 아니다. 인물의 성향, 취향, 수행 기준, 경험은 서로 다를 수 있으므로 오류나 대기시간 하나만으로 성향 수준을 단정하지 않는다.

## A판을 먼저 읽기

A판에는 행동 종류, 대상, 순서와 작성된 행동 전 대기시간이 있다. 대기시간은 실제 사람에게서 측정한 반응시간이 아니다. 각 익명 ID의 전체 행동 흐름을 읽고 제공된 기준에 따라 판단한다.

공통 성향 모드에서는 숙고(`deliberation`), 확인(`checking`), 탐색(`exploration`), 지속(`persistence`), 도움 활용(`helpSeeking`)의 다섯 축을 각각 `low`, `medium`, `high`, `unknown` 중 하나로 기록한다. 다섯 축을 모두 채우되 해당 행동을 볼 기회가 없거나 자료가 부족하면 `unknown`으로 보류한다. 도움을 쓰지 않았다는 사실만으로 도움 활용이 낮다고 보거나, 어려움이 없었는데 재시도가 없다는 이유로 지속이 낮다고 보지 않는다.

선택적 `confidence`는 해당 기록에 대한 전반적 판단 확신을 0~1로 표시한다. 성향별 수준이나 확인 횟수를 정답에 맞추려 하지 않는다. 오류 없이 완료한 행동에 실수를 요구하지 않으며, 오류를 많이 낼수록 특정 장애의 행동에 가깝다고 해석하지 않는다. 관심에 따라 고른 비목표 상품과 잘못 고른 목표 상품도 구분한다.

legacy 모드는 공개된 네 허구 인물 설명 중 기록과 가장 맞는 `personaId`를 선택한다. 이 모드의 답안 계약에는 `unknown`이 없으므로 근거가 약하면 선택적 확신도와 별도 검토 메모에 그 한계를 남긴다. 실제 사람의 장애 여부를 추정하는 활동으로 바꾸지 않는다.

## A 제출 후 B판 읽기

진행자가 A를 제출해 채점한 뒤 같은 판별자 ID로 B를 요청한다. 판별자는 B 제출 전 A의 점수·정답을 보지 않는다. 채점 도구 응답은 진행자가 보관하고 판별자에게는 요청한 판 파일만 전달한다. 이 분리는 도구가 입증하지 못하므로 보고서에는 `independenceVerified:false`, `keyIsolationVerified:false`가 남는다.

B에는 행동 기록에 배우가 작성한 `reason`이 추가된다. 설명이 실제 행동과 맞는지 살피되 설명만으로 관찰되지 않은 행동이 있었다고 확정하지 않는다. A/B는 같은 표본에서 나온 자료이고 독립적인 두 실험이 아니다. 익명 ID와 순서가 다르므로 A 답안을 ID별로 복사하지 않는다. A와 B 답안은 각각 채점 후 고정되며 동일 재제출만 허용한다.

다음은 전문가의 공통 성향 답안 **입력 형식 예시이며 실행 결과가 아니다**. 실제 제출은 해당 판의 모든 익명 ID와 다섯 축을 포함한다.

```json
{
  "runDirectory": "/absolute/output/validation-01",
  "panel": "A",
  "reviewerId": "expert-01",
  "reviewerKind": "expert",
  "reviewerSession": "independent-review-01",
  "answers": {
    "opaque-id-from-panel": {
      "traits": {
        "deliberation": "medium",
        "checking": "high",
        "exploration": "unknown",
        "persistence": "unknown",
        "helpSeeking": "unknown"
      },
      "confidence": 0.6
    }
  }
}
```

위 객체는 `submit_blind_review`에 전달한다. 전문가는 `reviewerModel`을 생략할 수 있다. 같은 ID로 `prepare_blind_review({"runDirectory":"/absolute/output/validation-01","panel":"B","reviewerId":"expert-01","reviewerKind":"expert"})`를 요청한 뒤 B 답안을 별도로 제출한다. 준비 도구는 모델이나 사람에게 자동으로 판별을 요청하지 않는다.

## 결과 읽기

보고서의 `blindReviews`에는 판별자별 A/B 점수가 있고 `interReviewerAgreement`에는 판별자 간 일치도가 있다. 같은 판을 채점한 사람이 2명이면 Cohen의 κ, 3명 이상이면 Fleiss의 κ를 계산한다. legacy는 인물 라벨별, 공통 성향은 다섯 축별로 A/B를 나누어 보고한다. 공통 익명 항목이 2개 미만이거나 판별자가 2명 미만이면 κ는 `null`이다. 모든 답이 같은 범주라 우연 일치도가 1인 경우도 κ를 정의할 수 없어 `null`로 남긴다.

`unknown`은 일치도 계산에서 별도 범주다. 같은 보류가 많아 일치도가 높아져도 성향을 잘 구별했다는 뜻은 아니다. 정확도·판별 비율·보류 수와 함께 읽는다. κ는 정답과의 일치나 실제 사람과의 유사성을 나타내지 않으며, 표본이 적으면 값이 쉽게 달라질 수 있다. 전문가와 모델을 합한 값은 이 판별자 구성의 설명적 요약일 뿐 일반화된 전문가 신뢰도가 아니다.

기존 `blind-review.json`은 단일 판별자 형식으로 읽으며, 새 ID로 제출한 답안은 `blind-reviews.json`에 별도로 저장한다. 기존 파일을 새 형식으로 변환할 필요가 없다. 세부 절차와 해석 범위는 [페르소나 충실도 검증 절차](persona-validation.md)를 따른다.
