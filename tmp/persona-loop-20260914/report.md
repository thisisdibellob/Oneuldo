# 가상 사용자 장보기 반복 실험 — 2회차에서 분석 오류 발견

이 자료는 합성 사용자 P01의 실제 웹 UI 조작 및 실제 AI 서버 응답이다. 지적장애인의 행동을 대표하지 않으며, 교육 효과를 입증하지 않는다. 실행자가 조작·디버깅·페르소나 역할을 겸했으므로 완전한 맹검이 아니다. 실험 중 발견한 구현 오류 수정으로 회차 간 조건도 동일하지 않다.

## 핵심 결과

예정한3회 중2회 플레이 후 중단했다. 두 번째 AI 분석은 원본에 존재하는 사과 선택을 없다고 해석했다. 이 잘못된 근거로 다음 훈련을 이어가면 교육 효과를 평가할 수 없으므로 세 번째 플레이는 실행하지 않았다.

- 원본E104: itemId=apple, quantityBefore=0, quantityAfter=1
- 원본E105: itemId=apple, quantityBefore=1, quantityAfter=2
- 원본E318: 구매 제출 장바구니 apple2, water1
- AI: “E104-E105의 수량 변경이 사과인지 확인되지 않았으며…”
- AI: “생수 구매는 확인되었으나 사과 구매 과정이 명확히 관찰되지 않아 전체 미션 완료 여부를 판단할 수 없습니다.”

저장된 실제 모델 입력과 중간 응답도 확인했다. 두 번째 구간 입력에 E104/E105와 apple0→1→2가 포함되어 있지만, 해당 구간 AI 요약이 이를 없다고 서술했다. 최종 통합이 그 잘못된 요약을 이어받았다. 로그 전송 누락은 아니다. 열별·사전별로 압축한 입력을 모델이 잘못 읽었을 가능성이 있으나, 표현 방식의 원인 여부는 대조 실험 전에는 확정하지 않는다.

응답은 READY로 저장되었다. 형식과 인용 ID 존재 검사가 문장과 실제 값의 의미 일치를 보장하지 못한 사례다. 세션 일부라는 불확실성 표현이 있더라도 존재하는 사건을 부정한 오류는 해결되지 않는다.

## 누적 프로필 결과

프로필 버전2도 READY로 저장되었고, 잘못된 사과 선택 누락 해석이 그대로 이어졌다. “과일 선택 단계에서 탐색 또는 조작의 어려움” 가능성과 “이전 세션의 잔여 데이터”라는 대안을 생성했다. 실제 초기 장바구니는 비어 있었고 사과0→1→2가 기록되어 있으므로 이 해석은 근거와 맞지 않는다. 이는 사용자 능력의 악화가 아니라 분석 오류의 누적이다.

이번 실행은 별도 합성 계정에서만 이루어졌다. 해당 프로필과 원본은 실패 재현 자료로 보존했으며 실제 이용자 평가로 사용하지 않는다. 세 번째 퀘스트 생성·플레이는 실행하지 않았다.

## 조건

게임을 처음 이용하는 가상 성인. 익숙한 상품명과 짧은 문장을 이해하며, 여러 지시와 수량을 한꺼번에 기억하는 데 지원이 필요하다고 설정했다. 진단명만으로 실수·실패를 강제로 만들지 않았다. UI에 보이는 목록·장바구니·안내를 이용하며, 회차가 늘었다고 기억력이나 수행 능력을 자동으로 높이지 않았다. 진단명과 운영자 관찰 메모를 실제 행동 분석 입력에 추가하지 않았다.

- 사용자와 분리한 합성 테스트 계정
- 실제 모델: qwen3.6:27b-q4_K_M
- 컨텍스트18432, 분석 요청 예산18000
- 판단/다음 연습 계획: 실제 AI 출력
- 행동 로그는 실제 조작에서 수집. 사후에 성공 로그를 만들어 넣지 않음

## 현재 완료 결과

| 항목 | 회차1 | 회차2 |
|---|---|---|
| 목표 | 사과2개·생수500mL1개 | 동일 목표, AI 생성 공원 간식 구매 |
| 최종 장바구니 | 사과2·생수1 | 사과2·생수1 |
| 원본 이벤트 | 208 | 318 |
| 전송 누락 | 0 | 0 |
| 분석 구간 | 2 | 3 |
| AI 결과 | SUCCESS | UNDETERMINED — 원본과 모순 |
| 맞춤 생성 시간 | 초기 기본 과제 | 89.788초 |

회차1 분석은 목록과 장바구니 비교를 통한 확인 행동을 제안했다. 이동 중 멈춤을 능력 부족으로 단정하지 않았고, 기기 입력 지연 등의 대안을 제시했다. 회차2에서는 한 번에 두 개를 담은 후 수량을 확인했다. 이것은 가상 수행의 차이이며 실제 학습의 증거가 아니다.

## 발견한 문제

1. 기본 과제 식별자로 UUID가 아닌 문자열을 전송해 기록 제출이 실패했다. 해당 기술 실행은 제외하고 UUID를 사용하도록 수정했다.
2. AI가 생성한 briefing/checkoutDialogue가 화면에 표시되지 않았다. 실제 생성 안내가 나타나도록 수정했다. 회차1과2 사이 UI 변경이 있어 직접적인 학습 비교가 제한된다.
3. 이동 이벤트의 movementContext.stations에 이전 매장 좌표가 들어갔다. sceneSnapshot의 실제 배치와 충돌할 수 있다. 실제 환경 좌표를 전달하도록 수정했으며, 이미 제출된 회차1·2 원본은 수정하지 않았다. 해당 회차의 동선 해석은 신뢰하지 않는다.
4. 맞춤 퀘스트의 계산대 대사가 구매 확정 전에도 ‘구매가 완료되었습니다’라고 말한다. 대사의 노출 시점을 생성 프롬프트에 명시해야 한다.
5. 두 번째 퀘스트는 동일 상품·수량 반복이며, ‘목록과 장바구니 비교’라는 다음 연습 전략을 구체적인 단계로 구현하지 않는다. 효과적인 개인화인지 아직 확인할 수 없다.
6. 자동 분석은 구매 제출 시점에 시작하여 세션 종료 전 OPEN 스냅샷을 사용한다. 이벤트 누락은 없지만 종료 상태와 구분해야 한다.
7. 접근성 메타데이터 textLevel은 STANDARD이다. 분석 제안 SIMPLIFIED가 실제 표시 수준에 정확히 반영·기록되는지 추가 점검이 필요하다.

## 시간 해석

회차2: 구매 제출에서 분석 저장까지22분37초. 구간별6분6초/7분9초/4분24초, 최종통합4분34초. 누적 프로필 갱신은4분7.5초. 구매 제출부터 프로필 포함 작업 완료까지26분45초.


회차1의 분석 작업 생성부터 완료까지 약37분35초가 걸렸다. 공용 추론 대기열, Mac 연결 정체 및 최종 단계 재시도가 포함된다. API latencyMs 필드만을 전체 분석 시간으로 보고하면 과소 보고한다. 플레이 시간은 UI 자동화 지연 및 탐색 조정이 섞여 교육 지표로 쓰지 않는다.

## 수정 검증

- UUID 및 생성 안내 표시 관련3개 테스트 묶음40개 통과.
- 실제 배치 좌표 전달 관련3개 테스트 묶음13개 통과.
- TypeScript 검사 통과.
- 변경은 로컬 작업 트리에 있으며 아직 커밋·푸시하지 않았다.

## 개선 방향

실제 이용자 검증 전, 데이터 좌표·세션 종료·안내 노출을 먼저 정확하게 맞춰야 한다. AI에는 관찰 근거→연습 기술→짧은 행동 안내→다음 회차 확인할 행동을 연결하도록 요청하는 것이 적절하다. 성공/실패에 따른 난이도를 규칙으로 정하지 않고, 지원 유지·감소·과제 변경의 이유를 AI가 근거와 함께 설명하게 한다. 실제 교육 효과는 당사자와 지원 인력이 참여하는 별도의 평가가 필요하다.
